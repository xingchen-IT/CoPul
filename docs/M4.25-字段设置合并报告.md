# M4.25 字段设置合并：悬浮窗 / 任务栏条一张卡

需求原话：

> 将悬浮窗字段与任务栏字段设置合并到一起，做成类似文字颜色的那种效果

原来「任务栏条字段」与「悬浮窗字段」各占一张卡、各摆一片勾选框，同一件事（哪些字段要显示）
被拆在两处：改完任务栏的还得往下翻过「悬浮窗外观」「文字颜色」才看到悬浮窗的。

而「文字颜色」（M4.19/M4.20）早就用"先选视图 → 再看一条字段条"解决了同一形状的问题。
这一版把字段开关也统一成那一套。

编译：0 警告 0 错误（Release）。

---

## 1. 现在长什么样

设置页 → 常规 → 「显示字段」（在原「任务栏条字段」的位置，紧跟显示模式）：

```
显示字段
[悬浮窗✓] [任务栏条]
[FPS] [CPU] [GPU] [内存] [显存] [网络延迟] [硬盘温度] [上传/下载] [整机功耗]
       ↑ 点亮的 = 显示，灰字带删除线的 = 隐藏
点亮 = 显示，划掉 = 隐藏。关闭的字段不占位：横向条会变窄，竖向条会变矮。
只剩一个字段时该项不可关闭。与任务栏条各自独立保存。
```

切到「任务栏条」时，字段条换成任务栏那一套，说明文字也跟着换成带"让位"规则的那段
（任务栏空白不够时按「功耗 → 延迟 → 网络速率」让位，FPS 留到最后）。

## 2. 两张字段表**不能**合成一条

看着像同一件事，但两边的 key 表顺序不同：

| 位次 | 任务栏条 `TrayFields.Keys` | 悬浮窗 `FloatFields.Keys` |
|---|---|---|
| 1–5 | fps / cpu / gpu / ram / vram | 同 |
| **6** | **disk**（硬盘温度） | **net**（网络延迟） |
| 7–9 | io / **lat** / pwr | disk / io / pwr |

任务栏用 `lat`、悬浮窗用 `net`（都绑 NetLatency），第 6 位起的顺序整整错开一格。
共用一条字段条会按错的 key 落盘 —— 表现为"关掉硬盘温度，结果网络延迟没了"。
所以卡片合并，**字段条仍然按视图重建**（`InitFieldBar()` 读当前视图的表）。

## 3. 状态标记不能只靠颜色

M4.19 已经踩过一次"两种状态长得一样"：色板里"没选中"和"自动"分不出来。
字段开关是同一个陷阱 —— 深色主题下"关闭的字段"和"普通字段"只差一档灰，扫一眼看不出来。

所以熄灭态画成**灰字 + 删除线 + 透明底**三件事一起：删除线是这里唯一不依赖颜色的状态标记。

用 `ToggleButton`（多选）而不是 `RadioButton`（互斥）：文字颜色那边一次只能选一格，
字段开关可以同时关掉三个，语义上就不是单选。

实测前景色确认模板 trigger 生效：

```
fields: [cpu] CPU checked=True  enabled=True  fg=#FFE8ECF2   ← BrushTextPrimary
fields: [io]  上传/下载 checked=False enabled=True  fg=#FF6B7480   ← BrushTextTertiary
```

## 4. 改了什么

| 文件 | 改动 |
|---|---|
| `SettingsWindow.xaml` | 新增 `FieldToggle` 样式（ToggleButton，熄灭态灰字 + 删除线 + 透明底）；删除「任务栏条字段」与「悬浮窗字段」两张卡；新增「显示字段」一张卡（视图分段 + `FieldBar` + `FieldHint`） |
| `SettingsWindow.xaml.cs` | `InitFieldGrid` + `InitFloatFieldGrid` → `InitFieldBar()`（按视图重建）；`Field_Changed`/`ApplyFields`/`UpdateFieldEnabled`/`FloatField_Changed`/`UpdateFloatFieldEnabled` 五个方法 → `FieldToggle_Changed` / `SyncFieldToggles` / `UpdateFieldToggleEnabled` / `FieldView_Changed` / `SetFieldView`；探针新增 `fieldview:` 与 `fields`，`field:`/`floatfield:` 保留旧语义 |

**一个行为差异要记着**：老代码从"全关"回滚时是"整份按配置重同步"（M4.14 踩过
"记一个 lastOff 结果勾错了项"的坑）。合并后仍然保留这个写法 —— `SyncFieldToggles()`
把整条按配置重刷，而不是只把手里的 chip 勾回去。

## 5. 取证

| 项 | 结果 |
|---|---|
| 悬浮窗视图字段顺序 | `fps cpu gpu ram vram net disk io pwr` —— 与 `FloatFields.Keys` 一致（第 6 位 net） |
| 任务栏视图字段顺序 | `fps cpu gpu ram vram disk io lat pwr` —— 与 `TrayFields.Keys` 一致（第 8 位 lat） |
| 熄灭态前景色 | `#FF6B7480`（Tertiary），点亮态 `#FFE8ECF2`（Primary） |
| 切视图后说明文字 | 任务栏版含「功耗 → 延迟 → 网络速率」「让位不写入配置」 |
| 关到只剩 CPU | `[cpu] checked=True enabled=False` —— 置灰 |
| **最后一个也尝试关掉** | 配置不变（8 项 hidden，没多出 cpu），CPU 保持勾选 —— 兜底回滚生效 |
| 落盘 | `TaskbarHiddenFields` 记为 8 项；`FloatHiddenFields` 关掉 ram 后变成 `io,pwr,ram` |
| 窗口真重排 | 任务栏条 `--shot` 宽度 **618px（8 字段）→ 84px（1 字段）** |
| 主窗口冒烟 | 退出码 0，日志无 exception |

截图（`m425-final.png` / `m425-tray.png`）已确认：两张视图的字段条与下方「文字颜色」卡片
风格一致、无挤压、说明文字各按视图切换。

⚠️ 探针会真写 `config.json`，本轮结束后 `TaskbarHiddenFields` 已还原为 `["fps"]`、
`FloatHiddenFields` 还原为 `["io","pwr"]`。

## 6. 探针兼容

既有取证脚本用的是 `field:<key>`（任务栏）与 `floatfield:<key>`（悬浮窗）。
合并后只剩一条字段条，但**两个命令名保留、语义不变**：内部先 `SetFieldView()` 切到对应视图
再翻那一格。新增：

- `fieldview:float|tray`：切视图并重建字段条（不依赖 RadioButton 的 Checked 事件，
  重复发同一个值也能保证 `_fieldView` 与界面一致）
- `fields`：打印当前视图整条字段条（key / 文案 / 勾选 / 置灰 / 前景色）
  —— "划掉"在缩略截图上看不清，前景色才是模板 trigger 真的生效的硬证据

（比如左右两列并排），可以再加，但那会把卡片撑高不少 —— 先按同构这一版用着看。
