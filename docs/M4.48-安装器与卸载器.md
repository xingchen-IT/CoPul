# M4.48 安装器与卸载器

目标很朴素：**双击就装、不弹 UAC；协议只在首启弹一次；卸载时问一句要不要连配置一起删。**
这一版只做 Windows 用户级安装，不做签名、不做自动更新、不做商店上架。

## 结论

| 项 | 值 |
| --- | --- |
| 产物 | `artifacts\CoPul-0.1.0-setup-x64.exe` |
| 体积 | 57.3 MB（发布目录 170.2 MB / 484 文件） |
| sha256 | `60FA379604AA4E2BA8397B7952FC12E18F104AA07CE9B905D5D49923CFC34A4C` |
| 安装耗时 | 干净状态 12.0 s；重复测试 9.4 ~ 20.9 s（杀软与磁盘缓存抖动） |
| 卸载耗时 | 7.7 ~ 21.2 s |
| 安装位置 | `%LOCALAPPDATA%\Programs\CoPul`（可改，不强制） |

打包入口 `tools\build-installer.ps1`：读 csproj 的 `<Version>` 用 `/D` 传给 ISCC，版本号只有一个来源；
发布目录不存在时自动调 `publish.ps1 -NoZip`；文件数少于 400 直接报错（防"拿半份包去打安装器"）；
产出 `.exe` + `.sha256`（大写十六进制 + 文件名，`sha256sum -c` 能直接验）。

## 三个设计决定

| 决定 | 怎么实现 | 为什么不这么做 |
| --- | --- | --- |
| 仅当前用户 | `PrivilegesRequired=lowest` + `DefaultDirName={localappdata}\Programs\CoPul` | 装一个监控条不该要管理员。另：**不要加 `PrivilegesRequiredOverridesAllowed`**，那会让安装器又去争取提权，"双击即装"就没了 |
| 协议只在首启弹 | 安装向导不挂许可页；首启弹 EULA（M4.43 那套，正文嵌程序集） | 向导一遍、首启一遍，等于让人连读两遍同一份文本，第二遍必然被跳过。点击合同要的是"知悉"，不是"点过两次" |
| 卸载时询问 | `MsgBox(PurgePrompt(), mbConfirmation, MB_YESNO or MB_DEFBUTTON2)` | 删数据默认必须落在安全侧：默认按钮是「否」。静默卸载弹不了窗，改读环境变量 `COPUL_PURGE=1` |

`[Code]` 段的两件小事：

- 静默卸载不弹窗 → 看 `GetEnv('COPUL_PURGE')`，没设就按"保留"处理；
- 配置位置写死成 `{userappdata}\CoPul` 与 `{localappdata}\CoPul`，与 `Config` 的落盘位置一一对应，
  不靠 `{app}` 反推（卸载时 `{app}` 已经在被删了）。

## 踩到的八个坑（按发现顺序）

| # | 坑 | 表现 | 判据 | 修法 |
| --- | --- | --- | --- | --- |
| 1 | `SolidCompression=yes` | 安装器启动后 37 s `exit=1`，目标目录 0 文件 | 连 `/LOG` 指定的日志都没创建 | 改 `SolidCompression=no`，11.7 s 装完 485 文件，代价产物大 6 MB |
| 2 | `[Code]` 段的 `const` 拼接 | 0.2 s `exit=1`，同样没有日志 | `'a' + #13#10 + 'b'` 编译能过，但整个 Code 段初始化失败 | 文本改成函数在运行时拼（`PurgePrompt()`） |
| 3 | Git Bash 的 MSYS 路径转换 | `/VERYSILENT` 变成 `D:/work/.../PortableGit/NOCLOSEAPPLICATIONS` | 安装器 `exit=1`，参数完全不是本意 | Python `subprocess.run([...])` 传列表，或 `MSYS_NO_PATHCONV=1` |
| 4 | **源码目录 ACL 带 Deny** | 从 `D:\CoPul开发` 跑 `setup.exe` 一律失败（本里程碑 20+ 次假阴性全出自此） | 同一份包拷到 `D:\CoPulProbe` 一次成功 | 打包产物一律从 `D:\CoPulProbe` 或 `D:\` 启动 |
| 5 | `CloseApplications=yes` | 用来测安装的 PowerShell 进程被杀，退出码 1、无输出 | Restart Manager 会关掉"占用待覆盖文件"的进程，包括调用方自己 | 改用 Python 起进程（被杀也不影响结论） |
| 6 | 卸载器**另起进程**显示界面 | 按启动 pid 枚举窗口，一个都找不到 | 启动 pid=64368，弹窗却属于 pid=96572 | 全桌面扫 `#32770` 并按标题 `CoPul 芯脉 卸载` 认人 |
| 7 | 交互卸载有**两个**必答页面 | 只点完第一个询问框就挂住，60 s 后被沙箱回收，看起来像"卸载失败、什么都没删" | `exit=None`、安装目录 484 文件一个没少 | 循环处理所有弹窗：询问框按 `同时删除` 认，Inno 自带的确认页点「是」 |
| 8 | `unins000.exe` 的自删发生在**退出之后** | 退出瞬间读目录，看到 `unins000.exe` 孤零零剩着，像没卸干净 | `%TEMP%\is-XXXX-uninstall.tmp\_unins.tmp` + `_unins-done.tmp` 是第二份副本在干活 | 留在同一进程里再盯 0.5 s，安装目录连同 exe 一起消失 |

第 4 条值得单独记一笔：它和 MEMORY 里那条"源码目录 ACL 带 Deny → 直接跑 `bin\Release` 报
`0x80008082`"是同一类问题，只是这次吃亏的是**安装器自己**。当时的表现是"脚本肯定有问题"，
于是把 AppId、中文 AppName、版本号段数挨个改成 12 份变体（`test-a` ~ `test-t`）逐个排除，
全都通过而正式脚本仍失败——最后发现变体也是拷贝目录跑的，只是恰好都在 `D:` 根。

## 验收：卸载侧（四条路径）

| 路径 | 怎么触发 | 耗时 | 安装目录 | `%APPDATA%\CoPul` | `%LOCALAPPDATA%\CoPul` | 快捷方式 |
| --- | --- | --- | --- | --- | --- | --- |
| 交互 → 「否」 | `unins000.exe`，点「否」 | 9.9 s | 全清 | 保留（5 文件） | — | 清掉 |
| 静默（无环境变量） | `/VERYSILENT` | 7.7 s | 全清 | 保留（5 文件） | — | 清掉 |
| 静默 + 清配置 | `/VERYSILENT` + `COPUL_PURGE=1` | 13.2 s | 全清 | **删除** | **删除**（1 文件→0） | 清掉 |
| 交互 → 「是」 | 点「是」 | 14.4 s | 全清 | **5 文件→0** | **1 文件→0** | 清掉 |

四条全部 `exit=0`，全部在退出后 0.5 s 内连 `unins000.exe` 一起消失。
"默认落在安全侧"这一点是实测的：`MB_DEFBUTTON2` 下直接点「否」，配置完好。

## 探针怎么写的

- `m448-install.py`：静默安装 + 立刻数文件（同一次调用里完成，避免 GUI 进程被回收）。
- `m448-uninstall-probe.py`：四种模式（`interactive-no` / `interactive-yes` / `silent` /
  `silent-purge` / `interactive-dump`），交互模式用 `SendMessage(BM_CLICK)` 点按钮。

为什么程序化点按钮而不是模拟鼠标：`SetCursorPos`/`SendInput` 在本机不可靠（DPI 1.5 倍 + 前台抢占，
见 MEMORY），标准 MessageBox 的按钮对 `BM_CLICK` 有确定性响应。

**探针会污染配置**：动之前先把 `%APPDATA%\CoPul` 整份备份到 `D:\CoPulProbe\m448-cfg-backup`，
收尾 `diff` 过一遍——与备份逐字节一致，5 个文件（含 `m14bak`~`m434bak`）都在。

## 没做的

- 代码签名与 EV 证书：需要企业资质，个人开发者走不通；SmartScreen 首次运行会提示"未知发布者"。
- 自动更新：与专有许可的"版本可追溯"要求一起来了再设计。
- 32 位 / ARM64：发布产物只有 win-x64。
- 升级覆盖安装：AppId 固定意味着 MSI 式的升级能跑通，但这一版没做跨版本实测。
