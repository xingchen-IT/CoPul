# M4.34 温度单位统一为 `℃`

## 现象

用户截图里任务栏 / 悬浮窗的硬盘温度显示成 `49°`、`44°` —— **只有一个度数符号，没有单位字符**。
其余温度（CPU / GPU）写的是 `°C`，两处不一致。

## 根因

温度文本有三条各自独立的拼装路径，只有一条带了 `C`：

| 路径 | 代码 | 改前 |
| --- | --- | --- |
| 悬浮窗 / 任务栏的硬盘温度 | `DashboardState.DiskTempText` | `v.ToString("F0") + "°"` ← 缺 `C` |
| 悬浮窗的 CPU / GPU 副值 | `WithUnit(CpuTemp.Value, "°C")` | `°C` |
| 大窗口指标格的单位 | `MetricCell.Unit` | `°C` |

`FloatDisk` 一个格子同时喂任务栏与悬浮窗（`ApplyDisk` 里那行 `FloatDisk.Set`），
所以改一处两边都变；但它在 `DiskBlock.Collapsed` 之前，折叠大窗口也照样刷新。

## 改法

新增 `Fmt.TempUnit = "℃"` 作为**唯一来源**，所有温度拼装都引用它：

- `DiskTempText` → `v.ToString("F0") + Fmt.TempUnit`
- `DiskRow.SetTemp`（大窗口硬盘列表）→ `$"{celsius:F0}{Fmt.TempUnit}"`
- `CpuTemp` / `GpuTemp` 的 `MetricCell` 单位、`WithUnit(...)` 两处
- 温度趋势图轴标签 `Unit="℃"`、`TempSubtitle`「0–100℃」

**为什么用单字符 `℃`(U+2103) 而不是 `°C`**：任务栏与悬浮窗的列宽是定尺的
（`FloatField.BaseWidth`，DISK 只有 36 px），两字符的 `°C` 会把整格撑宽；
`℃` 一个字宽，与 `%` 同宽，视觉上就是一列数字的尾巴。
「Microsoft YaHei UI」与「Segoe UI」都含 U+2103 字形，不需要字体回退。

## 验收

| 判据 | 结果 |
| --- | --- |
| Release 编译 | 0 警告 0 错误 |
| dll 内字符串 | `100℃` × 1，`100°C` × 0 |
| 悬浮窗（竖排，`--shot`） | CPU 副值 `57℃`，未被列宽裁切 |
| 任务栏条（`--shot`） | CPU 副值 `56℃`，整条宽度不变 |
| 大窗口（`--shot`） | GPU 核心温度 `61℃`、CPU 封装温度 `— ℃` |
| 探针污染 | `config.json` 与备份 `diff` 无差异 |

硬盘温度的 `49℃` 需管理员权限才读得到盘温，普通权限下该格恒为 `—`，
本次只能靠「同一常量 + 同一格」推定；重启后由用户目视确认。

## 遗留

- 温度趋势图纵轴仍然只画刻度数字，单位写在 `Unit` 里，改后为 `100℃` 宽，轴宽（`AxisWidth`）无需调整。
- `CoPul.Collector` 里的日志文案（如 `TjMax=100°C`）保持 `°C`：那是诊断日志不是 UI。
