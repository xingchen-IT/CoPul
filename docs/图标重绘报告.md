# 图标重绘报告（R-01 / R-02 / R-03）

- 日期：2026-11-02
- 需求依据：需求文档 14.1「必需」三项 —— R-01 应用主图标、R-02 托盘深色版、R-03 托盘浅色版
- 生成器：`tools/make-icon.py`（取代旧的 `make-tray-icon.py`）

---

## 1. 旧图标的问题

旧图标（`make-tray-icon.py` 生成，5 帧 16–64）是一个**深色圆角方块 + 一条青绿心电图**。实测两个问题：

1. **只表达"心电"，没表达"芯脉"。** 需求对 R-01 的要求是「"脉"意象：波形/电路交叠，
   单色几何，避免渐变堆叠」。旧图只有波形，没有电路；放在一堆健康类 App 里认不出是
   资源监控工具，也看不出和"芯"有什么关系。
2. **深色方底在浅色主题下很跳。** 项目现在默认白色主题（b71bad9），托盘/资源管理器里
   一个近黑方块与界面观感不统一；而在**深色任务栏**上，同一个深底方块又会融进背景
   （见第 3 节实测）。

## 2. 设计迭代过程（六版，每版都有截图对比）

这一轮的价值主要在于**排除了四种错误方向**，而不是最后那张图：

| 版本 | 做法 | 结果 |
| --- | --- | --- |
| v1 | 一条心电图 + 一条横穿的电路走线（两套图形叠加） | ❌ 杂乱，像"心电图旁边又画了几根线" |
| v2 | 改成两条短走线（上下各一）避开波形主体 | ❌ 走线太淡（55% 白在同色系底上没层次），仍读不出关系 |
| v3 | **一条连续路径**：走线 → 脉冲 → 走线 | ✅ 结构对了，但分段线宽在斜线段上粘连 |
| v4 | 矩形距离场求尖角 | ❌ 斜线段被沿坐标轴平切 → 脉冲**方波化** |
| v5 | 沿线段法向的平头方笔（正确尖角） | ⚠️ 尖角对了，但"脉冲段加粗"依旧粘连成白斑 |
| **v6（最终）** | **砍掉分段线宽**：均匀粗线脉冲 + 两端焊点 | ✅ 干净、16px 可辨 |

### 2.1 关键设计决定：砍掉"分段线宽"

v3–v5 都在"走线细、脉冲粗"这个维度上迭代，反复失败。原因是几何本身不允许：

> R 峰的 x 半宽只有约 0.048，脉冲段线宽到 2.9× 时，两条粗线的笔迹**直接重叠成一块白斑**。
> 调细失去主次，调粗就粘连 —— 这个参数维度没有可行区间。

砍掉之后问题从根上消失：**尖峰靠几何角度表达，不靠加粗**。角度够尖，细线也像脉冲；
角度不尖，粗线只会更糊。

那"芯"靠什么表达？不用走线，用两个更省的元素：
- **圆角方底** —— 现代应用的容器形态，本身就是"芯片/面板"的语义
- **两端焊点** —— PCB 最小的视觉语素（一颗焊盘）。放两个在波形两端，
  "这是一条走在线路板上的信号"立刻成立，且不造成任何杂乱

### 2.2 两次几何错误（技术细节，值得复用）

**错误一：用"到线段最短距离 <= 半线宽"判断笔迹 → 圆头端点。**
距离场在端点外是圆的，于是 R 峰顶、S 谷底被抹成圆弧，脉冲变成圆滑正弦，失去"尖峰"语义。

**错误二（v4）：改用"轴向投影 t ∈ [0,1] + hypot 距离"求尖角 → 斜线段被沿坐标轴平切。**
斜线段的平切口应当**垂直于线段**，而 hypot+裁剪 得到的切口是水平的 ——
R 峰变梯形、S 谷变方块，脉冲彻底方波化。

**正确写法（v5）**：在线段坐标系里判断。令 `u` = 沿轴向投影（按线段长度归一）、
`v` = 横向垂距，约束 `|v| <= half` 且 `u ∈ [-0.12, 1.12]`。u 两侧外扩 12%
让相邻段在拐角处**轻微重叠** —— 否则平切口会在尖角外侧留出小缺口。

### 2.3 为什么必须超采样

旧脚本在每个目标尺寸上**直接**画抗锯齿（按距离做 1px 淡出）。16px 时描边只有 1.4px、
整条曲线才 3–4 像素，那种做法会把波形糊成一团，所以旧脚本被迫为小尺寸单独再写一套点。

新做法：**先在一张 4× 超采样的 256 母版上算覆盖率，再盒式降采样到目标尺寸**。
小尺寸拿到的是真实高分辨率几何的平均，边和线自然收敛。

**并且**：16/24 用一套**独立的简化几何**（WAVE_SMALL，峰谷更高更深），
从另一张母版降采样 —— 不是在小尺寸上重画（那样抗锯齿又不够），
仍然超采样，只是喂给它更简洁的形状。

> **带 alpha 的图降采样必须预乘**：直接平均 RGB 会让透明边缘混进黑色（暗边）。
> 代码里先 `RGB × alpha` 再平均，最后除回去。

## 3. 托盘为什么必须要两版（R-02 / R-03）

需求 14.1 要求托盘图标分深浅两版。这不是讲究，是**对比度实测结论**：

把 R-01 主图标（深青绿方底 `#17655C`）直接放到真实任务栏背景下：

| 背景 | 结果 |
| --- | --- |
| 浅色任务栏 `#F0F0F2` | ✅ 深方底压出清晰轮廓 |
| 深色任务栏 `#202022` | ❌ 方底**几乎融进背景**，只剩中间一小段白线 —— 用户看到的是"一个白点" |

所以托盘出两版，**按任务栏实际亮度挑一份**：

| 版本 | 配色 | 用于 |
| --- | --- | --- |
| `copul-tray-light.ico`（R-03） | 深方底 `#17655C` + 白波形 | 浅色任务栏 |
| `copul-tray-dark.ico`（R-02） | 亮方底 `#4FB3A6` + 深波形 `#0B2E2A` | 深色任务栏 |

两版都是"实心方底 + 反色波形"，**不是同色系调透明度** —— 半透明在小尺寸下最先糊掉，
必须两边都是实色高对比。

### 3.1 选版逻辑

复用 `Taskbar.SampleLuma`（与任务栏模式取字色同一套逻辑）：采样任务栏右侧空白 5 点平均 luma。

- `luma > 128` → 浅色任务栏 → `copul-tray-light.ico`
- `luma <= 128` → 深色任务栏 → `copul-tray-dark.ico`
- `luma < 0`（自动隐藏时整条滑出屏幕，取不到任何像素）→ **按深色处理**
  （深色壁纸是绝大多数，猜错时亮方底至少不会消失）

版本文件缺失时退回主图标 —— 宁可图标不完美，也不能托盘没图标（绿色版被手动删文件的场景）。

实测（本机任务栏 luma=177）：

```
[tray] icon: luma=177 darkTaskbar=False -> copul-tray-light.ico
[tray] added=True ico=.../assets/copul-tray-light.ico exists=True
```

## 6. 已知限制

| 限制 | 说明 |
| --- | --- |
| 托盘不做主题热切换 | 图标在启动时按当时的任务栏亮度选一次。用户中途切任务栏明暗需要重启才能换版（托盘图标 API 支持更新，但当前没做） |
| 无 SVG 源 | R-04/R-05 要 .svg，但本机无矢量编辑能力（无网络装工具），只有生成器脚本作为"源" |
| 1024 源图是双线性放大的 | 母版 256 → 1024 双线性放大。几何图形放大足够（不是照片），但不是真矢量渲染 |
| 未做 R-04/R-05 | 指标图标组（10 枚）与状态图标组（3 枚）本次未涉及 |
