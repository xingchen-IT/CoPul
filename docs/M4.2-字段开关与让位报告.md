## 3. 三个设计决定

### 3.1 存「关掉的」而不是「打开的」

`TaskbarHiddenFields` 只记被隐藏的 key。以后新增字段默认可见，不需要写迁移把老配置补全；
反过来存 visible 列表，老配置里没这个新 key 就等于"新字段默认不显示"，用户会以为功能坏了。

### 3.2 `Collapsed` + 最后一列去右间距

Q-03 写「不保留空位」，所以：
- 隐藏用 `Visibility.Collapsed`（不占位），**不能**用 `Hidden`（占位，仍留一段空白）
- 每个可见列的右间距由代码按"是不是最后一个"设 0 或 7 DIP

宽度计算与之严格对齐：`needed = Σ字段宽 + 7×(n-1) + 12`。早先的做法是每列都带 7、
最后统一减一次，字段一隐藏就对不上（宽度多算 7 px，右边空一条）。

### 3.3 拒绝关最后一个 + 该项置灰

全关之后内容宽度是 0，窗口会被夹到 1 px —— 屏幕上留一根发丝长的竖线，用户只会以为程序坏了。
所以 `TrayFields.Toggle` 在"这是最后一个可见字段"时返回 `false`，菜单那项同时置灰：
**让"不能再关"看得见**，而不是点了没反应。

`VisibleCells` 里另有一层兜底：配置被手改成八个全隐藏时，仍然保最后一列。

## 4. 菜单：为什么把数字 id 换成字符串命令

原 `RunTrayCommand(int id)` 的 id 是"菜单项下标 + 1"，调用方写着 `case 5: 切换穿透`。
这次给菜单插了一整个子菜单（八项），**先序遍历的序号整体平移**，而 `switch (id)` 不会报错 ——
表现是"点了退出却切了视图"这种静默错位。

改成 `TrayMenuEntry.Item(text, command, ...)` 携带命令串（`"view:taskbar"` / `"field:pwr"` / `"toggle:clickthrough"` / `"exit"`），
`ShowMenu` 返回被选项的命令而不是 id。探针也随之从 `--tray-menu-probe 5` 变成
`--tray-menu-probe field:pwr`。

顺带一个必须做的细节：**八项字段开关要在两个地方出现**（托盘 + 条右键）。
穿透是默认状态（Q-12 方案 2），条上根本收不到右键，所以托盘那份不是重复而是主路径。

## 5. 验证证据（全部真实运行）

### 5.1 宽度自适应

| 场景 | `place:` 行 | 结论 |
| --- | --- | --- |
| 八字段全开 | `need=419 used=419 fields=8/8 dropped=[]` | 基线，与 M3.0 的 419 一致 |
| 关掉「整机功耗」 | `need=368 used=368 fields=7/8` | 419−368 = **51** = PWR 44 + 间距 7 ✓ |
| 再关到只剩 FPS（配置手改） | `need=46 used=46 fields=1/8` | 46 = FPS 34 + 内边距 12 ✓ |
| 配置八个全隐藏 | `need=56 used=56 fields=1/8` | 兜底保最后一列（PWR 44 + 12）✓ |

截图逐列核对：419 那张是 `FPS / 65% / 38% / 86% / — / ↑10.9K ↓122.0K / 13ms / ~41W`，
368 那张右端的 `~41W PWR` 消失且右边界收紧 —— 不是"文字没了但宽度还在"。

### 5.2 空间不够时自动让位（7.7）

用 `--tray-free <px>` 只伪造"可用空白"，其余走生产路径：

| 伪造空白 | 结果 |
| --- | --- |
| 300 px | `need=272 used=272 fields=5/8 dropped=[pwr,lat,io]` |
| 150 px | `need=97 used=97 fields=2/8 dropped=[pwr,lat,io,disk,ram,gpu]` |

让位顺序与 7.7 原文一致，FPS 留到最后。**且不改配置** —— 任务栏图标被挤走后条要能自己长回来。

### 5.3 拒绝关最后一个

只剩 FPS 时跑 `--tray-menu-probe field:fps`：

```
[tray] probe: menu-command=field:fps
[tray] field: 拒绝关闭最后一个可见字段 fps
```

条宽保持 46，`config.json` 的 `TaskbarHiddenFields` 仍是那 7 项（未追加 fps）。

### 5.4 菜单外观（真实右键 + 展开子菜单）

- 父菜单：`显示大窗口 / 显示悬浮窗 / 显示任务栏条(✓) / ─ / 显示字段 ▸ / 任务栏条可点击 / ─ / 设置…(灰) / 开机自启(灰) / ─ / 退出`
- 子菜单（全开时）：FPS / CPU / GPU / 内存 / 硬盘温度 / 上传 / 下载 / 网络延迟 / 整机功耗，**八项全勾**
- 子菜单（只剩 FPS 时）：**FPS 带勾且灰色不可点**，其余七项无勾可点

## 6. 验证工具的新坑

**`TrackPopupMenu` 的菜单收不到 `keybd_event`。** 菜单弹出时确实是前台窗口，
但按键不会进它的模态循环 —— 发 4 次 `VK_DOWN` 再 `VK_RIGHT`，菜单毫无反应，截图里连高亮都没有。

能用的手法：**`PostMessage(menuHwnd, WM_MOUSEMOVE, 0, MAKELONG(x, y))`**，
菜单的模态循环自己 `GetMessage` 到它，会做悬停高亮，停在带子菜单的项上一会儿自动展开。
坐标不要猜 —— 写个从 10 到菜单高度逐行扫描的循环，看 `#32768` 窗口从 1 个变 2 个就停。

（`--tray-menu-probe` 仍然负责"点了之后做什么"；菜单只是"长什么样"。）

## 7. 已知限制

1. **穿透模式下条右键用不了**（Q-12 的既定代价）。字段开关请走托盘右键。
2. **`--tray-menu-probe` 会写真实配置**。验证完要手动把 `TaskbarHiddenFields` 清回 `[]`。
3. 字段顺序固定按 7.4，不支持重排 —— 用户按"第三个是 GPU"记位置，重排反而是负担。
4. 让位只砍字段，不缩字号 / 不缩间距。8.4 已定不做白名单，这里保持同一条原则。
