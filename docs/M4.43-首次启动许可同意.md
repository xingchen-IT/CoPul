# M4.43 首次启动的许可协议同意

> 来源：`docs/发布合规评估-2026-11-04.md` 里唯一一个「当前不满足」的实体条件。
> 那份评估的结论是：**顺序不涉及合法性，合法性取决于 5 个实体条件，其中用户同意环节缺失**。
> 这一版把它补上。

## 问题

中国法院认可点击合同（杭州互联网法院等判例），前提是两条同时成立：

1. **条款可获取** —— 用户能读到完整条款；
2. **同意有记录** —— 能证明"某人在某时同意了某一版"。

当时的实现一条都不满足：`LICENSE` 只躺在仓库根目录，`LICENSE.txt` 虽然随包发了，但
双击 exe 就能直接用，程序里没有任何同意动作。真起纠纷，对方可以主张**合同未成立**——
那么「禁止二次分发」和免责声明这两段最关键的条款**全部用不上**，前面写的许可等于白写。

## 改法

| 文件 | 内容 |
| --- | --- |
| `Sdk/Eula.cs`（新增） | 协议版本常量 `Version = "1"`、正文读取（嵌入资源）、同意状态判定与落盘 |
| `EulaWindow.xaml(.cs)`（新增） | 720×660 的协议窗：可滚动全文 + 勾选框 + 「退出 / 同意并继续」 |
| `Sdk/ConfigStore.cs` | 新增 `LicenseAcceptedVersion` / `LicenseAcceptedAt` 两个字段 |
| `App.xaml.cs` | 启动闸门：单实例之后、建主窗口之前；另加 `--eula` / `--eula-pick` / `--eula-consent` 三个探针 |
| `CoPul.App.csproj` | 把根目录 `LICENSE` 以 `LogicalName=CoPul.App.EULA.txt` **嵌入程序集** |

### 几个刻意的选择

**正文嵌进程序集，而不是运行时读 `LICENSE.txt`。**
后者一旦文件被删（精简部署、用户清理目录），弹窗里就只剩一句摘要——而那恰好是最需要
完整条款的时刻。嵌入用的是同一份 `LICENSE` 文件，**不复制第二份正文**：两份文本迟早会
不一致，而"展示的协议"和"随包的协议"不一致比没有协议更危险。
`LICENSE.txt` 仍然复制到输出目录，给人读。

**只存版本号，不存「是否同意」。**
存 bool 的话，条款换了两代也永远问不到第二次。现在改协议 = 把 `Eula.Version` +1，
老用户自然会被重新询问一次，配置Migration 一行都不用写。

**三个探针开关**（否则所有取证都会被弹窗挡住）：

| 开关 | 作用 |
| --- | --- |
| `--eula` | 强制把窗口摆出来（**非模态**，好让 `--shot` 的定时器拍得到） |
| `--eula-consent` | 把勾选框摆成已勾选，拍"主按钮可用"的样子 |
| `--eula-pick accept\|decline` | 不弹窗，直接走同意/拒绝的收尾路径 |

所有 `--*-probe`、`--shot`、`--shot-screen`、`--stats`、`--hidden`、`--settings` 一律跳过闸门。

**窗是 `Topmost` 的。** 实测在全屏游戏正在跑时启动本程序，`ShowDialog` 抢不到前台，
窗口被压在游戏后面——用户看到的是"点了图标什么都没发生"，进程却一直停在等同意。
这是一次性的法务弹窗，压过别人比静默卡住更可接受。

**「同意」按钮默认禁用，勾选后才可点。**
只有一个按钮的话，误点一下就"同意"了，举证时对方会说"我根本没看"。勾选把动作拆成两步。

## 验收

编译 0 警告 0 错误。

### 1. 真路径：全新状态启动（清空同意字段，按正常方式双击）

用 `EnumWindows` 按 pid 枚举可见顶层窗口 —— **只有一个窗口，且是许可窗**：

```
visible windows: [('CoPul 许可协议', '0x9d1408')]
still running (未被自动退出): True
```

没有 `CoPul 芯脉`（主窗口）说明闸门确实卡在 `new MainWindow()` **之前**，
不是"先开主界面再弹窗"。

### 2. 同意之后：正常启动不再询问

```
visible windows: ['CoPul 芯脉']
```

### 3. 两条收尾路径

| 路径 | 结果 |
| --- | --- |
| `--eula-pick decline` | 进程 exit=0，**配置文件一个字都没写**（`LicenseAcceptedVersion` 仍为空） |
| `--eula-pick accept` | 写入 `'1'` / `'2026-11-04 00:38:09 +08:00'`，随后正常进入采集 |

### 4. 窗口本身

- 条款正文 `chars=3073`（含抬头与要点），不是空文本也不是兜底摘要；
- 未勾选时 `consent=False acceptEnabled=False`，勾选后 `consent=True acceptEnabled=True`；
- 截图见 `docs/M4.43-首次启动许可-未勾选.png` / `-已勾选.png`（浅色主题；
  深色主题走同一套 `DynamicResource`，主按钮前景绑定 `BrushBg` 自动反相）。

## 坑

- **`--eula --shot` 时窗口必须非模态**：`ShowDialog` 会阻塞 `OnStartup`，后面注册的截图
  定时器永远等不到（与 M4.30 的 `Loaded` 坑同源）。
- **整屏 BitBlt 拍不到这张窗**：第一次用 `shot.py` 抓屏，拍到的是全屏运行中的 Minecraft。
  这是 M4.33 那条结论的复现——**合成层 ≠ 扫描输出**；游戏走独立翻转时全屏抓取不含我们的窗口。
  所以"窗口是否真的出现"改用 `EnumWindows` + 窗口标题判定，像素只作辅助。
- **探针关窗不是"用户拒绝"**：非模态窗口在截图收尾时被 `Quit()` 关掉，`OnClosing` 会记一条
  "declined"。已加 `ProbeMode` 区分，否则回头看 trace 会误判有人在测拒绝路径。
- LICENSE 里那些 `======` 的 ASCII 下划线在弹窗里像漏了格式的代码，`Tidy()` 把**纯等号行**
  换成一条细横线，一个字都没改。

## 遗留

- 协议版本升级时的"增量告知"（现在只有"重新询问一次"，没有"变更了哪几条"的提示）。
- 安装器勾选同意（P0 的安装包那条）—— 与首启弹窗是二选一，**安装器做了就可以去掉弹窗**，
  但两者都保留也不算重复（先装后同意，条款仍然可获取）。
