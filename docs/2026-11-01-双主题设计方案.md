# 2026-11-01 双主题（白色默认 / 深色可选）设计方案

- 决策人：用户，2026-11-01
- 范围：**大窗口 + 设置页**（用户选定 A 案）
- 悬浮窗、任务栏条**不动**：它们各自有实测过的取色逻辑（玻璃深浅 / 跟随任务栏亮度），并入 App 主题会破坏已验证行为

---

## 1. 需求

用户原话：「大窗口界面和设置界面还是不是很好看，你来美化一下顺便添加一个白色的界面（能够自由切换）」

拆成三件事：
1. 新增**白色界面**，作为**默认**
2. 与现有深色**自由切换**（运行时即时生效，不重启、不重建窗口）
3. 顺手**美化**（不只是换色，卡片层级与信息密度一起调）

---

## 2. 技术前提验证（已实测，见 `tools/theme-probe/`）

方案 A 依赖三个假设，全部单独验证过：

| # | 假设 | 结果 |
| --- | --- | --- |
| 1 | 整本替换 `Application.Resources` 里的调色板字典，`DynamicResource` 会即时生效 | ✅ 390 元素 × 2 绑定，替换耗时 **7.31 ms**，颜色立刻变 |
| 2 | 已 `Freeze()` 的画刷可以放进字典并被解析 | ✅ 可用（项目现有 `Palette.Brush()` 的 Freeze 策略无需调整） |
| 3 | 可以来回切换（深→浅→深） | ✅ 均正确 |
| 4 | **反证**：`StaticResource` 静态取值是否会跟随 | ❌ 不会 —— 拿到的是当时的画刷实例 |

**结论**：必须**全量**改 `DynamicResource`，漏一处就是"切换后那一处颜色不变"。这是本方案唯一的机械风险点，用脚本 + 漏网扫描兜住（见第 7 节）。

## 3. 调色板拆分

现在 `Themes/Palette.xaml` 是**一本混合字典**，里面同时装着：
- 深色主体色（`BrushBg` / `BrushPanel` / `BrushTextPrimary` …）
- 悬浮窗浅色玻璃专用色（`BrushGlassTint` / `BrushTextSecondaryLight` / `Accent*Light` …）—— 这些**不随 App 主题变**

拆成三本：

```
Themes/PaletteDark.xaml    ← 深色主题色（键名 A 组）
Themes/PaletteLight.xaml   ← 白色主题色（键名 A 组，同名不同色）
Themes/PaletteShared.xaml  ← 两套共用：玻璃色、浅底语义色、字体（键名 B 组）
```

加载顺序：`Shared` 先、主题本后（主题本可覆盖同名键）。

**键名分组（这是设计的核心，写错会导致悬浮窗跟着 App 主题变）**

A 组（主题相关，两本各自定义）：
```
BrushBg  BrushPanel  BrushPanelHover  BrushStroke  BrushTrack
BrushDivider  BrushGrid
BrushScrollThumb  BrushScrollThumbHover  BrushScrollThumbDrag
BrushTextPrimary  BrushTextSecondary  BrushTextTertiary
AccentCpu  AccentGpu  AccentRam  AccentVram  AccentNet  AccentFps  AccentDisk  AccentPower
BrushWarn  BrushDanger  BrushOk
BrushShadow            ← 新增（卡片投影，白色界面必需）
BrushRowAlt            ← 新增（表格隔行底）
```

B 组（不随主题，`Shared` 独有）：
```
BrushGlassTint  BrushGlassSolid  BrushGlassEdge*  BrushGlassEdgeDrag*
BrushTextOnGlass  BrushTextSecondaryLight
Accent*Light（8 个）  BrushWarnLight  BrushDangerLight
FontUi / FontNumeric / FontMono
```

> **`FloatWindow` 的隐患**：`FloatWindow.xaml.cs:1844` 有
> `Shell.Background = light ? Brush("BrushGlassSolid") : Brush("BrushBg")` ——
> 深色玻璃用 `BrushBg`（会随主题变！）。白色主题下 `BrushBg` 变浅，悬浮窗深色玻璃的底会跟着变浅。
> **修法**：新增 B 组键 `BrushGlassSolidDark`（深色玻璃关玻璃时的底），悬浮窗改用它，与 App 主题解耦。

## 5. 美化（不只是换色）

白色界面如果只做反色，会出现两个问题：**卡片浮不起来**、**信息密度显空**。三处针对性调整：

### 5.1 卡片加投影（白色必需）
`MainWindow` / `SettingsWindow` 的卡片容器统一挂 `BrushShadow`：
```xml
<Border.Effect>
  <DropShadowEffect Color="#000000" BlurRadius="12" ShadowDepth="2" Opacity="0.06" />
</Border.Effect>
```
深色主题下同位置给 `Transparent`（用 `BrushShadow` 做 switch：白色 `#0F000000`，深色全透明）。

> **为什么不用 `BrushShadow` 当背景色**：`DropShadowEffect` 需要具体效果对象，且项目有 A-38 的教训——
> **WPF `DropShadowEffect` 在非 layered 窗口上会被内容裁剪**（M2 踩过，最终用了 DWM 系统阴影）。
> 主窗口是 `AllowsTransparency=False` 的普通窗口，`Effect` 在**内容层**是安全的（裁的是窗口外，不是卡片外），
> 但必须实测确认投影真的画出来了（第 7 节验收项）。

### 5.2 指标数值层级（白色下更需要）
白色底上"数值 24px + 单位 12px + 标签 12px"三者如果都同色，会显得平。调整：
- 数值：`BrushTextPrimary` 保持
- 单位：从 `BrushTextSecondary` 提到 `BrushTextTertiary` 的**浅一档**（白色下单位不该抢数值）
- 标签：`BrushTextSecondary`

### 5.3 切分区块的"呼吸感"
白色界面卡片之间间距 12 → **14**，卡片内边距 14 → **16**。理由：白色底缺少深色那种"暗部自然分割"，
需要更多留白来区分区块（深色不动，保持现有 12/14）。

> 这一条用 `DynamicResource` 做不了（`Thickness` 不是画刷）。**实现方式**：代码里读主题后统一设
> `MainWindow.ContentPaddingScale` / `SettingsWindow` 同名字段（默认 1.0，白色 1.12），
> 由 XAML 绑定到各个 `Margin`/`Padding`。**若实测效果不明显则跳过**（不让它变成复杂度的借口）。

## 6. 切换与持久化

### 6.1 入口
**只有一个**：设置页「常规」顶部新增「外观」卡片，两档分段（`Segment` 样式复用）：
- **白色（默认）**
- **深色**

选中即生效。不在标题栏/右键菜单加第二入口 —— 两处入口会有状态不同步风险。

### 6.2 实现
```csharp
// Sdk/ThemeManager.cs（新增）
public enum AppTheme { White, Dark }

public static class ThemeManager
{
    public static AppTheme Current { get; private set; } = AppTheme.White;

    // 启动时调一次
    public static void Apply(AppTheme theme, bool persist);

    // 运行时切换：替换 Theme 字典那一本 + 清 Palette 缓存 + 重建 DropShadow 效果
    public static event Action? Changed;
}
```

**替换细节**：`Application.Resources.MergedDictionaries` 里按**标记键**定位主题那一本
（`__theme = "dark" / "light"`），只换那一本、`Shared` 保持不动。避免"整本清空"把字体也弄丢。

### 6.3 Palette 缓存失效（关键）
`MetricCell.cs:139` 的 `Palette` 有 `static Dictionary<string, Brush> Cache`，
**切主题后不清就会一直返回旧画刷**。加：

```csharp
internal static void InvalidateCache() => Cache.Clear();
```

并在 `ThemeManager.Apply` 里调。同时 `MetricCell` 等 VM 的画刷属性是「每次 get 现查」，
清缓存后下一次刷新自然取到新色 —— 不需要额外通知（0.5s 内就会重绘）。

> 但**静态字段**除外：`FloatWindow.xaml.cs:1947-1964` 有一组 `private Brush _edgeNormal = Palette.Brush(...)`
> 在字段初始化时取值，只赋一次。这些属于悬浮窗（不在本次范围），且悬浮窗有自己的主题，**不动**。

### 6.4 持久化
`ConfigStore` 新增：
```csharp
/// <summary>App 级主题（大窗口 + 设置页）。"White" / "Dark"。默认 White。</summary>
public string AppTheme { get; set; } = "White";
```
存字符串（与 `FloatTheme` 一致，插入新枚举值不会整体错位）。

## 8. 实施记录与变更（2026-11-01 实做阶段）

### 8.1 用户中途变更：白色界面**不要阴影**

设计最初为白色主题加了卡片投影（5.1 节），实做后逐像素调参（alpha 6%→3.5%、Blur 12→14、卡片间距 12→18），
投影确实画出来了，但用户明确要求"白色界面不需要阴影，直接去掉阴影"。

**已全部移除**：
- 删除 `Sdk/CardShadow.cs`（附加属性 + 视觉树遍历 + 主题变化重建）
- 删除 `Styles.xaml` 里 `BlockCard` 的 `CardShadow.Enabled` 标记与 `xmlns:sdk`
- 删除 `App.xaml.cs` 三处接线（两个 `ContentRendered` + 一个 `ThemeManager.Changed`）
- 删除两本调色板里的 `BrushShadow` 键（深色本就是全透明、白色已不再使用）
- 卡片间距 **18 → 12** 复原（那 6 DIP 本就是给投影腾地方的）

**替代方案：靠底色差分层的重新配平**（这是"去掉阴影后如何还浮得起来"的答案）

去阴影后实测问题：卡片 `#FFFFFF` 对窗口底 `#F2F4F7` 只差 13/11/8 个色阶，而描边 `#DDE3EA` 也很淡，
九张卡连成一片、像"一张大白纸上画了几条线"。解法是把**窗口底压深**：

| | 原值 | 改动后 | 说明 |
| --- | --- | --- | --- |
| `BrushBg` | `#F2F4F7` | **`#EDF0F4`** | 窗口底压深 5 个色阶 |
| `BrushPanel` | `#FFFFFF` | `#FFFFFF` | 卡片保持纯白 |
| `BrushStroke` | `#DDE3EA` | `#DDE3EA` | 描边已比深色主题更明确 |

实测效果：卡片与底差 18/15/11 个色阶，配合描边，分层清晰且**没有任何灰带**
（阴影方案的副作用是 12 DIP 缝里塞满阴影，实测缝内像素被压成 (113,114,115) 一条硬灰带）。

> **方法论**：「让元素浮起来」有三条路 —— 投影、底色差、描边。
> 投影在**窄间距**的多卡片布局里天然容易塞满缝隙（越浅越看不见、越重越脏），
> 而底色差是零成本、无异味的那条。这次是被用户否掉投影后才发现底色差更好。

### 8.2 与原设计的其他差异

| 项 | 设计 | 实做 | 原因 |
| --- | --- | --- | --- |
| 语义色来源 | 复用 `*Light` 那组值 | 同设计 | 白底对比度已验 ≥4.5:1 |
| `BrushOk` | 压暗到 `#3F8A4C` | 同设计 | 白底 4.6:1 |
| 5.2 指标层级微调 | 调整单位颜色层级 | **未做** | 白色主题下现观感已可接受，不做无效改动 |
| 5.3 间距 12→14 / 内边距 14→16 | 白色加呼吸感 | **未做** | 同上；实际只把窗口底压深就够分层了 |
| `FloatWindow` 玻璃底解耦 | `BrushGlassSolidDark` | 同设计 | 已验证 App 主题切换不影响悬浮窗 |

### 8.4 新增自测开关

| 开关 | 用途 |
| --- | --- |
| `--app-theme white\|dark` | 临时覆盖主题、**不写盘**，用于双主题验收截图 |
| `--settings-probe 'theme:white,theme:dark'` | 走**真实分段选择**（`RadioButton.IsChecked` 触发 Checked 事件）验运行时切换链路，而不是直接调 `ThemeManager.Apply` |

> 后者是关键：直接调 `Apply` 只能验"颜色换了"，验不到"用户点这一下"的整条链路
> （RadioButton 状态同步、写盘、`ThemeManager.Changed` 通知）。
