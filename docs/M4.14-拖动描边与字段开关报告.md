## 1. 拖动描边：白 → 粉，且松手立刻撤

### 1.1 为什么"松手后白边不及时消失"

M4.13 已经把拖动期间的描边压回常态、并把深色悬停档从 22% 白降到 14% 白，
但用户仍然看到"松手后还挂着一圈白边"。原因在恢复那一步写错了：

```csharp
// M4.13 的写法（错）
finally { Shell.BorderBrush = Shell.IsMouseOver ? _edgeHover : _edgeIdle; }
```

`DragMove()` 是模态移动循环，**松手那一刻鼠标 100% 还在窗口上**（否则拖不动），
所以这个三元永远取到 `_edgeHover`。语义上等于"把粉色/常态换成悬停色继续挂着"，
用户看到的"没消失"其实是"换了一种白继续在"。

### 1.2 改动

| 文件 | 改动 |
| --- | --- |
| `Themes/Palette.xaml` | 新增 `BrushGlassEdgeDrag` `#E8489B`（浅色底）/ `BrushGlassEdgeDragDark` `#FF7FB8`（深色底） |
| `FloatWindow.xaml.cs` | 新增 `_dragging` + `_edgeDrag`；`BeginDragVisual()` / `EndDragVisual()` |
| `FloatWindow.xaml.cs` | `EndDragVisual()` 一律回 `_edgeIdle`（**不再判 `IsMouseOver`**），并 `InvalidateVisual()` |
| `FloatWindow.xaml.cs` | `Shell_MouseEnter` / `MouseLeave` 加 `if (_dragging) return;` |
| `App.xaml.cs` | `--float-drag-probe keep\|release` |

`MouseEnter/Leave` 那两句守卫是必需的：`DragMove` 循环期间 WPF 仍会派发鼠标进出事件，
没有守卫的话粉色会在拖动中途被悬停色盖掉，看起来像"一拖就变白"。

### 1.3 取证（`--float-drag-probe`，RTB 走视觉树、颜色是准的）

```
keep     during=#FFFF7FB8  after=#FFFF7FB8  idle=#24FFFFFF  hover=#24FFFFFF
release  during=#FFFF7FB8  after=#24FFFFFF  idle=#24FFFFFF  hover=#24FFFFFF
```

- `keep`：停在粉色上供拍照 → `preview-m4.14-drag-pink.png`，粉边完整包围一圈（圆角闭合）。
- `release`：`after` 与 `idle` 完全相等 → 松手即回常态，**不再是"换一种白继续挂着"**。

## 2. 首进竖向尺寸不对：隐藏期间改过布局，Show 时不会自己跟上

### 2.1 这条最难的地方是"复现不了"

用户报的是宽度，但按描述直接构造的两条路都量到了正确结果：

| 路径 | 结果 |
| --- | --- |
| `--float --float-vertical`（直接起竖向） | 47.33×272 DIP / 71×408 px |
| 大窗 → 切悬浮窗（`--switch-view float@2500`） | 47.33×272 DIP / 71×408 px |

**原因是取证工具本身有个洞**：`--shot` 走 `RenderTargetBitmap`，它按 `ActualWidth/Height`
（WPF 布局值）作画，**量不到 HWND 实际多大**。布局值与 HWND 尺寸不一致时，截图看起来
完全正常，而用户屏幕上看到的就是"宽度不对"。

补了一个 `HwndDiag`，把 HWND 物理矩形、`ActualWidth`、`SizeToContent`、`Width` 当前值
一起写进 sidecar：

```
hwnd : hwnd=(1960,197)-(2031,605) 71x408px dip=47.33x272.00 stc=WidthAndHeight vertical=True width=47.33
```

### 2.2 真正的触发条件：窗口隐藏期间布局被改过

用新增的**时序探针** `--switch-view "float@800;main@3000;field:ram@4000;field:vram@4200;float@5000"`
（先显示 → 回大窗 → **隐藏期间**关掉两格 → 再显示）做 A/B：

| 构建 | 竖向尺寸 | HWND | 结论 |
| --- | --- | --- | --- |
| 关掉显示时重排（`--no-relayout-on-show`） | **47.33×272.00** | 71×**408**px | ❌ 停在旧尺寸，布局没生效 |
| 当前（每次显示强制重排） | 47.33×**168.00** | 71×**252**px | ✅ 与全新窗口一致 |

对照基准（全新窗口直接关掉同样两格，`--float --float-vertical --float-field-probe "ram,vram"`）
也是 `47.33×168.00` —— 说明 168 才是正确值，272 是**过期值**。

这正好解释了"随便改一下设置就好了"：任何外观设置改动都会走 `ApplyScale()`，
里面顺带做了 `SizeToContent` 切换 + `UpdateLayout`，过期尺寸就被冲掉了。

### 2.3 改动

| 文件 | 改动 |
| --- | --- |
| `FloatWindow.xaml.cs` | `IsVisibleChanged` → 每次变可见就 `RelayoutNow()` |
| `FloatWindow.xaml.cs` | `RelayoutNow()`：`InvalidateMeasure` + `Shell.InvalidateMeasure` + `UpdateLayout`，首帧之后补 `EnsureFullyVisible` + `SavePlacement` |
| `App.xaml.cs` | `--switch-view` 升级为时序序列（`view@ms` / `layout:row\|column@ms` / `field:<key>@ms`，分号分隔） |
| `App.xaml.cs` | `--no-relayout-on-show`（A/B 开关）、`--shot` 的 sidecar 增加 `hwnd:` 一行 |

### 2.4 一个试错：不要在显示时把 `Width/Height` 清成 NaN

看 `SizeToContent` 会把实测值**写回** `Width`（实测 `width=47.33` 而不是 `NaN`），
第一版顺手在 `RelayoutNow()` 里加了"竖向下把 `Width/Height/ShellHeight` 清成 NaN 再量"。
**实测这是负优化**：

```
加了 NaN 重置   → 47.33×272.00（回到错误值），且 Width 读回来仍是 NaN
撤掉后          → 47.33×168.00（正确）
```

隐藏状态下把尺寸清成 NaN 之后，WPF 不会给 HWND 重新定尺寸（Show 之后 `Width` 仍读到
`NaN`，HWND 停在旧值）。而 `SizeToContent` 自己写的那个定值，在
`InvalidateMeasure + UpdateLayout` 之后是会跟着内容走的。这行已撤回，并在代码注释里写明了原因。

## 3. 悬浮窗字段开关

与任务栏条**分成两套**（`FloatFields` vs `TrayFields`）：悬浮窗只有六项，且"关掉之后怎么收缩"
与任务栏完全不同（任务栏是九格里挤，悬浮窗宽高都由内容撑着）。

| 文件 | 改动 |
| --- | --- |
| `Sdk/FloatFields.cs` | 新增。`Keys` / `Labels` / `IsVisible` / `VisibleCount` / `LabelOf` / `Toggle` |
| `Sdk/ConfigStore.cs` | 新增 `FloatHiddenFields`（与 `TaskbarHiddenFields` 各存一份） |
| `FloatWindow.xaml` | 横竖两套面板的六格加 `x:Name`（`RowFps…RowNet` / `ColFps…ColNet`）；原「显示字段」禁用项换成可展开的 `FieldMenu` |
| `FloatWindow.xaml.cs` | `BuildFieldMenu()`（按 `FloatFields.Keys` 生成子项）、`ApplyFieldVisibility()`、`ReloadFields()`、`RelayoutNow()` |
| `FloatWindow.xaml.cs` | `EstimateVerticalLength()` / `AllFields` 只计**可见**字段 |
| `SettingsWindow.xaml` | 「悬浮窗字段」卡片（`UniformGrid` 3 列）+ 提示文案 |
| `SettingsWindow.xaml.cs` | `InitFloatFieldGrid()`、`LoadFromConfig`、`UpdateFieldEnabled`（只剩一个时置灰） |
| `App.xaml.cs` | `--float-field-probe <key,key>` |

关闭的字段**不占位**：横向条变窄、竖向条变矮。

## 4. 顺手修掉的一个验收陷阱：探针会污染用户配置

字段类探针改的是共享的那份 `AppConfig`，而**主窗口关闭时也会整份落盘** ——
实测跑一次 `--float-field-probe` 就把 `FloatHiddenFields` 永久写成了 `["ram","vram"]`，
之后每次验收量到的都是"上次探针留下的尺寸"（B 组突然从 272 变 168 就是这么来的）。

改法：`FloatWindow.ProbeToggle()` 在第一次改字段时备份原数组，并挂
`Application.Current.Exit` 在最末尾写回 —— 位置比任何窗口的 `Closing` 都晚，
谁先存都不会把它带走。同时给 `--float-drag-probe` / `--float-field-probe` /
`--switch-view field:` 都设了 `PersistToConfig = false`。

验证：跑完 `field:ram,field:vram` 之后 `config.json` 里仍是 `"FloatHiddenFields": []`。

## 6. 新增的自测开关

| 开关 | 用途 |
| --- | --- |
| `--float-drag-probe keep\|release` | 进入 / 退出拖动外观，把三个描边色写进 sidecar |
| `--float-field-probe <key,key>` | 首帧后逐个翻字段开关，输出 `win=` 与各格状态 |
| `--switch-view "<v>@<ms>;…"` | 时序序列：`view@ms` / `layout:row\|column@ms` / `field:<key>@ms` |
| `--no-relayout-on-show` | 关掉"每次显示强制重排"，A/B 对照用 |

> `--shot` 现在会给 `FloatWindow` 写 `.info.txt` sidecar（`size` / `px` / `hwnd` / `scale` / `place`），
> 宽度类问题必须看 `hwnd:` 那一行 —— RTB 量不到 HWND。
