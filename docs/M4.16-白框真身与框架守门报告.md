# M4.16 白框真身：DWM 的 8px 框架 + 框架守门

> 现象（用户报）：**「移动过位置之后再点击别的页面就会出现白框，横向也是这样」**
> 结论：那圈白**不是我们画的描边**，是 `WS_THICKFRAME` 带来的 DWM 框架（150% 下单边 10px），
> 系统浅色主题下画成白色。修法是加一个「框架守门」，发现几何被算回去就纠正。

---

## 1. 排除：不是我们的描边

`Shell.BorderBrush` 只有三个来源（常态 / 悬停 / 拖动）。用新探针
`--float-move-focus-probe` 做四组对照（移动 / 拖动收尾 / 失焦，任意组合）：

| 组合 | border before | border after | active |
| --- | --- | --- | --- |
| `move,drag` | `#24FFFFFF` | `#24FFFFFF` | True |
| `move,drag,defocus` | `#24FFFFFF` | `#24FFFFFF` | **False** |
| `defocus` | `#24FFFFFF` | `#24FFFFFF` | False |
| `frame`（主动通知框架变更） | `#24FFFFFF` | `#24FFFFFF` | True |

全程恒定 `#24FFFFFF`（白 14%）。**松手、失焦都不会让描边变**，所以白框不在这一层。
（失焦那两组的 `active=False` / `fgIsSelf=False` 证明"点别处"这步真的生效了。）

## 2. 定位：10px 宽的纯白竖带

在用户那张截图上按像素量（189×480）：

- 两条**纯白 `#FFFFFF`（luma 255）**的竖带：`x=57..66`、`x=119..127`
- 每条 **10px 宽**，纵向覆盖 405/480 行 —— 缺的正是**上下圆角**那两截，形状跟着窗口轮廓走
- 中间 `x=67..118` 是内容区（luma 152），外侧 `x<57` 是桌面背景（luma 130）

宽度 10px 是关键：我们的描边是 2 DIP（150% 下 3px），对不上；
而 `WS_THICKFRAME` 的 8px 框架在 150% 下是 **8 × 1.5 ≈ 10 物理像素**，正好。

## 3. 反例实验：把框架放出来量一量

新增 `--no-nccalc` 关掉「把客户区铺满整个窗口」这一步（`WM_NCCALCSIZE` 返回 0）：

| | 窗口尺寸 (DIP) | 截图区域 (含 pad) |
| --- | --- | --- |
| 吃框架（正常） | 47.33 × 272.00 | 113 × 450 |
| `--no-nccalc`（框架露出） | **61 × 285**（每边多 ~7 DIP） | 133 × 470 |

量出来单边 gap 正好 **10px** —— 和截图里那条白竖带同宽。

颜色也对得上：系统 `AppsUseLightTheme = 1`（浅色主题），DWM 的窗口框架就是白的。
（我这台机器跑 `--no-nccalc` 时底层是 `--backdrop #0A0A0A` 纯深底，框架区透出深底所以是暗的；
用户桌面上是浅色，露出来就是白框。同一件事，背景不同观感不同。）

## 4. 修法：框架守门

`WM_NCCALCSIZE` 不是每次重绘都来，DWM 偶尔会用「带框架」的几何，于是窗口四周多一圈。
守门不去猜时机，而是**每次可能变化后量一次**，不一致就补一次"框架已变"，让 DWM 重新问一遍：

```csharp
LocationChanged / SizeChanged / Activated / Deactivated / DpiChanged → GuardFrame()
+ 1Hz 兜底巡检（窗口不可见时跳过）

GuardFrame()：client == window ? 什么都不做 : NotifyFrameChanged(hwnd)
```

三条纪律：

- **只在真的不一致时才动**。通知用的是 `SWP_NOMOVE|NOSIZE|NOZORDER|NOACTIVATE|FRAMECHANGED`，
  不改几何也不触发重排，但没必要每秒发一次（任务栏条 1Hz 巡检的教训：每次 `SetWindowPos` 都会重排）。
- **判据是几何，不是画刷**。白框是我们看不见的那一层，`Shell.BorderBrush` 查不出来。
- **自测开关 `--no-frame-guard`** 留着做 A/B。

## 5. 取证

| 场景 | 结果 |
| --- | --- |
| 常规启动（横 / 竖） | `guardHits=0`，尺寸 380.67×34 / 47.33×272 与基线一致 → **零干预** |
| `--float-move-focus-probe framebreak` | `break=10/10 -> guard=0/0 hits=1` → 放出来 10px，守门收回 0 |

`framebreak` 是专门用来自证的：先把 `EatFrame` 关掉并通知框架变更（人工制造"框架露出来"），
量到 gap，再打开守门量一次。守门能修，这条才成立 —— 否则只是加了个没验证过的动作。

## 6. 新增的自测开关

| 开关 | 用途 |
| --- | --- |
| `--float-move-focus-probe move,drag,defocus,frame,framebreak` | 复现"挪过位置 + 点别处"；`framebreak` 自证守门 |
| `--no-nccalc` | 不吃框架，看 8px 露出来什么样（反例） |
| `--no-frame-guard` | 关掉守门做 A/B |

sidecar 新增 `ncCalcHits` / `guardHits` / `window=… client=… gapLR=… gapTB=…` 三行，
以及 `active` / `fgIsSelf`（确认失焦这步真的生效）。
