# M4.52 许可协议切换为 GPL-3.0

> 2026-11-05。上午的许可讨论落到了代码里：从「专有、禁止二次分发」改为「GPL-3.0 自由软件」。
> 本文记录为什么选它、改了哪些地方、哪些地方**没**改。

## 1. 起因

原始诉求是「源码可见、可改、改后可分发，但不能原样搬运分发」。这个组合在标准许可里不存在：

- OSI 开源定义第 1 条要求允许自由再分发，凡 OSI 认可的协议都**强制**允许原样分发；
- 所有非开源的 source-available 协议（PolyForm、FSL、BUSL、Elastic）都允许原样分发，
  只限制商用 / 竞争 / 部署场景；
- 「允许改后分发」与「禁止原样分发」互相消解 —— 改一个字符就算修改版。

最终选择加入开源行列，并选定 GPL-3.0。

## 2. 为什么是 GPL-3.0

### 2.1 不是 MIT / Apache-2.0

两者都允许他人闭源商用，与「不想被白嫖」的核心诉求相反。

### 2.2 不是 MPL-2.0

MPL 是**文件级** copyleft，优势在被集成进其他项目时保留隔离。CoPul 是终端应用，别人要
基于它开发只能 fork 整个程序 —— 要么全开（GPL），要么全闭（侵权）。MPL 在这里约等于半个 MIT。

### 2.3 不能是 GPL-2.0（硬约束）

依赖里有 **Apache-2.0** 的 HidSharp 2.6.4（见 `docs/依赖许可审计-2026-11-05.md`）。
Apache-2.0 与 GPLv2 因专利条款互不兼容，与 GPLv3 兼容（GPLv3 第 11 条给出了专利授权）。
**选 GPL-2.0 会让整个项目失去合法的分发依据。**

### 2.4 不是 AGPL-3.0

AGPL 的增量条款针对「通过网络提供服务」。CoPul 是本地桌面程序，该条款永不触发，只会抬高
企业用户的法务门槛 —— 零收益、纯成本。

## 3. 兼容性核对

| 组件 | 许可 | 与 GPL-3.0 | 依据 |
| --- | --- | --- | --- |
| LibreHardwareMonitorLib 0.9.6 | MPL-2.0 | 兼容 | MPL-2.0 §3.3 允许以 GPL-2.0+ 作为 secondary license；且仅以**未修改**的程序集引用 |
| HidSharp 2.6.4 | Apache-2.0 | 兼容 | Apache-2.0 与 GPLv3 兼容（FSF 认定） |
| PresentMon | MIT | 兼容 | 独立进程调用，不构成衍生作品 |
| .NET 8 运行时 | MIT | 兼容 | 自包含发布随包分发 |
| PawnIO | 用户自装 | 不涉及 | 不随包分发 |

结论：不需要替换任何依赖，也没有「MPL 部分必须单独保留」的额外义务（未修改过 LHM 任何文件，
源码地址已在 `THIRD-PARTY-NOTICES.txt` 中给出）。

`LICENSE` 仍是**唯一事实源**：它既复制到输出目录（`LICENSE.txt`，给人读），也以
`EmbeddedResource LogicalName=CoPul.App.EULA.txt` 嵌入程序集（弹窗正文）。改一处，两边同时变 —— 这个
设计从 M4.43 起就是这样，切换协议时省掉了「两份正文不一致」的隐患。

## 5. EULA 的语义变了，不只是文案

原来（v1）是**点击合同**：不同意的用户被拒绝运行，理由是「中国法院认可点击合同，前提是
条款可获取 + 同意有记录」。

GPL-3.0 第 9 条明确「运行本程序不需要接受本许可」。继续写「同意才能用」既没有法律收益，
反而给对方留下「你附加了额外限制」的抓手（GPL 第 7 条禁止 further restrictions）。

所以 v2 的定位改成**一次性告知**：

- 勾选文字去掉「同意」，改为「我已阅读上述条款」；
- 主按钮「继续」而不是「同意并继续」；
- 脚注写明「GPL-3.0 已直接授予你运行、修改与再分发的权利；这里的勾选只表示已阅读」；
- 配置字段名 `LicenseAcceptedVersion` / `LicenseAcceptedAt` **保留不改**（改名会让老配置失效、
  触发无意义的二次弹窗），只把界面标签改成「阅读记录」。

弹窗机制本身保留：它仍是唯一能保证用户「看见许可全文」的途径，GPL §0 也要求交互界面展示
Appropriate Legal Notices。

## 6. 实测

### 6.1 编译

Release，**0 警告 0 错误**。

### 6.2 许可窗渲染 36 KB 全文

GPL 全文 674 行，加头部导读共 36 454 字符（v1 约 5 000 字）。`TextBlock` 在 `ScrollViewer`
里全量布局，没有做虚拟化：

```
eula: version=2 chars=36454 consent=False accepted=False modal=False readonly=False
```

目视核对（截图未入库）：中文导读 + 英文正文开头、右侧滚动条可用、底部勾选与「退出 / 继续」
按钮齐全，无重叠无截断。窗口高度策略未改（仍按工作区收缩，1366×768 上可用）。

### 6.3 完整启动流程（模态生产路径）

`--eula-auto-accept`（1.2 s 后自动勾选并点确认）：

```
eula: version=2 chars=36454 consent=True accepted=True modal=True readonly=False
config: LicenseAcceptedVersion="2"   LicenseAcceptedAt="2026-11-05 17:53:12 +08:00"
```

「弹窗 → 确认 → 主窗口」整条路径与 v1 一致，M4.45 修过的「协议窗一关就退出」没有复发。

### 6.4 关于页

```
about: version=0.1.0 (49defdb) build=2026-11-05 17:51 license=v2
       acceptedAt='2026-11-04 00:56:32 +08:00' noticesChars=2712 icon=ok
```

目视核对：类型「GNU 通用公共许可证第 3 版（GPL-3.0）· 自由软件」、协议版本
「CoPul 许可协议 v2 · 2026-11-05 生效」、阅读记录原样显示旧时间戳（未被探针改写）。

### 6.5 配置污染

探针跑完把 `config.json` 从测试前备份恢复，`diff` **逐字节一致**，
`LicenseAcceptedVersion` 回到 `"1"` —— 用户第一次装新版时仍会看到 GPL 弹窗，这是预期行为。

## 7. 没做的事

- **没有升版本号，也没有重新打包。** 0.1.0 已经挂着专有协议的安装包（Release 私有、下载量 0）。
  同一个号对应两套协议会让「哪个包是 GPL」说不清，建议发 **0.1.1**。
- **没有改仓库可见性。** 公开是不可逆操作；公开前还要在 Release 里补「未签名 → SmartScreen」
  的说明。
- **没有给每个 `.cs` 加 SPDX 文件头。** GPLv3 §5(a) 要求「作品显著声明其受本许可约束」，
  `LICENSE` + README + 关于页 + 每次启动的告知窗已经满足；逐文件加头会在 60 多个文件上
  制造无意义 diff。

## 8. 后续要注意

1. **别再引入 GPL 不兼容的依赖。** Apache-2.0 可以；EPL-1.0、CDDL-1.0、MPL-1.1 不行。
   加包前跑一遍 `docs/依赖许可审计-2026-11-05.md` 里的命令。
2. **发版时二进制旁边要给源码。** GPLv3 §6(d) 允许通过同一网络服务器提供，链到仓库对应
   tag 即可，不必把源码塞进安装包。
3. **商标不随代码走。** 「CoPul」名称与图标没有授权，衍生版本必须换名换标 —— 这句已经写进
   README、关于页和发行说明，后续版本别漏掉。
