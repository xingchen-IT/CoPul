# 性能复测（2026-11-05）

承接 [M4.35](M4.35-性能测试.md)。这次是在 **M4.50 单文件发布之后**、用即将发布的
`CoPul-0.1.0-win-x64` 产物实测的，目的是给 README 一组"用户拿到的那个 exe"的数字，
而不是开发目录里的 `bin\Release`。

## 测量口径

- 被测程序：`artifacts/CoPul-0.1.0-win-x64/CoPul.exe`（单文件自包含，151 MB）
  复制到 `D:\CoPulPerf\` 运行 —— 工作区带 Low 完整性标签，原地跑会以 Low IL 启动
  并写不了 `%TEMP%`，见 [M4.48](M4.48-安装器与卸载器.md) 坑 #4。
- 机器：i7-13650HX（14 核 20 线程）+ RTX 4060 Laptop + Windows 11，单实例串行测量。
- 窗口 60 s、预热 10 s，取**窗口内增量**（`--stats` 的 frames/均值已扣掉 warmup）。
- **普通权限**（`admin: False`）：PresentMon 的 FPS 会话与 NVMe 盘温读不到，
  这部分成本没有计入。
- 每个场景重复 2～4 次，**取中位数**。个别场景波动接近 0.8 个百分点（见末节）。
- 采集间隔用 `--sample-interval` 显式指定，分别测 500 ms（当前默认）与 1000 ms 两档。

## 结论

### 500 ms 档位（默认）

| 场景 | 各次单核占用 | 中位数 | 整机占用（÷20） | 每拍 ApplySnapshot | 每拍 Layout |
| --- | --- | --- | --- | --- | --- |
| 无窗口（只有采集） | 1.380 / 1.120 | **1.3%** | 0.063% | 0.2–0.3 ms | 0.004 ms |
| 大窗口 · 数据冻结 | 0.729 / 0.963 | **0.8%** | 0.043% | — | — |
| 悬浮窗 | 1.718 / 2.499 / 2.265 / 2.134 | **2.2%** | 0.110% | 0.3–0.4 ms | 1.5 ms |
| 任务栏条 | 2.197 / 2.324 | **2.3%** | 0.113% | 0.3 ms | 1.4 ms |
| 大窗口 · 每拍更新 | 2.707 / 2.574 | **2.6%** | 0.132% | 0.8 ms | **4.8 ms** |

### 1000 ms 档位（单次测量）

| 场景 | 单核占用 | 整机占用（÷20） | 每拍 Layout |
| --- | --- | --- | --- |
| 无窗口（只有采集） | 1.0% | 0.048% | 0.004 ms |
| 大窗口 · 数据冻结 | 1.5% | 0.077% | — |
| 悬浮窗 | 1.8% | 0.092% | 1.6 ms |
| 任务栏条 | 1.9% | 0.097% | 1.7 ms |
| 大窗口 · 每拍更新 | 2.3% | 0.117% | **5.9 ms** |

**一句话**：默认档位下最坏情况（大窗口常开）约 **2.6% 单核 / 0.13% 整机**，
把采集间隔放宽到 1000 ms 降到 2.3%；覆盖层两档都在 2% 上下。

## 三条判读

**1. 成本在"更新那一帧"，不在常驻采集。**
冻结数据后大窗口 500 ms 档 0.8%、1000 ms 档 1.5%，与完全无窗口的 1.0%–1.3% 落在同一区间。
静止的窗口不重绘，不会像某些监控软件那样空烧。两档之间 freeze 与 idle 谁高谁低不一致，
说明这个差值本身就在噪声量级 —— 判读只能取"持平"，不能取具体高低。

**2. 大窗口的 Layout 仍是唯一大头。**
500 ms 档每拍 4.8 ms × 100 拍 = 480 ms / 60 s ≈ **0.80% 单核**，
占"大窗口 − 无窗口"差值（1.3 个百分点）的六成。两个覆盖层只要 1.4–1.5 ms，
因为它们只有一行多格子，没有 20 核网格与三张趋势曲线。

**3. 500 ms 档的 UI 更新被天然合批，所以没到 1000 ms 的两倍。**
60 s 内采样 120 次，实际只产生 86–103 次 `ApplySnapshot`（1.4–1.7 Hz）。
和 M4.35 的结论一致，这次没有变化。

## 与 M4.35 的差异

| 场景（1000 ms） | M4.35（2026-11-02） | 本次（2026-11-05） | 变化 |
| --- | --- | --- | --- |
| 无窗口 | 1.066% | 0.963% | −0.10 |
| 大窗口 | 1.976% | 2.344% | **+0.37** |
| 悬浮窗 | 1.562% | 1.848% | +0.29 |
| 任务栏条 | 1.431% | 1.938% | +0.51 |
| 大窗口冻结 | 1.016% | 1.536% | +0.52 |

三次采样全是单次、机器后台状态不可控（两次测量之间跑过打包、安装、卸载与多轮探针），
**0.3–0.5 个百分点的差异不足以归因到代码**。可以确认的只有：量级没变（都在 1–2.6%），
没有出现回归。真要追究就得在同一时刻做 A/B（两个二进制交替跑），这次没做。

## 测量条件与局限

- **非管理员**：少了温度 / 功耗 / 硬盘 / FPS 四项采集，真实实例会略高；
  M4.28 记过管理员比普通权限高约 0.5 个百分点。
- **噪声**：悬浮窗四次测量 1.72 / 2.13 / 2.27 / 2.50，极差 0.78 个百分点，
  所以 README 里给的是中位数与一位小数，不是单次值。
- **单文件发布**：解压缓存落在 `%TEMP%\.net\CoPul\`（约 9.6 MB），启动期一次性成本，
  不计入 60 s 窗口；启动耗时与 M4.50 记录一致，没有变慢。
- 探针会改写 `%APPDATA%\CoPul\config.json`（`--sample-interval` 会落盘），
  测量前备份、收尾核对恢复。
