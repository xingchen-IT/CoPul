## 2. 毛玻璃：三次失败才走通（A-35）

这是本阶段唯一的未知项，实测推翻了"优先用新 API"的直觉。

### 2.1 实验记录

| # | 做法 | 窗口内部像素（同一行 10 个采样点） | 结论 |
| --- | --- | --- | --- |
| 1 | `DWMWA_SYSTEMBACKDROP_TYPE = Acrylic`，`SourceInitialized` 里设透明底 | 全部 `#050608` | 纯黑，没透出 |
| 2 | 同上 + `DwmExtendFrameIntoClientArea(-1)` | 全部 `#3C3D3F` | 均匀 tint，没有模糊 |
| 3 | 只留 systembackdrop，`Loaded` 里补设透明底 | 全部 `#050608` | 仍纯黑 |
| 4 | 改 `SetWindowCompositionAttribute` + `ACCENT_ENABLE_ACRYLICBLURBEHIND` | `152030 / 191C1F / 1E2123 / … / 25292D` | **有变化，背景透出** |

`#050608` 这个值本身就是诊断线索：`#0F1216 × 35% = (5, 6, 8)`，正好等于"着色层叠在纯黑上"。

### 2.2 根因

**WPF 的非 layered 窗口走不透明 DXGI swapchain。** `DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE)`
会返回 `S_OK`——参数合法、系统也接受——但 DWM 拿不到窗口的 alpha，backdrop 没有可透出的地方，
于是画成纯黑。这条路上"API 成功"和"渲染成功"是两件事。

`DwmExtendFrameIntoClientArea` 是它的上一代方案（sheet of glass）：把客户区标成玻璃边框区，
DWM 改用老式 tint 填充。**两者互斥**，并用后模糊被 tint 覆盖，所以第 2 次实验得到均匀灰。

accent 方案（`WCA_ACCENT_POLICY`）不依赖 swapchain alpha——它是 DWM 在窗口**后方**注入的一层，
窗口只要自己透出（WPF 侧 `Window.Background = Transparent` + `CompositionTarget.BackgroundColor = Transparent`），
就能看到模糊后的背景。这是 WPF 上真正可行的那条路。

### 2.3 着色层要按总量算

`6.4` 要求着色 55–70%。accent 路径有两层着色：accent 自己的 `GradientColor` alpha + 窗口 Shell 的半透明底。

第一次按"每层都吃满"配（accent 65% + Shell 35%），背景只剩 `0.35 × 0.65 ≈ 22%`：
放在暗色壁纸上实测相邻采样点只差 **4/255**，肉眼等于纯色，等于白做。

改成 accent **45%** + Shell **20%**（总着色 ≈ 56%，仍在区间内），透出率翻倍到 ~38%，
同一行的采样差拉到 `15 → 25`（约 16/255），肉眼可辨。

### 2.4 圆角

`DWMWA_WINDOW_CORNER_PREFERENCE = ROUND` 生效（角部像素有过渡）。半径是系统值（约 8px），
**DWM 不支持自定义半径**，与 6.1 写的 10px 差 2px。要 10px 只能退回 `SetWindowRgn`（带锯齿，A-30）。
取舍：吃 8px，换硬件裁剪 + 无锯齿 + 零成本。

## 3. 一个会浪费半天时间的坑：`WS_EX_NOACTIVATE`

第一版给窗口同时加了 `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`（想让点击不抢焦点）。
`NOACTIVATE` 会让窗口永远拿不到焦点，连带：

- `DragMove()` 失灵（内部走 `WM_NCLBUTTONDOWN`，需要窗口可激活）
- 右键 `ContextMenu` 弹不出来

两者都**不报错**，表现是"窗口点了没反应"。只保留 `WS_EX_TOOLWINDOW` 即可满足 6.1（不进任务栏、不进 Alt+Tab）。

## 4. 验收工具：为什么必须用 `--shot-screen`

原有 `--shot` 走 `RenderTargetBitmap`，渲染的是 WPF 自己的视觉树。
**毛玻璃是 DWM 在合成阶段画的，根本不在视觉树里**——用它截图永远是纯色，
"背景确实被模糊"（6.8 第 1 条）会一直是假通过。

新增 `--shot-screen`：GDI `BitBlt` 从屏幕抓像素（含合成结果），用 `PngBitmapEncoder` 编码。
不引 `System.Drawing.Common`（.NET 8 上 WPF 项目不会自动引用，为一个截图加 NuGet 依赖不划算）。

配合 `--shot-pad <px>` 把窗口周围背景一起截进来，`--float-center` 把窗口挪到屏幕中间——
三项一起才能做出"窗口内 vs 窗口外"的对照。
