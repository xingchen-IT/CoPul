# M4.12 竖排文字居中

- 日期：2026-10-31
- 范围：6.1 悬浮窗 —— 竖向排列下六格文字的水平对齐
- 用户原话：`能不能将竖直排列的字体尝试改成字体居中`

---

## 1. 问题

竖排（M4.10）的六格由 `Grid` 一列 `Auto` 排成，六个格子都被拉到同一列宽。但格内
`TextBlock` 沿用横向的写法 —— 左对齐。横向那样做是对的（每格宽度按内容定，文字贴着
格左缘，读起来是一"串"数据）；竖排就露馅了：

```
   ┌──────┐              ┌──────┐
   │ —    │              │  —   │
   │ FPS  │              │ FPS  │
   │ 22%  │   ← 左对齐    │ 22%  │   ← 居中
   │ —    │              │  —   │
   │ 29%  │              │ 29%  │
   │ 49°C │              │ 49°C │
   │ 58%  │              │ 58%  │
   │18.3G │              │18.3G │
   │/31.6G│              │/31.6G│
   └──────┘              └──────┘
```

短数据（`—`、`22%`）右侧空出一大片，长的（`/31.6G`）顶到右缘，视觉上像一堆没对齐的
碎片，重心散在左边。

## 2. 实现：两套竖向专用样式

`FloatWindow.xaml` 的 `Window.Resources` 里，在 `FloatValueScaled` / `FloatLabelScaled`
之后派生两个只给 `ColumnPanel` 用的副本：

```xml
<Style x:Key="FloatValueCentered" TargetType="TextBlock" BasedOn="{StaticResource FloatValueScaled}">
    <Setter Property="HorizontalAlignment" Value="Stretch" />
    <Setter Property="TextAlignment" Value="Center" />
</Style>
<Style x:Key="FloatLabelCentered" TargetType="TextBlock" BasedOn="{StaticResource FloatLabelScaled}">
    <Setter Property="HorizontalAlignment" Value="Stretch" />
    <Setter Property="TextAlignment" Value="Center" />
</Style>
```

`ColumnPanel` 里 6 个主值 + 12 个次值改绑这两套；`RowPanel` 一行未动（仍是
`FloatValueScaled` / `FloatLabelScaled`，仍左对齐）。

### 2.1 踩坑：只写 `TextAlignment` 不生效

第一版只加了 `<Setter Property="TextAlignment" Value="Center" />`，编译过、运行不报错，
但**文字一点没动**。像素测出来的行中心仍在 −5 ~ −17 像素。

原因在 `Themes/Styles.xaml` 的基样式：

```xml
<Style x:Key="FloatValue" TargetType="TextBlock">
    ...
    <Setter Property="HorizontalAlignment" Value="Left" />
</Style>
```

`HorizontalAlignment=Left` 让 TextBlock **只占内容宽**（宽 = 文字宽），
`TextAlignment` 是"在自身宽度内怎么摆"—— 框和文字一样宽时，居中等于没设置。
必须先 `Stretch` 把框拉到列宽，居中才有作用对象。

> 这条和 M4.8 的 `TemplateBinding` 是同一类问题：**属性写了不报错、只是静默无效**。
> 判据不能是"编译过了"，得看元素的运行值或像素。

### 2.2 为什么不会撑宽窗口

`Grid` 的列为 `Auto`：测量阶段按子元素**期望宽**取最大，`Stretch` 在测量阶段退化为内容宽，
所以列宽仍是"最长那句"决定的。`Stretch` 只在排列阶段生效，把每格拉到已定的列宽上。
实测尺寸完全没变：

| 档位 | 竖向 | 横向 |
| --- | --- | --- |
| 100% | 47×272（不变） | 381×34（不变） |
| 125% | 56×333（不变） | 475×43（不变） |
| 150% | 69×401（不变） | 571×51（不变） |

## 3. 验收：像素级测中心

屏幕抓图里条是亚克力半透明，壁纸上的文字会透进条内，基于亮度的包围盒判定不可靠
（第一轮测出来的"文字左偏 5~17 像素"是假象）。改用 `--shot`（RenderTargetBitmap）
拍图 —— 背景是纯色 `(15,17,21)`，文字与背景对比干净，逐行求非背景像素的 x 包围盒，
再和窗口水平中线比：

| 行（150% DPI 像素） | 包围盒 x | 中心 | 偏差 |
| --- | --- | --- | --- |
| `—`（FPS 主值） | 26–45 | 35.5 | +0.0 |
| `FPS` | 25–47 | 36.0 | +0.5 |
| `22%` | 17–53 | 35.0 | −0.5 |
| `—`（CPU 次值） | 29–44 | 36.5 | +1.0 |
| `29%` | 17–53 | 35.0 | −0.5 |
| `49°C` | 20–50 | 35.0 | −0.5 |
| `58%` | 17–53 | 35.0 | −0.5 |
| `18.3G` | 18–52 | 35.0 | −0.5 |
| `/31.6G` | 13–55 | 34.0 | −1.5 |
| `v32%` | 11–58 | 34.5 | −1.0 |
| `v2.5G` | 18–52 | 35.0 | −0.5 |
| `/8.0G` | 17–51 | 34.0 | −1.5 |
| `12ms` | 12–59 | 35.5 | +0.0 |
| `NET` | 23–48 | 35.5 | +0.0 |

窗口中线 35.5 px。**14 行平均偏差 −0.39 px，最大 1.5 px（= 1 DIP）**，属字号取整与
`Tabular` 数字字宽的半像素误差，肉眼不可辨。

对比图：`preview-m4.12-center-vs-left.png`（左 = M4.11 左对齐，右 = 本版居中）。

## 4. 影响面

| 位置 | 是否受影响 |
| --- | --- |
| 竖排六格 | 是：改为水平居中 |
| 横排六格 | 否：样式未改，仍左对齐 |
| 任务栏条 | 否：`TaskbarWindow` 用自己的样式 |
| 大窗口 / 设置页 | 否：同上 |
| 窗口尺寸 | 否：三档尺寸一字未变 |

## 5. 自测开关

沿用现有探针，无新增：

- `--float --float-vertical --float-center --shot-screen <png> --shot-pad 14` —— 看实际观感
- `--float --float-vertical --float-center --shot <png>` —— 纯色背景，用于像素测量
- `--float --float-row ...` —— 确认横向未受影响
