# M4.47 仓库根目录整理

准备把仓库转公开、发首个 Release，根目录的文件该归位的先归位。**只动位置和文档，不动代码**——
编译仍是 0 警告 0 错误。

## 结论：根目录 11 个 → 5 个

移动前根目录平铺着 11 个被跟踪的文件，其中 6 份是需求规格说明书的历史快照，和 `CoPul.sln` 混在一起。
现在只剩 5 个，而且每一个都必须留在根目录：

| 文件 | 为什么不能挪 |
| --- | --- |
| `CoPul.sln` | `dotnet build` 的入口，`tools\publish.ps1` 与所有文档里的构建命令都指它 |
| `LICENSE` | Gitee 靠根目录这个文件名识别许可类型并在仓库页展示；放进 `docs/` 就等于没声明 |
| `NuGet.config` | `dotnet restore` 只从**项目目录向上**找，挪进子目录就不生效了 |
| `README.md` | 仓库首页渲染的就是根目录这一个 |
| `THIRD-PARTY-NOTICES.txt` | 与 `LICENSE` 同级才符合"许可随包走"的直觉，且 `csproj` 按 `..\..\` 相对路径嵌它 |

## 规格书归档到 `docs/spec/`

`CoPul-需求规格说明书-v0.13 ~ v0.18.md` 共 6 份，用 `git mv` 移进 `docs/spec/`（保留历史，Git 识别为 rename）。
`docs/` 下已有 `icon-lab/`、`screenshots/` 两个子目录，加一层 `spec/` 与此一致。

新增 `docs/spec/README.md` 索引，说明三件事：

1. 这是**逐版快照**，v0.18 最新；
2. **v0.18 只写到 M4.0（10-29）**，此后到 0.1.0 的实现没有回写——判断"程序实际什么行为"要看 `docs/M4.*` 与 `src/`；
3. 为什么留着不删：第 15 章的 `Q-01`~`Q-25` 决策与 `A-01`~`A-41` 假设被后续每份报告反复引用，删了就没有出处。

第 2 条是这次整理里最容易误导外部读者的一点：一份叫"需求规格说明书"的文档停在 40 个里程碑之前，
不写清楚，读者会拿它当当前规格。

## 顺带修掉 README 的两处过期描述

| 位置 | 原文 | 现在 |
| --- | --- | --- |
| 构建一章 | "目前**还没有安装包和发布版**，只能从源码构建" | 指向 `tools\publish.ps1`，并保留"安装包、签名、自动更新没做" |
| 项目结构 | 停在 4 行，没有 `docs/spec/` | 补上，并把"50+ 篇"改成实际的 60+ 篇（`docs` 下现有 63 篇 md） |

第一条是硬错误：包已经在 `artifacts\` 里打好了，README 还写着"没有发布版"。
第二条的篇数历史上写错过一次（把 png 算进"150+ 篇"），这次按 `find docs -maxdepth 1 -name "*.md" | wc -l` = 63 的实际值写。
