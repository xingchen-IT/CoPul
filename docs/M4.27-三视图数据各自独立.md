# M4.27 三个视图的数据各自独立（折叠不再连坐）

用户报障原话：

> 三个模式的数据不能同时显示

配图是**大窗口 + 任务栏条同时在屏**、悬浮窗上的「内存 / 网络 / 硬盘」三格是 `—`。
编译：0 警告 0 错误（Release）。

---

## 1. 根因：折叠是按区块整段跳过的，而覆盖层的字段挂在同一批函数里

`DashboardState.ApplySnapshot` 从 M1 起就是这段：

```csharp
if (!CpuBlock.Collapsed) ApplyCpu(snap);
if (!GpuBlock.Collapsed) ApplyGpu(snap);
if (!MemBlock.Collapsed) ApplyMemory(snap);   // ← 整段跳过
if (!NetBlock.Collapsed) ApplyNetwork(snap);  // ← 整段跳过
if (!DiskBlock.Collapsed) ApplyDisk(snap);    // ← 整段跳过
```

在"只有一个视图"的年代这是对的：区块折叠了就是没人看，整段跳过省下的正是
20 个核心的字符串拼接与多盘循环。**但 M4.26 让三个视图可以同时显示之后，
悬浮窗 / 任务栏条的字段（`FloatRam` / `FloatNet` / `FloatIo` / `FloatLat` / `FloatDisk`）
仍然写在同一批 `ApplyMemory / ApplyNetwork / ApplyDisk` 里** ——
用户在大窗口折叠内存/网络/硬盘，另外两个视图的这几格就永远停在初始值。

注意不是"停在旧值"，是**压根没写过**，所以显示的是构造时的 `—`。现场配置：

```json
"CollapsedBlocks": ["mem", "net", "disk", "proc"]
```

复现的对照（同一份配置，只换程序版本）：

| 悬浮窗格子 | 修复前 | 修复后 |
|---|---|---|
| CPU | 29% / 53°C | 33% / 52°C |
| RAM | **—** | **64% / 20.2/31.6G** |
| VRAM | v48% / v3.8/8.0G | v46% / v3.7/8.0G |
| NET | **—** | **14ms** |
| DISK | — | — （非管理员读不到盘温，正常） |

任务栏条同样：修好前 `RAM`、`IO` 两格是 `—`，修好后 `20.2/31.6G`、`↑8.5K / ↓1.9M`。

## 2. 改法：折叠判断下沉进每个 ApplyXxx

每个 `ApplyXxx` 拆成两段，**覆盖层要用的那几个指标放在前面无条件执行**，
`if (XxxBlock.Collapsed) return;` 之后才是"只有大窗口才看"的文案：

| 区块 | 每拍必做（覆盖层要读） | 折叠时跳过（只有大窗口看） |
|---|---|---|
| CPU | `CpuLoad` / `CpuTemp` / `CpuPower` + `FloatCpu` | `CpuClock`、各核心行、负载均值 |
| GPU | `GpuLoad` / `GpuTemp` / `GpuPower` / `GpuMem` + `FloatGpu` / `FloatVram` / `FloatPwr` | `GpuClock`、编解码一行 |
| 内存 | `MemLoad` + `FloatRam`（含 used/total 两行） | 标题行、提交、已缓存、页面文件 |
| 网络 | `NetDown` / `NetUp` / `NetLatency` + `FloatNet` / `FloatIo` / `FloatLat` | 丢包率 |
| 硬盘 | `FloatDisk`（盘温走 series） | 多盘循环 + 合计文案 |

**折叠省下的 CPU 没有被废掉**：真正贵的那两块（20 核字符串、多盘循环）都还在 `return` 之后。

## 3. 同源的第二个坑：折叠 FPS 区块会停掉 PresentMon

`MainWindow` 里原本是

```csharp
_host.FpsSamplingEnabled = !_state.FpsBlock.Collapsed;
```

折叠大窗口的 FPS 区块 → PresentMon 整个停采 → 悬浮窗 / 任务栏条上的 FPS 字段一起冻成 `—`。
同一个病：**采集开关被大窗口的折叠状态单方面决定了**。

改成 `FpsStillNeeded()`：大窗口 FPS 区块展开 **或** 悬浮窗 / 任务栏条的 FPS 字段还亮着，
任一成立就继续采。字段开关有两个入口（设置页、托盘），两边都回调 `window.RefreshFpsSampling()` ——
少接一处就会出现"先折叠 FPS、再点亮悬浮窗 FPS，那一格永远是 `—`"。

## 4. 顺带：主动退出给了条明路

`window.Closing` 里那条"还有别的视图 → 只收起"会 `Cancel` 并 Hide 大窗口。
托盘「退出」/ 探针收尾走的是 `Application.Shutdown()`，实测进程能退，但那一下仍会
打一行"大窗口被关闭 → 只收起"的误导日志；更麻烦的是一旦收尾方式换成 `Close()`，
Cancel 就会真把进程留在后台。现在所有主动退出走 `Quit()`（先置 `exiting` 再 `Shutdown`），
`Closing` 首行直接放行。
