## 1. 为什么这一项是 P0

A 方案（`d905568` 起）把任务栏条做成 **topmost 顶层窗口**。这是必要的——B 方案（`SetParent` 子窗口）已被证明退出必留残影、只有重启 explorer 能清。

代价是**条会盖在全屏游戏画面上**。这不是观感问题，是正确性问题：用户打游戏时屏幕左侧凭空多出一条仪表盘，而任务栏自己根本不知道被盖住（`Shell_TrayWnd` 的 rect 永远正确）。

B 方案时代这条是白送的（子窗口被任务栏连带裁剪）。换 A 方案等于把这块债务接了回来，**只能自己做全屏检测**。需求 7.1 的 A 方案说明、docs/M3.0 第 6 节「已知限制」第 1 行都记着这笔账。

## 3. 全屏检测：三套判据（8.4 / A-39）

```
主判据  SHQueryUserNotificationState ∈ {QUNS_BUSY(2), QUNS_RUNNING_D3D_FULL_SCREEN(3)}
辅判据  前台矩形 == 所在显示器整屏 && 无 WS_CAPTION
否决项  前台是 桌面(Progman/WorkerW) / 任务栏(Shell_TrayWnd) / 开始菜单(UWP CoreWindow)…
        以及前台是本进程自己的窗口
```

**否决项不能省。** `QUNS_BUSY` 不是"全屏应用"专属——Windows 在开始菜单全屏、锁屏前、专注时段也会返回它。少了否决项，用户点一下开始菜单条就莫名消失又回来。

**弱判据要旁证。** `QUNS_QUIET_TIME(6)` / `QUNS_APP(7)` / `QUNS_PRESENTATION_MODE(4)` 单靠 QUNS 会误判，必须同时满足"矩形铺满 + 无标题栏"才算全屏。

**矩形比较留 2px 容差。** 无边框全屏窗口在不同 DPI 感知路径下取整不同，严格相等会漏判。

### 实测证据（现场《剑星》全屏）

```
full=True reason=quns=2 +rect -caption quns=2 hwnd=0x5217FA
class=UnrealWindow pid=121088 "StellarBlade" rectMatch=True captionless=True monitor=\\.\DISPLAY1
```

连续 6 轮（500ms 间隔）结论完全一致、无一抖动。主判据 `quns=2` 与辅判据 `+rect -caption` **两条同时成立**，不是碰巧命中一条。

## 4. 状态机（8.2 / 8.3）：`floatOrigin` 是关键

```
                 ┌──────────────┐
                 │   Taskbar    │◄──────────────┐
                 └──────┬───────┘               │
                        │ EnterFullscreen       │ ExitFullscreen
                        │ (floatOrigin=auto)    │ (且 origin==auto)
                        ▼                       │
                 ┌──────────────┐               │
                 │ Float (auto) │───────────────┘
                 └──────┬───────┘
                        │ UserSwitch
                        ▼
                 ┌──────────────┐
任意模式 ──────►  │ Float(manual)│
                 └──────────────┘
```

**没有 `floatOrigin` 就会出现那个经典 bug**：用户手动选了悬浮窗 → 开游戏 → 退游戏 → 悬浮窗莫名变回任务栏。只有 `auto` 来源才回落。

### 两个实现细节（都是踩过的）

**1. 防抖用时间戳，不用数 tick。** 轮询 500ms、门限 800/500ms，不是整数倍。数 tick 只能二选一：1 tick（500ms 不够）或 2 tick（1000ms 远超）。用"首次观察到该状态的时刻"做差与轮询频率无关。

**2. 定时器状态必须跟着视图走。** `NeedsPolling = (view==Taskbar) || (view==Float && origin==Auto)`。8.6 已规定大窗口与 manual 悬浮窗**不会产生任何动作**，探测就是纯开销。实测单次 564 µs、2 Hz = **0.11% 单核**，在 1.5% 预算里占 7%，省下来是白赚。

反过来更要小心：**进入 auto 悬浮后不能停轮询**，否则退出全屏永远检测不到，用户卡在悬浮窗里。

## 5. 视图编排重构：`ShowView` 是唯一出口

M4 之前，视图切换散在三处（标题栏按钮、双击条、右键菜单），各自写 `Hide()`+`Show()`。全屏自动切换也要切视图，两边各写一套 → 状态机的 `CurrentView` 立刻与事实不符，表现是"退出全屏没回落"或"回落两次"。

**现在所有切换都过 `ShowView`**，函数内部保证先 Hide 其余视图再 Show 目标，然后把 `CurrentView` / `FloatOrigin` 同步给状态机，最后写 trace。自动切换传 `userInitiated: false`（不改变来源标记）。

## 6. 性能（A-26 口径）

全屏检测不是渲染面，但它是**新增的常驻轮询**，A-26 的同类要求适用（新增常驻开销必须报数）。

| 项 | 值 |
| --- | --- |
| 单次探测 | 平均 **563.8 µs**（104–1021 µs，10 轮） |
| 轮询频率 | **2 Hz**（8.4 定的 500ms） |
| 折算占用 | **0.1128% 单核**（0.0056% 整机 / 20 逻辑核） |
| 大窗口 / manual 悬浮 | **0**（按需停轮询，trace 实测 `polling=False`） |

同环境 A/B（60s × 2，游戏正在运行、环境不干净）：

| 条件 | 单核 | 整机 |
| --- | --- | --- |
| 全屏检测 **开** | 4.052% | 0.2026% |
| 全屏检测 **关** | 4.113% | 0.2056% |

**开反而更低** → 增量完全落在环境噪声下。正式判定仍按 R24 记「未判定」（环境不干净），但可给出上限：即使按最坏 1021 µs × 2 Hz = 0.20% 单核，仍在预算内。

## 8. 三个把实验带偏过的坑

### 8.1 探针与生产定时器互相打架（A-40）

`--view-probe` 要逐步切视图并数可见窗口，而全屏状态机每 500ms 会按**真实**全屏状态抢切一次。第一次跑 `--view-probe` 时游戏正在全屏，第 3 步就被状态机切走了，看起来像"编排有 bug"。

→ 探针模式下**不启动**状态机；`--fs-switch-probe` 则显式 `auto.Stop()` 后自己喂数据。**验什么就隔离什么，混在一起跑无法归因。**

### 8.2 自动切过来的悬浮窗被持久化还原"抢"回旧位置（A-41）

实测症状：悬浮窗自动出现后**半秒内自己跳走**。

```
#4 真切悬浮窗 → float=(24,1453)   ← 正确（全屏那块屏左下）
#5 退全屏#1   → float=(1989,0)    ← 跳到了上次手摆的位置！
```

根因：`PlaceOnMonitor` 在 `Show()` **之后**才调，而 `ContentRendered` 里 `TryRestorePlacement()` 先跑，按配置把窗口挪回旧位置。

→ **两处修正**：(a) App 在 `ShowView` 之前先调 `PlaceOnMonitor`（预摆位），(b) `ContentRendered` 里加 `_pendingAutoPlace` 分支，自动摆位优先于配置还原。

**教训：这类"位置对了半秒然后跳走"比"一直错"更难排查**，只有逐帧记录几何才看得出来。

### 8.3 首帧闪在屏幕左上角（A-42）

预摆位之前实测 `#4` 出现 `(38,38)`：`SizeToContent` 窗口首次 Show 默认落在左上角，600ms 后才被摆到左下角。全屏游戏上那一闪非常显眼。

→ 拆成两步：**Show 前按 DIP 预摆**（用 `Monitors.ScaleForMonitor` 取目标屏 DPI），**ContentRendered 再用物理像素校正**（那时宽度才定型）。修后 `#4` 首帧即 `(18,1459)`。

## 9. 已知限制

| 限制 | 说明 |
| --- | --- |
| 真机回落未验 | 需要退出全屏；状态机与接线已由探针覆盖，真机待用户确认 |
| 副屏未真机验 | 单显示器环境，`PlaceOnMonitor` 的副屏路径只做了代码审查 + 单屏跑通 |
| 自动隐藏副作用 | 任务栏自动隐藏时条会 `Suppress`，全屏切换与它的交互未实测（要改系统设置） |
| 8.5 不做白名单 | Q-15 已定：PPT 放映 / 浏览器 F11 / 视频全屏一律照切。若用户觉得吵，v2 再加"仅游戏进程"选项 |
| 没有托盘兜底 | 全屏时条藏了，用户想操作只能靠悬浮窗右键菜单（托盘还没做，见第 10 节） |
