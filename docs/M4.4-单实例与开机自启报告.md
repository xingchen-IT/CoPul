# M4.4 单实例与开机自启 阶段报告

- 日期：2026-10-30
- 范围：**G-05 单实例**（F-15）+ **G-04 开机自启**（F-14，默认关闭）
- 未含：G-03 全局热键、G-08 设置页、G-09 传感器自检

---

## 1. 单实例（G-05）

### 1.1 两半，缺一不可

| 机制 | 作用 |
| --- | --- |
| 命名互斥体 `Local\CoPul.SingleInstance` | 判重 —— 可靠，跨进程唯一 |
| `RegisterWindowMessage` + `HWND_BROADCAST` | 激活 —— 让已有实例**动起来** |

只有互斥体的话，第二个实例只会安静退出，用户连点两次图标会觉得"程序没反应"。

用 `Local\` 而不是 `Global\`：多用户同时登录时各跑一份是合理的；用 Global 会让
"另一个用户已登录" 变成 "我打不开程序"。

### 1.2 广播要有**顶层**窗口收

`HWND_BROADCAST` 只投递给顶层窗口，message-only 窗口收不到 ——
这个坑在 `TaskbarCreated` 上已经踩过一次（见 M3.0 报告 7.7 节）。
所以 `SingleInstance.Listen()` 自己建一个 `HwndSource`（不带 `WS_VISIBLE` + `WS_EX_TOOLWINDOW`）。

### 1.3 测量模式必须跳过

`--shot` / `--shot-screen` / `--stats` / `--hidden` 不参与单实例检查。
否则"用户实例开着的时候跑一次截图"会直接被互斥体拦掉，而这是本项目最常用的验收方式。

激活后统一走 `ShowView(Main)` 而不是直接 `Show()`，否则全屏自动切换的状态机会与事实不符。

### 1.4 验证

```
23:17:21.313 [single] 已有实例在运行 → 请求它现身并退出     ← 第二个实例
23:17:21.340 [single] 收到激活广播                          ← 第一个实例
23:17:21.341 [single] → 收到激活请求，准备显示大窗口
23:17:21.343 [single] → UI 线程执行 ShowView(Main)
23:17:21.xxx [view] Taskbar→Main by=second-instance user=True
```

第二个实例退出码 **0**（不是错误退出），第一个实例从任务栏条切回大窗口。

## 2. 开机自启（G-04）

### 2.1 为什么不能用 Run 键

程序完整功能需要管理员权限（13.5）。`HKCU\...\Run` **无法启动需要提权的程序** ——
UAC 开着时那条注册表项启动会直接失败且没有任何提示，用户只会觉得"自启坏了"。

所以主路径是**计划任务**：登录触发 + 最高权限，之后开机不再弹 UAC。
Run 键只在 `Disable()` 时顺手清掉（清历史遗留）。

### 2.2 为什么不用 `schtasks.exe`

第一次实现走的是 `Process.Start("schtasks.exe", "/create ...", runas)`。
本机直接失败：

```
Win32Exception An error occurred trying to start process 'schtasks.exe' ... 拒绝访问。
PROGRAM BLOCKED BY SECURITY POLICY — schtasks.exe 在程序黑名单里
```

改成 **COM 的 `Schedule.Service`**（taskschd.dll）：不启动任何外部进程，
同时避开了 `/TR` 里那层套娃引号转义（任务动作本来就该拆成 `Path` + `Arguments`）。

### 2.3 提权：让提权后的自己再跑一遍

COM 的 `RegisterTaskDefinition` 同样要求管理员。做法不是找别的工具，而是
`Process.Start(self, "--autostart-internal enable", runas)` —— 一次 UAC，子进程只做那件事：

```
if (ArgValue(e.Args, AutoStart.InternalSwitch) is { } autoInternal)   // --autostart-internal
{
    bool ok = ... ? AutoStart.DisableCore() : AutoStart.EnableCore();
    Shutdown(ok ? 0 : 1);
    return;
}
```

**这个分支必须放在单实例检查之前**：主程序很可能正开着（用户就是从它的托盘菜单点的），
子进程要是去抢互斥体会被当成"第二个实例"直接退掉，永远注册不上。

### 2.4 任务定义

```csharp
def.Settings.ExecutionTimeLimit = "PT0S";        // 常驻程序，不能有默认 3 天超时
def.Triggers.Create(9)                          // TASK_TRIGGER_LOGON
def.Principal.RunLevel = 1;                     // TASK_RUNLEVEL_HIGHEST
def.Principal.LogonType = 3;                    // TASK_LOGON_INTERACTIVE_TOKEN（不要密码）
def.Actions.Create(0).Path / .Arguments         // 拆开，不拼整条命令行
root.RegisterTaskDefinition(TaskName, def, 6, null, null, 3);   // CREATE_OR_UPDATE
```

命令行按当前进程反推，不写死：

```
"C:\...\dotnet-sdk\8.0.404\dotnet.exe" "D:\CoPulRun\CoPul.dll" --tray
```

本机 `CoPul.exe`（apphost）起不来（缺 WindowsDesktop 8 运行时），一直是
`dotnet.exe CoPul.dll` 在跑 —— 写死 exe 路径的话，换一种部署方式自启就悄悄失效。

### 2.5 验证（真实创建 → 读回 → 删除）

| 步骤 | 结果 |
| --- | --- |
| 不提权直接调 `EnableCore` | `E_ACCESSDENIED (0x80070005)` —— **API 用法正确**，只差权限 |
| `--autostart-probe enable` | `internal enable ok=True` / `enable ok=True` |
| `status` | `enabled=True` |
| `dump`（读回任务定义） | `state=3 runLevel=1 triggerType=9 userId=LAPTOP-XXXXXXXX\xingchen exec=dotnet.exe args="D:\CoPulRun\CoPul.dll" --tray limit=PT0S` |
| 托盘菜单截图 | 「开机自启」带勾、可点（「设置…」仍是灰色占位） |
| `disable` | `ok=True` |
| 删后 `status` / `dump` | `enabled=False` / `FileNotFoundException 0x80070002`（任务不存在） |

`state=3` = TASK_STATE_READY，`runLevel=1` = HIGHEST，`triggerType=9` = LOGON。
**验证完已把任务删掉，用户系统设置恢复原状。**

## 3. 本轮踩到的坑

1. **`schtasks.exe` 在本机是黑名单程序**，从程序里 `Process.Start` 也拦（不只是命令行）。
   诊断价值：不提权调 COM 得到 `E_ACCESSDENIED` 而不是 `E_INVALIDARG`，
   说明注册参数是对的 —— **看错误码比看"成功/失败"信息量大得多**。
2. **CS0165 "使用了未赋值的局部变量"**：把 `SingleInstance.ActivateRequested += ...`
   写在 `window` / `view` / `floating` / `taskbar` 声明之前时，lambda 里调用的
   局部函数 `ShowView` 引用了这些变量，编译器判定"可能在赋值前被调用"。
   订阅要挪到这些变量就位之后。
3. **`--autostart-probe` 的日志要写文件**：这是 GUI 程序，`Console.WriteLine` 没有控制台可去，
   写进 trace（`%TEMP%\copul-trace.log`）。
4. **验证"第二个实例"时别只看第一条日志**：第二次验证时 UI 线程那条
   `[view] Taskbar→Main` 还没落盘就去 grep，差点误判成"订阅没生效"。
   看日志要等到动作完成（或等 1 秒再读）。

## 4. 已知限制

1. 两个实例**完整性级别不同**时广播会被 UIPI 丢掉（与 `TaskbarCreated` 同一根因）：
   第二个实例仍会安静退出，只是没能把第一个叫到前面。真人连点两次图标时权限一定相同，可接受。
2. 首次打开自启要弹一次 UAC。这是提权的硬成本，之后开机不再弹。
3. 自启命令绑定的是**当前** dotnet 与 dll 路径。把程序换个目录后需要关掉再重新打开自启。
4. 设置页还没做，开关只在托盘右键菜单里（G-08 一并收口时会搬进去）。
