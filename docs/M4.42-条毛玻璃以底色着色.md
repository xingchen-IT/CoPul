# M4.42 条毛玻璃的着色改用「底色」

> 需求原话：「我想要的是毛玻璃的颜色要以底色为基础」

M4.41 上线后，磨砂的 tint 是内置的深/浅两档（`#0F1216` / `#F6F8FB`），按字色深浅反向挑：
深色字配白雾、浅色字配黑雾。逻辑没错，但和「任务栏条背景」这张卡自己的语义打架 ——
用户在卡片里挑了一块底色，磨砂却用它自己的一套颜色，等于两个作者各画一层。

## 改法

着色直接取 `TaskbarBackdropColor`，浓度只调它的 alpha。

| 文件 | 改动 |
| --- | --- |
| `Interop/WindowGlass.cs` | `TryApplyAccent` 增加 `Color? tint` 参数（`null` = 老的内置深浅档）；`ApplyAccent(Window, bool, double)` → `ApplyAccent(Window, Color, double)` |
| `TaskbarWindow.xaml.cs` | `ApplyGlassLayer` 传 `_backdropColor`；`ApplyInk` 的「自动」加一段玻璃混合判据；诊断串改打 `tint=#RRGGBB` |
| `SettingsWindow.xaml` | 「底色」标签加 `x:Name`；不透明度那一行单独包一层 `BgOpacityPanel` |
| `SettingsWindow.xaml.cs` | 透明 + 玻璃时色板**不再灰掉**（此时它是「玻璃色」）、只灰不透明度；色板/十六进制只换色不改档 |

`ApplyAccent` 的老调用方只有条一处，签名换掉不影响悬浮窗与大窗口（它们走 `Apply`，没有"用户自己的底色"）。

### 「自动」字色必须跟着改

玻璃染成浅色而字色仍按任务栏（可能是深色）判 → 浅底配浅字。所以玻璃开启时按
**accent 的实际合成**算一遍有效亮度：

```
a = 0.17 + 0.83 × (浓度 / 100)        // 亚克力自带 ~17% 基底，tint 再按浓度压上去
eff = 任务栏luma × (1 - a) + 底色luma × a
```

浓度低时仍跟任务栏走，浓度高时由底色接管 —— 一条公式覆盖两头，不用人为设阈值。

### 透明档下色板依然能用

既然磨砂的颜色就是底色，那「透明 + 毛玻璃」时这块颜色仍然有用，所以：

- 色板与十六进制**可用**，标签从「底色」变成「玻璃色」；
- 「不透明度」**灰掉** —— 它描述的是实色层有多实，磨砂档没有实色层；
- 点色板/填十六进制**不会**把「透明」改成「自定义」（见 `IsColorOnlyForGlass()`），
  否则挑个玻璃色会平白多出一层实色。

## 验收

同一浓度 60%、只换底色（透明档，`--tray --shot-screen`，条内区域去掉两端 10px）：

| 底色 | 浓度 | 条内均值 | 条外均值（同帧） |
| --- | --- | --- | --- |
| `#1B2127` 深 | 60 | (66.8, 71.8, 88.0) | (120.0, 142.8, 157.4) |
| `#D8DEE7` 浅 | 60 | (184.7, 188.5, 208.7) | (120.0, 142.8, 157.4) |
| `#7A3F1F` 棕 | 60 | (120.3, 92.7, 90.0) | (113.4, 136.4, 151.3) |
| `#D8DEE7` 浅 | 100 | (208.7, 212.7, 228.4) | (120.0, 142.8, 157.4) |
| `#D8DEE7` 浅 | 0 | (141.9, 146.3, 173.6) | (115.6, 137.8, 152.9) |
| `#1B2127` 深 | 0 | (114.1, 119.7, 147.2) | (118.0, 141.0, 155.9) |

三件事都成立：

1. **同一浓度下逐通道跟着底色跑**。棕色那行 `R>G>B`，色相也复现了，不只是亮度。
2. **浓度 0 时两档收敛**（141.9 vs 114.1，差 28 而不是 118）—— 说明差距是 tint alpha 给的。
   剩那 28 是亚克力自带的 17% 基底也吃 tint RGB，压不掉；要真"没有玻璃"只能关开关。
3. **字色反转**：诊断串 `glass=on/60%/tint=#D8DEE7/ink=dark`，浅底色自动配深字。

设置页 `taskbarbg: window=backdrop=transparent color=#D8DEE7 … customEnabled=True` ——
透明档下色板确实是可用的，不是只是看起来能点。

## 坑

- **`custom` + 不透明度 100% 会把磨砂完全盖住**。这是既有语义（实色层在磨砂之上），
  不是本轮引入的 bug；想看见玻璃就把不透明度降下来，或者切「透明」。设置页文案已写明。
- `BgCustomPanel` 是 `IsEnabled` 的**父级**：只把父级设 true、再单独禁用子行才有效，
  反过来（子 true 父 false）子行一样是灰的。
- 设置页探针的 `bg` 命令打印两行：`taskbarbg: mode=…`（面板值）与
  `taskbarbg: window=…`（窗口实际值）。两行都要读 —— 控件对了窗口没跟上，正是"改了没反应"。
