# M4.45 首次启动点了「同意」之后程序自己退出

> 用户报告：第一次打开程序弹出用户协议，点了同意之后**程序直接退出**，必须再手动双击
> 一次图标才能用。M4.43 上线当天就带了这个缺陷 —— 当时的验收只看"配置里有没有记下同意"，
> 没看"点完同意之后窗口还在不在"。

## 问题

复现（`--eula-auto-accept`，走生产路径的模态协议窗，不手点）：

```
[proc] pid=77616 alive=False exit=0x0
[win ] 0 visible-titled windows
[cfg] 结果 version='1' at='2026-11-04 18:34:23 +08:00'
```

同意**记下来了**，进程**退出码 0**，窗口**一个都没留下**。日志上看一切正常：

```
[eula] window accepted modal=True appMain=True      ← 关键
[eula] accepted v1 at 2026-11-04 18:34:23 +08:00
[app]  before main window: MainWindow=(null) shutdownMode=OnMainWindowClose
[single] activate-handler 已订阅
[tray] added=True ...                                ← 托盘图标都挂上了
[fullscreen] start enabled=True view=Main origin=Manual
[app]  exit code=0                                   ← 30ms 后收摊
```

## 根因

`App.xaml` 写的是 `ShutdownMode="OnMainWindowClose"`，而 WPF 会把**第一个 Show 出来的窗口**
自动认成 `Application.MainWindow`（`appMain=True` 就是证据）。协议窗恰好就是"第一个窗口"，
于是它一关，WPF 判定"主窗口关闭了"，把 `Shutdown()` 排进调度队列。

麻烦在于**这一步是异步的**：`RunModal()` 返回时 `Dispatcher.HasShutdownStarted` 还是 `false`
（`[app] after eula: shutdownStarted=False`），`OnStartup` 会继续把 MainWindow 建出来、挂托盘、
起全屏检测，全部执行完 —— 然后调度器处理那条已经排队的关闭请求，进程正常退出（code 0）。

所以它看起来不像崩溃：没有异常、没有错误对话框、退出码漂亮，只是"窗口不见了"。
用户侧的感受就是"同意完程序没了"。而且同意已经落盘，第二次启动直接进主界面，
更像"第一次装的时候没成功"这种莫名其妙的偶发问题。

## 改法

协议阶段把退出模式切成 `OnExplicitShutdown`，真正的主窗口挂上 `Application.MainWindow`
之后再切回来：

| 位置 | 改动 |
| --- | --- |
| `App.xaml.cs` | `EnterEulaStage()`：建协议窗之前切 `OnExplicitShutdown`，并留一条 trace |
| `App.xaml.cs` | `MainWindow = window` 之后还原为原模式（`OnMainWindowClose`） |
| `EulaWindow.xaml.cs` | `AutoAcceptMs`：取证用的"自动勾选并同意"，走与用户点击**同一条** `Finish` |
| `App.xaml.cs` | `--eula-auto-accept` 单独放行单实例互斥体，否则用户实例开着时永远测不到闸门 |
| `App.xaml.cs` | 三处 trace：`after eula` / `before main window` / `OnExit code`，下次同类问题看日志即可定位 |

### 为什么不用别的修法

| 方案 | 为什么不行 |
| --- | --- |
| 关窗前把 `Application.MainWindow = null` | 无效。WPF 是在窗口关闭的过程中判定"这是不是主窗口"，置空发生在判定之后 |
| 改成 `ShutdownMode.OnLastWindowClose` | 更糟。任务栏条、悬浮窗都是真窗口，随便关一个（或某个探针收尾）就可能把进程带走 |
| 全程 `OnExplicitShutdown` | 能跑，但把"主窗口关闭"这条系统语义彻底废掉。现在 `Closing` 里是 `Cancel + Hide`，看似不依赖它，**恰好依赖**：将来谁写一句直接 `Close()` 就会变成关不掉 |

局部开关的好处是改动面只有两行，且状态在日志里可见：`协议阶段 shutdownMode=... → OnExplicitShutdown`
与 `协议阶段结束 shutdownMode → OnMainWindowClose`。
