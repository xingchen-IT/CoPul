# M4.23 全屏切换：防抖档位（1s / 2s / 3s）

需求原话：

> 做一下其它挡位的效果（1s，2s，3s等）

承接 M4.22：抖动已修（点悬浮窗不再被判成非全屏），剩下的是**门限本身只有一个值** ——
需求 8.4 定的"进入 800ms / 退出 500ms"是写死在代码里的常量，用户没法按自己的习惯调。
这一版把两个门限做成**可选档位**并逐档做了真机取证。

编译：0 警告 0 错误（Release，`dotnet build CoPul.sln -c Release`）。

---

## 1. 改了什么

| 文件 | 改动 |
|---|---|
| `Sdk/FullScreenAutoSwitch.cs` | `EnterHold`/`ExitHold` 两个 `static readonly` → 实例属性 `EnterHoldMs`/`ExitHoldMs`；新增档位表 `EnterHoldChoices`/`ExitHoldChoices`、`NormalizeHold()`、`SetHold()`、`ApplyConfig(enabled, enter, exit)` |
| `Sdk/ConfigStore.cs` | 新增 `FullScreenEnterHoldMs`（默认 800）/ `FullScreenExitHoldMs`（默认 500） |
| `SettingsWindow.xaml` | 「全屏时自动隐藏」下加两行分段按钮：**进入确认** 0.5s/0.8s/1s/2s/3s，**退出确认** 0.5s/1s/2s/3s |
| `SettingsWindow.xaml.cs` | `FsHold_Checked`（落盘 + 立即生效）、`SelectHoldSegment()`、探针命令 `fshold:<进入>;<退出>` |
| `App.xaml.cs` | `SettingsContext.SetFullScreenHold`；启动时 `ApplyConfig(开关, 档位, 档位)`；新增 `--fs-hold <进入>,<退出>`（命令行覆盖，不落盘） |
| `Probes/FullScreenLiveProbe.cs` | 头部打印当前档位；每次迁移打一行 `---- <t>ms 迁移 #n：<内容> ----`（档位取证主要看这行） |
| `tools/fake-fullscreen.py` | 新增 `--restore <秒>`：缩窗后再铺满，模拟"Alt+Tab 出去看一眼又回来" |

**默认值不动**（进入 800ms / 退出 500ms），升级后行为与原来一致；档位只在你主动改时才生效。

档位值由 `FullScreenAutoSwitch` 一处定义，UI 与探针共用同一份数字 —— 不会出现"设置页有 2s、探针不认"这种分叉。
手改配置写了 1500 也不会被拒绝：`NormalizeHold()` 归一到最接近的档（与 `NormalizeScale` 同一套取舍）。

## 2. 各档实测：门限真的按值生效

真机场景不变（`tools/fake-fullscreen.py` 另进程造无边框铺满屏窗口当"游戏"，CoPul 用 `--fs-live-probe` 真实跑）：

```
游戏全屏 ──▶ Taskbar ──进入档位──▶ Float(auto) ──游戏销毁──▶ 退出档位 ──▶ Taskbar
                                      ↑
                              中途 Activate 悬浮窗（模拟点它一下，M4.22 回归）
```

脚本 `D:\CoPulRun\fs-hold.sh <进入ms> <退出ms>`，汇总 `fs-hold-summary.py`。
绝对时刻不可比（CoPul 每次启动耗时不同），所以量的是 **"首次观测到该状态" → "真的迁移"** 的耗时，
采样粒度 500ms，实测值应落在 `[档位, 档位+500]`：

| 档位（进入/退出） | 进入实测 | 退出实测 | 迁移次数 | 终态 |
|---|---|---|---|---|
| **800 / 500**（默认） | 1131 ms | 495 ms | 2 | Taskbar ✓ |
| 1000 / 1000 | 1101 ms | 997 ms | 2 | Taskbar ✓ |
| 2000 / 2000 | 2135 ms | 2005 ms | 2 | Taskbar ✓ |
| 3000 / 3000 | 3178 ms | 3009 ms | 2 | Taskbar ✓ |
| 1000 / 3000 | 1089 ms | 3000 ms | 2 | Taskbar ✓ |

五组**全部只有 2 次迁移**（进一次、退一次），说明 M4.22 的修复在各档位下都还成立 ——
中途那次"点一下悬浮窗"没有触发任何多余回落。

## 3. 档位的实际价值：短暂切出去还回不回得来

只看"门限准不准"说明不了档位该选哪一档。真正决定体验的是**防抖能不能挡住瞬时状态**：
打游戏时 Alt+Tab 出去看一眼（1.5s）再切回来，退出档位够长就**不会**回落任务栏。

新增 `--restore` 让假游戏缩窗 1.5s 后重新铺满，脚本 `D:\CoPulRun\fs-flicker.sh <退出ms>`：

| 退出档位 | 迁移次数 | 实际发生什么 |
|---|---|---|
| 500 ms（默认） | **3** | 缩窗 0.5s → 回落任务栏；恢复全屏 → 又切回悬浮窗（**一次多余抖动**） |
| 1000 ms | **3** | 同样抖（1.5s 已超过门限） |
| 2000 ms | **1** | 稳在悬浮窗，全程不动 |
| 3000 ms | **1** | 稳在悬浮窗 |

进入档位同理：调长 = 进游戏后要等更久才切到悬浮窗，但切屏/弹窗/进度条抢焦点时不会被带过去。

**怎么选**（写进设置页的说明文字，可照着挑）：

- 打游戏为主、很少切屏 → 默认（进入 0.8s / 退出 0.5s），反应最快。
- 经常 Alt+Tab、或游戏爱弹窗口 → **退出确认调到 2s 或 3s**，进入保持默认。
- 常被 PPT/浏览器 F11 误触发 → **进入确认调到 2s / 3s**。

## 4. 界面与探针

设置页「常规」页，「全屏时自动隐藏」下方新增两行（截图 `m423-s1300.png` 已确认渲染完整、无截断/重叠）：

```
进入确认   [0.5s] [0.8s✓] [1s] [2s] [3s]
退出确认   [0.5s✓] [1s] [2s] [3s]
须连续满足这么久才切换：进入=进游戏后多久切到悬浮窗，退出=退出全屏后多久回任务栏条。
调长可挡住切屏/弹窗造成的误判，切回来也会慢一点。
```

改档位**立即生效**（下一轮判定就按新门限走），不重置已经攒着的计时 ——
用户是在观察中调档位，清掉计时反而会让"刚从 2s 调到 0.5s"这一下不立刻切过去。

探针：

| 命令 | 用途 |
|---|---|
| `--fs-hold <进入>,<退出>` | 命令行覆盖档位做取证（**不落盘**）。只写一个数字 = 两个都设成它 |
| `--fs-live-probe <txt> --fs-live-end <ms>` | 真机采样，头部打印档位、每次迁移打一行 |
| `--settings-probe "scroll:1300,fshold:2000;3000"` | 设置页点档位并把九个按钮的选中状态打到 stdout |

⚠️ 设置页探针串按**逗号**切命令 → 多值只能写**分号**（`fshold:2000;3000`），与 `textcolor` 同一套约定。
⚠️ `fshold` 会**真的写用户配置**（走的是同一条 `Checked` 路径）：取证完记得核对 `config.json`，
本次已把 `FullScreenEnterHoldMs/ExitHoldMs` 还原回 800 / 500。

## 6. 一句话结论

两个防抖门限从"写死的常量"变成"用户可调的档位"，默认行为不变；
真机实测五组档位门限均按值生效（误差 ≤500ms 采样粒度），且 **退出档位 2s/3s 能挡住 1.5s 的 Alt+Tab 切出**，
而默认 0.5s/1s 会多出一次"回落又切回"的抖动 —— 这就是档位存在的意义。
