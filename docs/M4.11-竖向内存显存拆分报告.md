# M4.11 竖向内存 / 显存拆分「已用 / 总共」

- 日期：2026-10-31
- 范围：6.1 悬浮窗 —— 竖向下内存 / 显存的数值版式
- 用户原话（两条）：
  1. `先推送到远程然后尝试将内存和显存的具体已使用和总共上下排列，并稍加增大不同数据之间的空隙`
  2. `只有竖直方向才拆成两部分，横向不用修改`

---

## 1. 需求收敛：横向拆过一次，被否掉

第一版我把「已用 / 总共」两行同时用在横向和竖向，横向因此从 34 DIP 高长到 52：

| 版本 | 横向 | 竖向 | 结果 |
| --- | --- | --- | --- |
| v1 | 三行（占用率 / 已用 / 总共），34 → 52 高，381 → 327 宽 | 三行 | 横向否 —— 细条形态被改掉了 |
| **v2（本版）** | **原样两行 `18.8/31.6G`，381×34 一动不动** | 三行 | 采用 |

横向是 6.1 的「细长条」，34 DIP 是它的形态本身：多一行，它就不再是细条。
竖向是侧边竖条，宽窄由最长那句决定，拆行有实际收益（见第 3 节）。

## 2. 实现

### 2.1 数据层：`FloatField` 多两行，`Bottom` 保持不变

`FloatField` 原来只有 `Top` / `Bottom` 两行。新增：

| 成员 | 语义 |
| --- | --- |
| `Line2` | 悬浮窗第二行；未设置时**退回 `Bottom`** |
| `Line3` | 第三行（"总共"）；未设置时为空 |
| `Line3Visibility` | 空串时 `Collapsed`，不让空 TextBlock 占位 |

关键约束：**`Bottom` 始终是完整那句 `18.8/31.6G`**。任务栏（7.4）绑的就是 `Bottom`，
它是一条横着的、74/78 宽的格子，没有拆的必要，也不该跟着悬浮窗的版式改动。

`Set(...)` 追加两个可选参数，不传即不分拆：

```csharp
FloatRam.Set(WithUnit(MemLoad.Value, "%"), ramSize, brushOnGlass, brush,
             line2: $"{used:F1}G",
             line3: $"/{total:F1}G");
```

显存在第二行仍带小写 `v`（Q-04）：拆开之后 `v2.5G` 一眼仍是显存，
第三行 `/8.0G` 紧跟其下，同属一格。

### 2.2 XAML：横向两行，竖向三行

`RowPanel` 六个 `TextBlock` 全部恢复绑 `Bottom`，格子 `VerticalAlignment="Center"` ——
与 M4.10 完全一致。`ColumnPanel` 每格补第三个 `TextBlock`（`Line3`）。

### 2.3 空隙：只动竖向

| 常量 | 原 | 新 | 说明 |
| --- | --- | --- | --- |
| `BaseRowGap`（竖向行距） | 6 | **8** | 格的行数不再统一（4 格两行、2 格三行），行距太小会分不清"哪两行属于同一格" |
| `BasePadY`（竖向上下内边距） | 10 | **12** | 条变高之后上下留白跟着放大 |
| `BaseSplitGap`（已用 / 总共之间） | — | **1** | 让这两行读成一组，与格间 8 拉开层次 |
| `BaseGap`（横向列距） | 8 | 8 | 不动 |
| `BaseHeight`（横向条高） | 34 | 34 | 不动 |

## 3. 实测

### 3.1 尺寸

| 档位 | 竖向（旧 → 新） | 横向（实测，与改动前一致） |
| --- | --- | --- |
| 100% | 61×229 → **47×272** | 381×34 |
| 125% | 76×280 → **56×333** | 475×43 |
| 150% | 93×341 → **69×401** | 571×51 |

宽度从 61 掉到 47 的原因只有一个：竖条宽度 = 最长那句 + 内边距 + 边框。

- 旧：`18.8/31.6G`，10px 时约 53 DIP → 53 + 12 + 2 ≈ 61；
- 新：最长的是 `31.6G` / `v2.5G`，约 25 DIP → 内容 33 + 12 + 2 ≈ 47。

也就是说 **M4.10 里"61 是下限"的结论被这次拆行推翻了** —— 当时的下限是"一句话读完"，不是正立本身。

### 3.2 侧车（`--shot-screen` 的 .info.txt）

```
竖 100% ... font=13.0/9.0 cells=33x253 [29.3/16.0 29.3/16.0 29.3/16.0 44.0/16.0 44.0/16.0 29.3/16.0]
横 100% ... font=13.0/10.0 h=34.0 cells=358x29 [29.3/16.0 ×6]
```

前三格与最后一格 29.3（两行 16 + 13），内存 / 显存 44.0（16 + 13 + 1 + 13）——
逐格实际高度是这次唯一能证明"第三行真的进去了、且没有把条撑破"的证据。

## 4. 顺带

- 新增自测开关 `--float-row`：强制横向。配置里可能存着 `FloatVertical=true`，
  验收横向时不该靠"删配置"（与 `--float-vertical` 对称，且同样不落盘）。
- `ScaleDiag` 改成逐格打印 `实际高度/主值高度`，替代原先只打第一格三行的写法 ——
  竖排之后各格行数不同，只打第一格会漏掉真正把条撑高的那两格。

## 5. 未验证 / 已知边界

- **任务栏模式没重跑**：任务栏读 `Bottom` 与 `Width`，这两个值本次一行未改
  （`74` / `18.8/31.6G`），属静态可确认；为不打扰用户正在运行的那份实例，没有实拍。
- 150% + 竖向高度 401 DIP，在 1080p 的 150% 屏（720 DIP）上超过半屏；
  `EnsureFullyVisible` 会把窗口夹回工作区，但"能夹住"不等于"看起来不挤"，真要用 150% 竖排需再议。
