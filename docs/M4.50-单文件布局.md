# M4.50 安装目录整合：改单文件发布

用户反馈「安装的根目录文件太多了」。这是 485 个文件摊在 `%LOCALAPPDATA%\Programs\CoPul`
根下的直接后果，不是主观感受——274 个条目里有 259 个是文件。

## 一、为什么不能靠"把 dll 挪进子目录"解决

第一反应是建个 `lib\` 把 dll 收进去。**行不通，而且不是"加载慢"级别的问题**：

根目录那 249 个 dll 里绝大部分是 .NET 运行时本身（`System.Private.CoreLib.dll`、
`PresentationFramework.dll`、`coreclr.dll`……）。自包含发布时 `hostpolicy` 按
`CoPul.deps.json` 在**程序目录**里逐个定位这些程序集，挪走任何一个都会在 host 阶段
直接失败——exe 双击没反应，连异常框都没有。

`runtimeconfig.json` 的 `additionalProbingPaths` 也救不了：它要求 NuGet 风格的
`<path>/<包名>/<版本>/lib/<tfm>/` 目录结构，不是把 dll 堆进一个文件夹就行。

能真正减少**根目录文件数**的只有一条路：把它们打包进 exe。

## 二、做法

三个开关缺一不可：

| 设置 | 作用 | 不设会怎样 |
| --- | --- | --- |
| `PublishSingleFile=true` | 托管程序集进 bundle | 249 个 dll 照旧摊在根目录 |
| `IncludeNativeLibrariesForSelfExtract=true` | 原生库（coreclr / D3DCompiler / LHM 的 dll）也进 bundle | 只减一半，根目录还剩几十个 `.dll` |
| `SatelliteResourceLanguages=zh-Hans` | 只留简体中文卫星资源 | 13 个语言目录、221 个 `resources.dll`（占全部文件 45%） |

前两个在 `tools/publish.ps1` 的 `$publishArgs` 里，第三个在 `CoPul.App.csproj`。

### 必须排除在 bundle 之外的文件

`ExcludeFromSingleFile=true` —— 单文件发布默认把 `CopyToOutputDirectory` 的内容
**一起塞进 exe**，而下面这些运行时是**按路径去磁盘找**的，塞进去等于找不到：

| 文件 | 谁按路径找 | 塞进 exe 的后果 |
| --- | --- | --- |
| `assets\*.ico` ×3 | `LoadImage` 加载 exe 图标 / 托盘图标 | 托盘空白、关于页没图标 |
| `presentmon\PresentMon.exe` | `Process.Start` 拉起的**独立进程** | FPS 永远 `—` |
| `presentmon\LICENSE.txt` | 给人读 | MIT §"保留所有副本的声明"落空 |
| `LICENSE.txt` / `THIRD-PARTY-NOTICES.txt` | 给人读 | 专有许可要求"随二进制走"落空 |

### 顺带修掉的三处 `Assembly.Location`

单文件下 `Assembly.Location` 恒为空字符串，编译器对每一处引用报 **IL3000**。而
「0 警告」是发版门槛（`publish.ps1` 带 `-warnaserror`）。三处都改掉：

| 位置 | 原写法 | 改为 | 为什么等价 |
| --- | --- | --- | --- |
| `AutoStart.SplitCommand` | `GetEntryAssembly()?.Location` | `EntryDllPath()` | 框架依赖模式下 `BaseDirectory\CoPul.dll` 就是同一路径；单文件里该文件不存在 → 空串，走 exe 直启分支，行为不变 |
| `AutoStart.RunElevated` | 同上 | 同上 | 同上 |
| `AboutInfo.BuildTime` | `Assembly.Location` 取 dll 写盘时间 | 优先 `BaseDirectory\CoPul.dll`，不存在则 `Environment.ProcessPath` | 单文件下取 **exe** 的写盘时间 = 打包完成时刻，比原来显示「未知（单文件发布）」有用 |

`EntryDllPath()` 用 `File.Exists` 判断而不是问 `Assembly`，两种发布模式走同一段代码。

## 三、验收

### 体积与文件数

| 项 | 改造前 | 改造后 | 变化 |
| --- | --- | --- | --- |
| 安装目录**根**条目 | 274（259 文件 + 15 目录） | **8**（6 文件 + 2 目录） | −266 |
| 全部文件 | 485 | **11**（含卸载器 2） | −474 |
| 磁盘占用 | 170.2 MB | 149.5 MB | −20.7 MB |
| 绿色包 zip | 57.0 MB | 60.5 MB | +3.5 MB |
| 安装包 exe | 57.3 MB | 57.4 MB | +0.1 MB |
| 静默安装耗时 | 12.0 s | **6.6 s** | −5.4 s |

zip 变大 3.5 MB 是预期的：LZMA 对 480 个小文件的压缩率高于对 1 个 144 MB 大文件。
换成安装包后几乎持平（Inno 的 lzma2 更强）。

装完的目录就这些：

```
%LOCALAPPDATA%\Programs\CoPul\
├─ CoPul.exe                144.3 MB（自包含运行时全在里面）
├─ LICENSE.txt
├─ THIRD-PARTY-NOTICES.txt
├─ BUILD-INFO.txt
├─ assets\                  copul.ico + 托盘深浅两版
├─ presentmon\              PresentMon.exe + LICENSE.txt
├─ unins000.exe
└─ unins000.dat
```

### 功能回归（都从安装目录跑）

| 项 | 判据 | 结果 |
| --- | --- | --- |
| 程序启动 | `--settings-probe` 输出 | `version=0.1.0 (ad89879) build=2026-11-05 15:41 icon=ok` |
| 关于页渲染 | 截图 | 图标、版本、构建时间、许可记录、第三方清单全部正常 |
| 图标资产 | `LoadImage` 直接加载三个 ico | 三个句柄全部非 0 |
| 硬件采集（NVML / PDH / 进程） | 传感器诊断页 | 三项**就绪**（NVML 原生库解压加载成功） |
| GPU 数据 | 主窗口截图 | 温度 48℃、显存 2.1/8.0 GB 有值 |
| 任务栏条 | `--shot-screen` | 365 / 19% / 10% / 56% / 26% / 44℃ / 120.4K / 27ms |
| PresentMon 路径 | 诊断页文案 | 显示「需管理员权限」而非「exe 不存在」→ 路径解析成功 |
| 卸载目录 | 隔离副本卸载 | 1.0 s，目录与注册表项都清空 |

### 启动耗时

`--shot` 端到端（含渲染等待），各 3 次：

| 发布形态 | 耗时 |
| --- | --- |
| 多文件（485 文件） | 5.19 / 5.21 / 5.27 s |
| 单文件 | 5.27 / 5.29 / 5.31 s |

差异 60~100 ms，在噪声范围内。**没有为了启动速度牺牲什么**——因为托管 dll 是直接从
exe 内存映射的，只有原生库落盘。

首次运行会把原生库解到 `%TEMP%\.net\CoPul\<hash>\`，实测 **9.6 MB**（不是 144 MB）。
删掉不影响，下次运行自动重建。

### 为什么不开 `EnableCompressionInSingleFile`

开了能把 exe 从 144 MB 压到约 65 MB，但**每次启动**都要把整个 bundle 解到内存，
冷热启动都变慢；而安装包的体积差已经被 Inno 的 lzma2 补回来了（57.4 MB 与原版持平）。
省启动时间比省磁盘划算。

## 四、打包脚本的判据也跟着改

单文件之后原来那些"缺文件就报错"的检查全部失效——它们查的是 `CoPul.dll`、
`LibreHardwareMonitorLib.dll` 之类，而**这些文件磁盘上已经没有了**。改成按形态判断：

| 脚本 | 原判据 | 新判据 | 为什么这样能发现问题 |
| --- | --- | --- | --- |
| `publish.ps1` | 逐个 `Test-Path` 10 个 dll | 根目录不得出现 `System.Private.CoreLib.dll` | 参数没生效会**安静地**退回散装布局，程序照常能跑，只有这条判据抓得住 |
| `publish.ps1` | — | `CoPul.exe` ≥ 100 MB | 运行时没打进去时体积明显偏小（正常 144 MB） |
| `build-installer.ps1` | 文件数 < 400 报错 | exe 体积 + 7 个外部文件 | 单文件只有 11 个文件，旧的 400 阈值会把正常产物判成半份包 |

两条新判据各管一头：一条查**布局**，一条查**内容完整性**。

## 五、遗留

- `artifacts\` 仍带低完整性标签，里面那份安装包双击报「错误 5」；`build-installer.ps1`
  会自动复制一份到 `Downloads`（无标签，可直接双击）。见 M4.48 坑 #4。
- 只保留 `zh-Hans` 卫星资源。要让英文系统显示英文框架文案，把 csproj 里改成
  `<SatelliteResourceLanguages>zh-Hans;en</SatelliteResourceLanguages>` 大约多 17 个文件。
