# 依赖许可审计 · 2026-11-05

> **注意：项目协议已于 2026-11-05 切换为 GPL-3.0。** 本文的依赖审计结论仍然有效
> （**没有 GPL/AGPL/LGPL 依赖**，GPL-3.0 可作为项目协议），但文末「专有 LICENSE 不需要改动」
> 一句已过时，以 `docs/M4.52-切换GPL-3.0.md` 为准。

审计对象：CoPul v0.1.0（`src/` 全部项目 + 随包二进制），目标只有一个 —— **确认没有任何 GPL / AGPL /
LGPL 代码混进来**，因为 CoPul 的 `LICENSE` 是专有协议（禁止二次分发），一旦引入强著佐权组件，整个作品
就必须换协议，且已发布的版本收不回来。

## 结论

**没有 GPL / AGPL / LGPL。** 全部 28 个 NuGet 包只有三种许可：MPL-2.0（5 个）、MIT（22 个）、
Apache-2.0（1 个）。都不要求 CoPul 开源。

但发现**一处实质合规缺口**：`HidSharp`（Apache-2.0）既没写进 `THIRD-PARTY-NOTICES.txt`，也没有随包
附带 Apache-2.0 许可全文。Apache-2.0 §4(a) 要求「向接收者提供本许可的副本」，§4(b) 要求保留修改声明 ——
目前两条都没做到。其余包只存在「漏列」这一层瑕疵，法律义务本身不重。

## 方法

1. 从 `src/CoPul.Collector/obj/project.assets.json` 取**还原后的完整闭包**（不是 csproj 里写的那几个直接依赖）；
2. 对每个包读本地 `%USERPROFILE%\.nuget\packages\<id>\<版本>\<id>.nuspec` 里的 `<license>` 节点
   （`type="expression"` 是 SPDX 表达式，`type="file"` 指包内许可文件，只剩 `<licenseUrl>` 的老包要追链接）；
3. 用 `bin\Release\net8.0-windows\win-x64\*.dll` 反查**哪些程序集真的随包分发**，构建期包不算分发；
4. `grep -ril copyright src --include=*.cs` 查有没有整段抄进来的第三方源码。

## 需要修的三处

### 1. `THIRD-PARTY-NOTICES.txt` 补 HidSharp 与 Mono.Posix

HidSharp 是 Apache-2.0，不是 MPL。它的许可文件在包内叫 `LICENSE.txt`（`<license type="file">`），
所以只看 nuspec 的 `licenseUrl` 会误判成 `aka.ms/deprecateLicenseUrl` 那种空壳链接。

### 2. 随包附 Apache-2.0 全文

新增 `licenses\Apache-2.0.txt`，在 `CoPul.App.csproj` 里与 `presentmon\` 同样处理（`CopyToOutputDirectory`
+ `ExcludeFromSingleFile`），否则单文件发布会把它吞进 exe，用户拿不到许可副本。`tools\publish.ps1` 的
「必须有这些外部文件」清单也要加一项，防止参数失效时静默退回。

### 3. 三本 MPL 传递依赖要么单列、要么在 LHM 那条里点名

MPL-2.0 §3.1 要求「告知接收者源码以本许可提供」。技术上指向 LHM 仓库即可覆盖它的传递依赖，但
`DiskInfoToolkit` / `RAMSPDToolkit-NDD` / `BlackSharp.Core` 是**独立仓库**（作者 Blacktempel），
指向 LHM 会让人找不到源码，建议单独写出地址。

## 已核查、确认无问题

- **源码里没有第三方版权头**：`grep -ril copyright src --include=*.cs` 只命中 `obj/` 下的
  `AssemblyInfo.cs`（自动生成），没有整段抄进来的代码。
- **PresentMon 未修改**：`assets\presentmon\PresentMon.exe` 与官方发布一致，`LICENSE.txt` 随包。
- **不涉及驱动分发**：PawnIO 只在诊断页提示用户去官网装，符合「个人无 EV 证书不得分发内核驱动」的红线。
- **`LICENSE` 与第三方许可不冲突**：专有协议约束的是 CoPul 自己的代码，第三方组件的再分发权由各自
  许可授予，条款里已单列声明（见 `THIRD-PARTY-NOTICES.txt` 末尾「补充说明」）。

## 复现命令

```powershell
# 1. 完整依赖闭包
python -c "import json;d=json.load(open('src/CoPul.Collector/obj/project.assets.json',encoding='utf-8'));print('\n'.join(sorted(d['libraries'])))"

# 2. 逐包许可（读本地 nuspec）
$p="$env:USERPROFILE\.nuget\packages"
Get-ChildItem $p -Directory | ForEach-Object {
  Get-ChildItem $_.FullName -Directory | ForEach-Object {
    $n = Get-ChildItem $_.FullName -Filter *.nuspec -ErrorAction SilentlyContinue
    if ($n) { $x=[xml](Get-Content $n[0].FullName); "$($x.package.metadata.id) $($x.package.metadata.version) -> $($x.package.metadata.license.'#text')$($x.package.metadata.licenseUrl)" }
  }
}
```

## 什么时候要重跑

- **升级 LibreHardwareMonitorLib**：它的传递依赖换过好几次（0.9.x 期间从 `HidSharp 2.1` 换到 `2.6`，
  又加了 `RAMSPDToolkit`），新版本可能带进新许可。
- **引入任何新 NuGet 包**，尤其是 `SharpDX`、`NAudio`、`ffmpeg` 轮子（这几类里 GPL/LGPL 很常见）。
- 把 PresentMon 换成自行编译的版本时。
