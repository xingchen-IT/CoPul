# M4.29 三个视图各自独立开关（再点一次收起）

> 起因：用户「现在三个模式全部显示之后没办法单独关闭某个窗口，添加一个再次点击某个模式能够隐藏的功能」。

## 1. 为什么会"关不掉"

M4.26 把三个视图改成了可叠加（`shownMain/shownFloat/shownTray` 三个独立真相位），但**入口没跟着改**：

| 入口 | M4.28 时的行为 | 三视图叠加后的问题 |
|---|---|---|
| 设置页「显示模式」 | 三个 `RadioButton` + `GroupName="mode"` 互斥 | 只能选一个；点已选中的那个**连 `Checked` 都不触发**，没法挂"再点收起" |
| 大窗口标题栏 ▭ / ▤ | `Button` + `ShowView` | 视图已显示时再点，`Show()` 一遍等于什么都没发生 |
| 托盘菜单 | `view:xxx` → `ToggleView` | 已经是 toggle，是唯一能单独关的入口（但没人会去找） |
| 托盘左键 / 全局热键 | `ToggleAllViews` | 全开 ↔ 全关，粒度太粗 |

所以"关不掉"不是状态机的问题，是**四个入口里有三个不会表达"收起来"**。

## 2. 改法

### 2.1 设置页：分段单选 → 三个独立开关

`Mode_Checked`（RadioButton）换成 `Mode_Clicked`（ToggleButton）：

```xml
<ToggleButton x:Name="ModeMain" Style="{StaticResource ViewChip}" Content="大窗口"
              Tag="main" Click="Mode_Clicked" />
```

新样式 `ViewChip`：**实心圆点 = 正在显示，空心灰点 = 已收起**。

- 不用 `Checked/Unchecked` 而用 `Click`：前者在程序自己给 `IsChecked` 赋值时也会触发，
  `SyncViewChips()` 每刷一次就会把三个视图各翻一遍。
- 动作交给 `SettingsContext.ToggleView`，它按**真实可见性**翻，不看控件当前的 `IsChecked` ——
  点下去时 WPF 已经把 `IsChecked` 翻过了，拿它当依据等于翻两次。

### 2.2 大窗口标题栏：两个按钮变开关

`Button` → `ToggleButton`（样式 `TitleBarToggle`）。亮着 = 该视图在显示，前景提成 `AccentCpu` 蓝。

按钮状态由 App 统一刷，不靠点击事件自己记：

```csharp
void ShowView(...) { ...; window.RefreshViewToggles(); }
void HideView(...) { ...; window.RefreshViewToggles(); }
```

因为**全屏自动切换也会动这两个视图**（进游戏收条、退出放条），那时用户一次都没点过按钮。

### 2.3 状态同步

`SyncViewChips()` 把开关拉到 `_ctx.IsViewShown(...)`，在三处调用：

1. 打开设置页（`LoadFromConfig`）
2. 点完任意一个开关
3. 窗口重新 `Activated` —— 用户可能先去托盘点了一圈再回来

## 3. 一个连带的取舍：点亮大窗口时设置页会收起

大窗口 853 DIP 宽、设置页 800 DIP 宽，都是 `CenterScreen`，同时出现只会严丝合缝地重叠，
用户看到的是"点了没反应"（M3 时期就踩过）。

原来 `Mode_Checked` 用 `Close()`。现在改成 `Hide()`：

- **只关不显示**：收起大窗口时设置页保持（这才是"边看边调"的场景）；
- **显示大窗口**：设置页 `Hide()`，点 ⚙ / 托盘「设置」立刻回来，滚动位置与探针状态都还在。

配套改了 `OpenSettings()`：`IsLoaded==true` 但 `IsVisible==false` 时要先 `Show()` ——
对一个隐藏窗口只 `Activate()` 什么都不会发生，表现就是"点了齿轮没反应"。

## 4. 取证

### 4.1 视图开关（设置页）

```
--settings-probe "viewtoggle:float,viewtoggle:float,viewtoggle:float"
```

```
views: main True/live=True float True/live=True taskbar False/live=False
views: main True/live=True float False/live=False taskbar False/live=False
views: main True/live=True float True/live=True taskbar False/live=False
```

开关与真实可见性始终一致，`float` 走完 显示 → 收起 → 显示。

### 4.2 真的"点一下"（含设置页自动收起）

```
--settings-probe "chip:main,chip:main"
```

```
chip: main → 设置页 visible=True     views: main False/live=False
chip: main → 设置页 visible=False    views: main True/live=True
```

第二次点亮大窗口后设置页自己收起；截图目标随之变成 `MainWindow`（sidecar：
`target=MainWindow visible=True ... settings=False`），说明确实收起了而不是被遮挡。

### 4.3 托盘菜单两向

```
--tray-menu-probe "view:float"          → [view] show Float ← Main by=tray-menu
--float --tray-menu-probe "view:float"  → [view] hide Float by=tray-menu
```

### 4.4 标题栏开关的视觉

三视图全开时 `--shot` 一定先挑覆盖层当目标（设置页 > 任务栏条 > 悬浮窗），
主窗口标题栏永远拍不到"两个都亮"。新增自测参数 `--view-buttons float,tray`
（与 `--run-state-probe` 同一类），强制点亮后拍：

| 状态 | sidecar | 截图 |
|---|---|---|
| 点亮 | `float checked=True fg=#FF5B8FF9 \| tray checked=True fg=#FF5B8FF9` | 两个图标蓝色 |
| 熄灭 | `checked=False fg=#FF6B7480` | 两个图标灰色 |

### 4.5 回归

`--view-probe --hidden`：8 步 `0→1→2→3→2→1→0→1` **全部通过**（不符合期望步数 0）。
三视图叠加链路没被碰坏。

## 5. 已知边界

- 三个视图**全关**后进程仍在托盘：左键（`ToggleAllViews`）或右键菜单可恢复，不会变成"无窗口僵尸"。
- 视图**组合仍不落盘**：重启后按 `--tray` / `--float` / 默认三选一，与 M4.26 一致。
- `--settings-probe` 的老语义保持：`mode:float` 仍是"切到该视图"（幂等），不是 toggle ——
  老脚本会连发，toggle 一次反而把它关掉。验 toggle 用新命令 `viewtoggle:` / `chip:`。
