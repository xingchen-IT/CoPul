# M4.22 全屏自动切换：修掉"点一下就回任务栏"的抖动

需求原话：

> 从任务栏模式开全屏之后那个悬浮窗在点击一下之后就会回到任务栏模式，再次点击屏幕其它地方之后就会进入悬浮窗模式；
> 除此之外我想要的全屏自动切换为悬浮窗模式是直接切换到真正的悬浮窗（与手动打开悬浮窗模式相同）

两个确认项（已与用户确认）：

1. **保留 8.2 的回落语义**：退出全屏后仍自动回任务栏条。
2. **自动切换不再按显示器重摆**：直接用用户自己的悬浮窗位置（与手动态一致）。

编译：0 警告 0 错误（Release，`dotnet build CoPul.sln -c Release`）。

---

## 1. 根因：判定的"主体"不是前台，而前台被用户点走了

全屏检测一直是这么问的：**前台窗口是不是全屏**（`GetForegroundWindow()` + 主判据 QUNS + 辅判据几何）。
这个问法有个隐含前提——前台就是用户正在用的那个应用。自动切到悬浮窗之后，这个前提没了：

```
任务栏条 ──全屏 800ms──▶ 悬浮窗(auto) ──用户点了一下悬浮窗──▶ 前台 = CoPul 自己的窗口
                                                              │
                                   检测器走 veto:self ────────┘
                                   "前台是自己 ⇒ 不是全屏"
                                            │
                                   500ms 防抖 ──▶ Float(auto)→Taskbar（回落）
                                            │
                          用户点回游戏/桌面 ──▶ 前台又不是自己 ──800ms──▶ 又切回悬浮窗
```

于是就成了用户描述的那个来回：**点一下回条、再点一下回悬浮窗**。

关键在于 `veto:self` 这条规则**没错**（自己的窗口确实不能当全屏证据），错的是**主体选错了**：
那一刻该回答的问题是"刚才那个全屏窗口还在不在全屏"，而不是"前台是不是全屏"。

### 顺带的两处"抢焦点"

排查时发现两个窗口都在 `Show()` 时抢前台（WPF 默认 `ShowActivated=True`）：

| 窗口 | 何时抢 | 后果 |
|---|---|---|
| 悬浮窗 | 全屏自动切过去的那一刻 | 把键鼠从游戏里抽走（有的游戏会因此暂停/掉帧） |
| 任务栏条 | 启动、"退出全屏回落任务栏"那一下 | 把刚退出来的游戏顶掉 |

两者都是覆盖层，只该"在最上面"（topmost 已经保证），不该抢前台。

## 2. 改了什么

### ① 记住"是谁把全屏顶起来的"，前台变自己时改判它

`FullScreenDetector.Probe()` 多了一个可选的**替补主体**参数：

```csharp
public static FullScreenInfo Probe(IntPtr candidate)
{
    IntPtr fg = GetForegroundWindow();
    ...
    if (IsSelf(fg) && IsUsableSubject(candidate, fg))
        return Evaluate(candidate, quns, "self-focus→prev ");   // 改判候选
    return Evaluate(fg, quns, "");                               // 原路径
}
```

替补必须"活着、可见、没最小化"（`IsWindow && !IsIconic && IsWindowVisible`），
否则一律退回前台判定 —— 这条是防止反过来赖着不走：游戏关了 / 最小化了 / 变窗口化了，都得照常回落。

状态机只在 **`Float` + `origin=Auto`** 时把记下的句柄交出去：

```csharp
private IntPtr CandidateSubject =>
    UseFullHwndCandidate && CurrentView == View.Float && FloatOrigin == Origin.Auto
        ? _fullHwnd : IntPtr.Zero;
```

别的视图下"前台是自己"完全正常（用户正在用 CoPul），拿旧句柄去判会把这种情形误判成全屏。
句柄在进入全屏时记、回落 / 用户离开悬浮态时清。

### ② 覆盖层不再抢前台

`FloatWindow` / `TaskbarWindow` 的 XAML 都加 `ShowActivated="False"`，
`ShowView` 多一个 `activate` 参数：用户主动切的照旧 `Activate()`，全屏自动切传 `activate: false`。

### ③ 自动切换 = 纯粹的切视图

`EnterAutoFloat` 里那句 `EnsureFloat().PlaceOnMonitor(monitor)` 去掉了（8.6 的"摆到全屏所在显示器左下角"）。
现在自动切与手动打开走的是同一条路、同一个窗口、同一个位置。副屏规则的钩子保留在 `FloatWindow.PlaceOnMonitor`，
将来要开只改一行。

## 3. 真机取证

伪造探测结果那条老探针（`--fs-switch-probe`）**结构上验不到这个 bug**：它把 `FullScreenInfo` 直接喂给状态机，
根本不经过 `GetForegroundWindow()`。所以新增 `--fs-live-probe`：什么都不伪造，真实探测 + 真实窗口，
按 500ms 采样，可选在中途 `Activate` 悬浮窗来模拟"用户点它一下"；"游戏"用 `tools/fake-fullscreen.py`
（另一个进程的无边框铺满屏窗口，会自己抢前台）扮演。

| 场景 | 命令要点 | 结果 |
|---|---|---|
| 修复后 | `--tray --fs-live-probe … --fs-live-focus 7000 --fs-live-end 20000` | **2 次迁移**：进 Float → 游戏关掉才回落 |
| 旧行为（A/B） | 同上 + `--no-fs-candidate` | **4 次迁移**：进 Float → 点一下回 Taskbar → 又进 Float → 又回 Taskbar |
| 退出全屏（缩成窗口） | `fake-fullscreen.py --shrink 11` + 同上 | 悬浮窗占着前台也照样回落 |

修复后的采样（`fs-live-fix.txt`，`fg` 列 `(own)` 表示前台是 CoPul 自己）：

```
  1591 Float    Auto  True  0x1B20ECA(ext)  True  quns=2(需几何旁证)+rect-caption ⇒ aux-full
  7102 Float    Auto  True  0x1B20ECA(ext)  True  …
---- 7102ms：Activate 悬浮窗（模拟用户点它一下）----
  7655 Float    Auto  True  0x1941180(own)  True  self-focus→prev quns=2…⇒ aux-full   ← 前台变自己，仍判全屏
 11678 Float    Auto  True  0x1941180(own)  True  self-focus→prev …
 12172 Float    Auto  True  0x1941180(own)  False veto:self                            ← 游戏已销毁，替补作废
 12684 Taskbar  Manual False 0x1200AB0(ext) False veto:self                            ← 500ms 后回落
```

A/B（`--no-fs-candidate`）原样复现用户报的现象：

```
23:46:51.764 enter-full: Taskbar→Float(auto) hwnd=0x9E0F92
23:46:58.337 exit-full:  Float(auto)→Taskbar reason=veto:self     ← 点一下就回落
23:46:59.862 enter-full: Taskbar→Float(auto) hwnd=0x9E0F92       ← 再点一下又回来
23:47:02.913 exit-full:  Float(auto)→Taskbar reason=veto:self
```

"游戏退出全屏但窗口还在"那条（`--shrink`）——替补主体被判非全屏，回落照旧：

```
23:51:14.166 enter-full: Taskbar→Float(auto) hwnd=0x6E1518
23:51:22.256 exit-full:  Float(auto)→Taskbar reason=self-focus→prev not-full: rect-caption
```

位置一致性：自动切过去时悬浮窗落在 `(24,1453)-(661,1504)`，手动 `--float` 启动同样是 `(24,1453)-(661,1504)` —— 完全一致。

回归：`--fullscreen-probe`（判据自检 + 成本 0.129% 单核）与 `--fs-switch-probe`（6 步全 ✓，终态 Taskbar）结果与改动前一致。

## 4. 自测开关

| 开关 | 作用 |
|---|---|
| `--fs-live-probe <txt>` | 真机采样：真实探测 + 真实窗口，500ms 一行 |
| `--fs-live-focus <ms>` | 第几毫秒 Activate 悬浮窗（模拟用户点它一下） |
| `--fs-live-end <ms>` | 第几毫秒收尾写文件并退出 |
| `--no-fs-candidate` | 关掉替补主体（= 修复前的旧行为，A/B 用） |
| `--no-float-activate` | `--float` 启动时也不 Activate |

配套：`tools/fake-fullscreen.py` 新增 `--shrink <秒>`（中途缩成 800×600，模拟"退出全屏但窗口还在"），
并修了 `SetWindowPos` 未声明 `argtypes` 导致缩窗静默失败的老问题。

## 5. 铁律补充

- **"前台窗口"这类判据，先问一句"前台被自己人占住时该怎么办"**。
  凡是以 `GetForegroundWindow()` 为主体的判定，都要考虑"用户点了我们自己"这条分支，
  否则覆盖层一旦可点击就会自证"非全屏"。
- **覆盖层一律 `ShowActivated="False"`**，要前台时显式 `Activate()`。
  topmost 管的是"在最上面"，不是"抢输入焦点"，两件事别混。
- **几何/状态类判据对"谁在前面"结构性失明**（与 M4.17 的 `WM_NCACTIVATE` 同类）：
  看日志里 `reason` 的前缀（`self-focus→prev`）比看像素有用得多。
