# M4.49 安装路径可自定义

> 起因：安装向导里找不到「选择目标位置」，无法把程序装到 `C:\Program Files` 以外的地方。
> 结论：路径本来就能改，是 **Inno 的 `DisableDirPage` 默认值 `auto` 在「本机已装过」时把整页藏了**。
> 显式打开这一页之后，又必须补一套校验——用户级安装写不进系统目录，光把「浏览」按钮露出来等于挖坑。

## 一、改了什么

| 项 | 改动 | 理由 |
| --- | --- | --- |
| `DisableDirPage` | 显式 `no` | `auto` 会在检测到已安装时隐藏目录页，重装/升级的用户永远看不到 |
| `UsePreviousAppDir` | 显式 `yes` | 记住上次选的路径，下次打开目录页默认就是它（默认值，写出来说明意图） |
| 目录页文案 | 覆盖 `SelectDirDesc` | 默认文案只说「装到哪个文件夹」，没讲清「仅当前用户、装不进 Program Files」 |
| `[Code]` 校验 | 新增 `CheckTargetDir` | 拦系统目录、盘符根、超长路径、无写权限目录 |
| `[UninstallDelete]` | `filesandordirs` → `dirifempty` | 允许自定义路径后，用户可能装进与别的软件共用的目录，递归删会连别人的文件带走 |
| `tools\build-installer.ps1` | 产物带 Low IL 时自动复制一份到 `Downloads` | 见 M4.48 补记，`artifacts\` 继承低完整性标签，原地那份双击报错误 5 |

## 二、校验规则

`CheckTargetDir` 按顺序判，命中即返回原因：

| 判据 | 拦下的路径示例 | 提示 |
| --- | --- | --- |
| 空路径 / 含双引号 | — | 直接说明 |
| 长度 > 180 | 深嵌套目录 | 自包含发布里有 `System.Private.Xml.resources.dll` 这类长文件名，再叠深就到 `MAX_PATH` |
| 落在系统目录下 | `C:\Program Files`、`C:\Windows`、`C:\ProgramData`、公共开始菜单 | 「需要管理员权限，本安装仅当前用户」+ 给出默认路径 |
| 盘符根 | `D:\` | 建议 `D:\Programs\CoPul` |
| 已存在且写不进去 | 别人设了只读的目录 | 实测 `SaveStringToFile` 探针 |

系统目录的判断用 `IsUnderPath`，比较前**统一正反斜杠**——命令行 `/DIR=C:/Program Files/...` 过来的是正斜杠，不归一化就匹配不上 `{pf}`，校验会被整个绕过。

三个入口都挂了校验：

1. `NextButtonClick(wpSelectDir)` —— 交互点「下一步」时
2. `InitializeSetup` —— 处理 `/DIR="..."`，因为带这个参数时向导会跳过目录页
3. 目录页之外的最终防线由 Inno 自己兜（创建目录失败会报错）

## 三、四个坑

### 1. `DisableDirPage` 默认 `auto`，已装过就藏页

Inno 默认值是 `auto`：检测到本机装过同一 `AppId` 就隐藏目录页，直接装到上次的路径。
表现是「安装器没有让选路径的地方」，很容易误判成脚本写死了路径。显式 `no` 之后每次都能看到。

### 2. `PrepareToInstall` 的错误框抑制不掉，静默安装挂死

最初把校验放在 `PrepareToInstall` 里（返回非空字符串即中止），交互模式下体验很好，但：

```
静默安装 /VERYSILENT /DIR="C:\Program Files\..." → TIMEOUT 300 秒
```

`/SUPPRESSMSGBOXES` 对这个框无效。原因是被拦时 Inno 用不可抑制的 `MsgBox` 报错。
无人值守安装（脚本、批量部署）会全部超时——比装失败更糟。

改成 `InitializeSetup` 里判断：静默模式只 `Log` + `return False`（Inno 对 `InitializeSetup` 返回 False 是**静默退出**，不弹任何框），交互模式才 `MsgBox`。实测 **0.7 秒**退出、日志有完整理由。

### 3. `WizardSilent` 在 `InitializeSetup` 阶段还没初始化

直觉写法 `if not WizardSilent then MsgBox(...)` 在 `InitializeSetup` 里恒为「非静默」，照样弹框。
只能自己看命令行：

```pascal
Tail := Uppercase(GetCmdTail());
if (Pos('/VERYSILENT', Tail) = 0) and (Pos('/SILENT', Tail) = 0) then
  MsgBox(Reason, mbError, MB_OK);
```

### 4. Pascal 注释不嵌套，注释里写 Inno 常量会截断

```pascal
{ 不统一就匹配不上 {pf}，校验会被绕过。 }
```

`{pf}` 的右花括号把注释提前结束了，后半句变成代码 → 编译报 `Syntax error. Column 18`。
注释里提常量要写文字（「Program Files 这类常量」），别写花括号原文。

## 四、卸载行为的变化

`[UninstallDelete]` 从 `filesandordirs` 改成 `dirifempty`：

- 原来路径固定在 `%LOCALAPPDATA%\Programs\CoPul`，一定是独占目录，递归删安全。
- 现在允许自定义路径，用户可能选 `D:\Tools` 这种与别的软件共用的目录。`filesandordirs` 会把整个目录删掉——**别人的文件一起没了**。
- `dirifempty` 只在目录为空时删，代价是极端情况下可能留一个空壳。

实测（独占目录）：卸载后目录连同 `unins000.exe` 一起消失，与 M4.48 的结论一致。

共用目录的验证：往 `D:\CoPulSharedTest` 先放一个「别人的文件.txt」，再装进去（485 个文件），
然后卸载——**目录还在、别人的文件还在、只剩 1 个文件**，CoPul 的 484 个全清。
换成原来的 `filesandordirs`，这个目录会连同别人的文件一起消失。

## 五、验收

| 项 | 结果 |
| --- | --- |
| 交互模式目录页出现 | ✓ 截图 `m449-dirpage.png`，路径框预填上次位置 |
| 静默装到 `D:\CoPulRun2\Programs\CoPul` | ✓ `exit=0` 7.4 秒 / 484 文件 / 卸载项 `InstallLocation` 指向新路径 |
| 静默装到 `C:\Program Files\CoPul-M449-Test` | ✓ `exit=1` **0.7 秒**退出、目录未创建、日志写明「这个位置需要管理员权限」 |
| 交互选 `C:\Program Files\...` | ✓ 弹错误框，留在目录页不前进 |
| 记住上次路径 | ✓ 第二次打开目录页预填 `D:\CoPulRun2\Programs\CoPul` |
| 自定义路径卸载（独占） | ✓ 目录连 `unins000.exe` 一起消失 |
| 共用目录卸载 | ✓ 装进去 485 个文件，卸载后目录保留、别人的文件完好、只剩别人那 1 个 |
| 恢复到默认安装 | ✓ 484 文件 / `InstallLocation` 指回 `%LOCALAPPDATA%\Programs\CoPul\` |

> `/LOG` 生成的是 **UTF-8 with BOM**（不是 UTF-16），探针按 utf-16 解码会全是乱码——踩过一次。

## 六、没做的事

- **没加「为所有用户安装」**。那需要 `PrivilegesRequiredOverridesAllowed=dialog` + 弹 UAC，与 0.1.0「双击即装、不弹 UAC」的定位冲突。真要装进 `Program Files`，得先改这个产品决策。
- **没动 `D:\CoPul开发` 的低完整性标签**。试过 `icacls /setintegritylevel Medium`，单文件和对 `artifacts\` 都返回 exit=5（被同目录那条 `Everyone:(CI)(DENY)(DC)` 挡住），改用「构建脚本自动复制一份到 Downloads」绕过，不碰工作区安全设置。
