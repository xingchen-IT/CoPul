# M4.21 悬浮窗：鼠标穿透 + 始终置顶

需求原话：

> 1. 添加悬浮窗模式锁定位置之后也能鼠标穿透的功能
> 2. 悬浮窗模式下，芯脉的悬浮窗始终置于桌面或者说窗口的最顶层

编译：0 警告 0 错误（Release，`dotnet build CoPul.sln -c Release`）。

---

## 1. 加了什么

### 悬浮窗右键菜单（新增两项）

| 项 | 说明 |
|---|---|
| 鼠标穿透 | 勾选后悬浮窗不接收任何鼠标消息，点它等于点它下面的东西 |
| 始终置顶 | 每秒把悬浮窗提回 topmost 组最顶（默认开） |

### 设置页新增「悬浮窗交互」卡片

三行开关：**锁定位置 / 鼠标穿透 / 始终置顶**。穿透开启时「锁定位置」自动置灰（见下）。

### 托盘图标右键菜单新增「悬浮窗可点击」

穿透后悬浮窗收不到鼠标，托盘这条是关掉它的出口之一。

### 配置

| 字段 | 默认 | 说明 |
|---|---|---|
| `FloatClickThrough` | `false` | 鼠标穿透 |
| `FloatAlwaysOnTop` | `true` | 每秒提回顶层 |

## 2. 五个关键取舍

### ① 穿透用 `WM_NCHITTEST → HTTRANSPARENT`，不用 `WS_EX_TRANSPARENT`

与任务栏条同一招。`WS_EX_TRANSPARENT` 要配 `LAYERED` 才生效，一配 WPF 就退软件合成、毛玻璃全变（M4.1 踩过）。
`HTTRANSPARENT` 只改命中测试的结论，不碰渲染，**画面一个像素都不变**，切换也不需要重建窗口。

### ② 穿透必然拖不动，所以打开它要连带锁上位置

鼠标消息根本不投递，`DragMove` 没有触发源。如果只加"穿透"而不动"锁定"，用户会得到"解锁了却还是拖不动"。
所以：开穿透 → 记下当前锁定状态 → 强制锁定 → 把「锁定位置」项置灰；关穿透 → 还原成开之前的样子。
菜单项置灰是刻意的：让"不能再动"看得见，而不是点了没反应。

### ③ 出口必须另有其人，且三处都在

穿透后右键菜单也收不到（消息不过来）。三个出口：

1. 托盘图标右键 → 「悬浮窗可点击」
2. 设置页 → 「悬浮窗交互」卡片
3. 全局热键 → 切到大窗口 / 任务栏条，再回来

缺任何一个都可能把用户困在"悬浮窗摸不到"的状态里。

### ④ 置顶不能只靠 `Topmost="True"`

XAML 里早就是 `Topmost="True"`，但它只保证"进 topmost 组"，不保证"排在组里最前"——
另一个置顶窗口（游戏浮层、录屏工具条）一激活就压上来，而**没有任何事件通知我们**。所以只能每秒巡检一次：
`SetWindowPos(HWND_TOPMOST, NOMOVE|NOSIZE|NOACTIVATE)` —— 不改几何、不抢焦点，没有可见副作用。

### ⑤ 巡检的判据是三层，"被挡住"不等于"上面有窗口"

| 层 | 挡掉的假阳性 | 实测对象 |
|---|---|---|
| 可见 | IME 窗口、托盘消息窗、监听用的 `HwndSource` | `Default IME`（自家、隐藏、永远占 Z 序第一） |
| 有面积 | `ThumbnailDeviceHelperWnd`（`IsWindowVisible` 为真，尺寸 0×1） | 排在上面，一个像素都不遮 |
| 矩形相交 | 屏幕另一头的置顶窗口 | 各占一块地方，为它提顶毫无意义 |

只看 `GW_HWNDPREV` 的结果：**9 秒提了 9 次顶，一次都没提动**（被 IME 挡着判成"永远被压"）。
改成三层过滤后空闲态 `raiseHits=0`，真被挡时提 1 次就稳住。

另外两条让路规则：前台是本进程窗口时不抢（用户在跟设置页交互）；压在上面的是自家**可见**窗口时不抢。
注意"自家"必须加可见判断 —— 本进程常驻的隐藏辅助窗口会把巡检永久挡死。

## 3. 两个实测踩到的坑

### 消息钩子挂错了地方

钩子原本挂在 `EnableSystemShadow()` 里，而那条路在 `--no-shadow` 时整个跳过。
穿透靠的 `WM_NCHITTEST` 走同一个钩子 → 变成"关掉阴影就没有穿透"，两者毫无关系。
现在钩子在 `SourceInitialized` 里独立挂一次，`EnableSystemShadow` 只管 style。

### 本机造不出能压住悬浮窗的外部窗口（UIPI）

CoPul 是提权进程，UIPI 保证高完整性窗口永远排在低完整性窗口之上 ——
用 Python 建的整屏 topmost 窗口**一次都没出现在悬浮窗的 Z 序链里**。
所以自测用 `--float-blocker`（本进程、置顶、可见的橙色窗口）当遮挡物，且必须**晚于悬浮窗 Show**
（同组里后 Show 的才在上面，直接在参数区 Show 会落在下面，一次都遮挡不到）。

## 4. 取证

sidecar 新增 `interact:` 行（`--float-zreport` 可打到标准输出，用于"设置页同时开着、sidecar 不写"的场景）。

### 鼠标穿透

| 场景 | 关键判据 |
|---|---|
| 默认 | `probeHT=HTCLIENT(1 正常接收)` |
| `--float-through 1` | `probeHT=HTTRANSPARENT(-1 穿透中)`、`hitTestHits=1` |
| 竖向 + 穿透 | 同上，尺寸 `51.33×384`（改穿透不影响布局） |
| 托盘命令 `toggle:floatthrough` | `through=True`、`hitTestHits=12`（真实鼠标移动产生的 12 条消息全被拦）、配置落盘 `true` |
| 未锁定 → 开穿透 | `lock=False → lock=True`（自动锁定） |
| 探针跑完 | 配置仍是 `FloatLocked=False / FloatClickThrough=False`（不污染） |

`probeHT` 是给自己发一条真实 `WM_NCHITTEST` 问出来的 —— 穿透改的是命中测试的结论，
`WindowFromPoint` 不做命中测试、截图更看不出差别（一个像素都不变），只有这条路问得到。

### 始终置顶

| 场景 | `interact` 关键字段 |
|---|---|
| 空闲（无遮挡） | `raiseHits=0 above=0x0` —— 不做无效功 |
| 有遮挡 + 自测算自家 | `raiseHits=1 raiseOk=True postRaise=0x0` —— 检测到 → 提顶 → 提完上方归零，之后稳定 |
| 有遮挡 + 生产行为 | `raiseHits=0 above=0x16B0E38 aboveOwn=True` —— 检测到但按策略给自家窗口让路 |
| 配置 `onTop=True` | `exStyle=True`（真在 topmost 组） |
| 配置 `onTop=False` 重启 | `exStyle=False`（真退出，不只是"不再巡检"） |
| `--float-topmost 0` | `ontop=False raiseHits=0` |

A/B 用的遮挡物是本进程的 `--float-blocker`；提顶只发生 1 次说明提完就稳在最顶，不会每秒互相拉扯。

### 设置页

截图 `docs/preview-m4.21-settings-interact.png`：三行开关齐全，「鼠标穿透」为开启态、「锁定位置」置灰、
说明文字 4 行完整换行不截断。探针 `floatinteract` 打印 `lock=False through=True topmost=True lockEnabled=False`，退出后配置还原。

## 5. 新自测开关

| 开关 | 用途 |
|---|---|
| `--float-through 1\|0` | 鼠标穿透（只开这一项不落盘） |
| `--float-topmost 0\|1` | 关/开置顶巡检 |
| `--float-hittest-probe` | 给自己发 `WM_NCHITTEST`，结论进 `interact:` 行 |
| `--float-ztop-probe` | 每秒打印"我"上面的 Z 序链（判据排错用） |
| `--float-ztop-own` | 把自家可见窗口也算遮挡（验提顶链路，生产不打开） |
| `--float-blocker <秒>` | 造一个本进程置顶可见窗口当遮挡物 |
| `--float-zreport` | 把 `interact:` 行打到标准输出 |
| 设置页探针 | `floatlock:1` / `floatthrough:1` / `floattopmost:0` / `floatinteract` |

## 6. 需要用户做的

**重启 `CoPul.exe`** —— 旧进程用的还是上一版程序集。

穿透默认是关的；打开后如果想关回来，右键点在悬浮窗上是没用的（消息穿透了），请走托盘图标 / 设置页 / 全局热键。
