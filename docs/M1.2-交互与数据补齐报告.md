## 2. D03 每盘速率（关闭 R21）

### 2.1 实现

`OsProvider.AddPerDiskCounters()` 枚举 `\PhysicalDisk(*)\Disk Read Bytes/sec`，
**从实例名首段解析 `PhysicalDriveN` 的 N**，按索引存进 `PdhCounter?[]`，
与 D02 盘温数组用同一套下标。

```
实例名 "0 C:"     → 索引 0
实例名 "1 D: E:"  → 索引 1
实例名 "_Total"   → 跳过
```

三个必须写下来的点：

| 点 | 为什么 |
|---|---|
| 只取索引，**忽略盘符** | 盘符会变（插 U 盘、改盘符），索引不会。按盘符匹配的话，"E: 变 F:" 会让整块盘的速率变成 `—` |
| 数组长度取 `maxIndex + 1`、空位留 null | 本机索引是 **0 和 2**，没有 1。按枚举顺序塞会把第 2 块盘的速率画到第 1 块上 |
| 与合计共用同一次 `Collect()` | 合计走 `_Total`、每盘走各自实例，同一个 query 一次刷新，不额外调 `PdhCollectQueryData` |

### 2.2 验证

用 Python 持续 `write + fsync` 往 `D:` 写 9 秒（1467 MB），同时截图：

| 位置 | 合计 | 盘 0 | 盘 1 |
|---|---|---|---|
| 截图读数 | 写 1.7 MB/s | 写 **1.7** MB/s | 写 **0.0** MB/s |

两块盘读数**不同**且合计等于盘 0 —— 说明下标对齐正确、没有把合计摊到每行。
（截图在写完后 10 秒才拍，所以只剩尾部 1.7 MB/s，不是 163 MB/s 的峰值。）

### 2.3 遗留：热插拔的盘不会出现（R23）

实例是初始化时一次性挂上的。开机后再插的盘，要等程序重启才会出现在列表里。
v1 不处理，理由：CoPul 是常驻工具，插拔盘的场景下"重启一次"成本可接受，而做动态重挂
要处理"实例名失效 → 全部计数器重新绑定 → 首帧无数值"，复杂度不对等。

## 3. D04 分区 10 秒刷新

### 3.1 实现

`SystemInfo.ReadPartitions()` 抽成静态方法，`Collect()` 与新增的 `RefreshPartitions()` 共用同一段逻辑
——两条路径分开写迟早会长歪。

`CollectorHost` 起一个 `BelowNormal` 线程，10 秒醒一次：

```
_refresh 计数 → info.RefreshPartitions() → 只有"真的变了"才 Post 到 UI
```

**"变了"的判定**：卷数量变了，或任一卷的**使用率整数位**变了，或容量差 > 1 MB。
不做这个判定的话，每 10 秒都会白白重排一遍分区行 —— 而这个行并不便宜。

### 3.2 验证

`--stats` 输出新增一行：

```
d04 refresh : 3 次  其中变化 0 次
```

35 秒窗口（预热 5 秒后计时 30 秒）刷新 3 次 = 10 秒一次，符合 4.4。
变化 0 次也是对的：300 GB 的 C 盘要跳 1 个百分点得写 3 GB。

## 4. 窗口几何持久化（A-07）

### 4.1 落盘

`Sdk/ConfigStore.cs`，路径 `%APPDATA%\CoPul\config.json`：

| 决策 | 理由 |
|---|---|
| 用 `%APPDATA%` 而不是 exe 目录 | Program Files 下没有写权限；绿色版放 U 盘又会把配置带到别的机器 |
| 临时文件 + `File.Replace` | A-07。直接 `WriteAllText` 写一半被杀，留下的是语法不完整的 JSON，用户表现为"设置永远保存不上" |
| `Flush(flushToDisk: true)` | 只写进 OS 缓存就返回的话，"原子替换"换上去的可能还是空内容 |
| 未知字段忽略、缺字段取默认 | 旧版本配置永远能读，不需要 migration |
| 读失败返回默认值 + `LoadError` | 配置坏了不能影响启动 |

### 4.2 一个必须修的坑：DIP 与物理像素混用

第一版直接用 `MonitorFromRect` 返回的 `RECT` 和 `Window.Left` 比较。**在 150% 缩放下两者差 1.5 倍**，
表现是配置里的位置每启动一次就往右下挪一截：

```
首次运行  → 保存 (443.33, 129.33)
第二次    → 读 443.33，写回 665   （443.33 × 1.5）
第三次    → 读 665，写回 997.5
```

第二版统一到 DIP：查询时把 DIP 乘 `DpiScale` 转物理像素交给 Win32，拿到工作区再除回去。
连跑三次，配置**逐字节一致**：

```
run 1 / run 2 / run 3 → { "WindowLeft": 443, "WindowTop": 129, "WindowWidth": 820, "WindowHeight": 760 }
```

### 4.3 5.4 的另外两条

- **位置必须落在当前可见显示器内**：`MonitorFromRect(..., MONITOR_DEFAULTTONULL)`。
  返回 NULL 说明上次的位置已经不在任何显示器上（拔了副屏 / 改了分辨率），回退居中。
  用 `DEFAULTTONULL` 而不是 `DEFAULTTONEAREST`——后者总会硬给一个最近的显示器，
  于是"窗口完全在屏幕外"这种真错误会被掩盖成"看起来正常"。
- **尺寸也要钳**：4K 下存的 3840×2000，换到 1080p 屏会超出工作区，必须按工作区上限截断。

### 4.4 存的是 RestoreBounds

最大化状态下 `Window.Left/Top/Width/Height` 是"最大化后"的值。直接存会让
"最大化退出 → 重开 → 还原"还原成一个占满屏幕的窗口。所以非 Normal 状态一律存 `RestoreBounds`。

## 5. 区块折叠

### 5.1 实现

`BlockState`（id / Collapsed / BodyVisibility / Arrow），四个区块各一个，绑到 XAML。
折叠状态存进 `config.json` 的 `CollapsedBlocks`。

**折叠不只是把内容藏起来**：`DashboardState.ApplySnapshot` 按区块拆成四个方法，
折叠的整段跳过 —— CPU 区块那行 20 个核心的字符串拼接、硬盘行的速率格式化都不再执行。

### 5.2 验证

手改配置 `"CollapsedBlocks": ["gpu", "disk"]` 后启动，截图确认：
GPU 与硬盘只剩标题行，箭头变成 `▸`，CPU 与内存正常展开。

## 6. 性能：这一轮**没能测准**，原因不在代码

### 6.1 六轮结果（60 秒窗口，`--stats --seconds 60 --warmup 10`）

| 轮次 | 1 | 2 | 3 | 4 | 5 | 6 | 中位 | 最坏 |
|---|---|---|---|---|---|---|---|---|
| 单核 % | 0.937 | 1.171 | 1.641 | 1.535 | 1.328 | 1.223 | **1.276** | **1.641** |

对照 M1.1（三轮）：0.807 / 1.172 / 1.249，中位 1.172、最坏 1.249。

**中位从 1.172 涨到 1.276（+0.10pp），最坏从 1.249 涨到 1.641，6 轮里 2 轮越 1.5% 线。**

### 6.2 测量期间机器上在跑什么

| 进程 | 单核口径占用 | 说明 |
|---|---|---|
| `java.exe` | **78.4%** | 持续，整个测量期间都在 |
| `WorkBuddy.exe` | 45.1% | 就是发起测量的这个会话 |
| `dwm.exe` | 20.5% | 桌面合成 |
| `System` | 22.5% | — |

合计约 **1.7 个核**持续忙。11 章与 A-26 都要求"必须独占运行"——这轮**不满足前提**。

### 6.3 但采集层可以单独看（不受 UI/DWM 影响）

同一时段的 `--hidden`（不显示窗口，只采集）：

| 模式 | 单核 | 帧数 | UI 线程 |
|---|---|---|---|
| `--hidden`（只采集） | **0.624%** | 57 / 30s | 47 ms |
| 显示窗口 | 1.249% | 58 / 30s | 94 ms |

`--hidden` 的 0.624% 与 M0.6 用 m06 单独测的 0.573% 相差 0.05pp —— **每盘 D03 的 4 个计数器没有带来可测的成本**。
差值 0.62pp 就是 UI。

### 6.4 决定性实验：把 T1b floor 抬到 1000ms，中位反而升高

按 A-26 的第一顺位退路，把 `Tier.T1b` 从 500 改成 1000（全核温度 1Hz），再跑四轮：

| 轮次 | 1 | 2 | 3 | 4 | 中位 |
|---|---|---|---|---|---|
| 单核 % | 1.380 | 1.197 | **2.062** | 1.445 | **1.41** |

**中位从 1.276 涨到 1.41**。这不是"抬 T1b 有害"，而是**0.1pp 级的参数效果被 0.7pp 级的环境噪声完全淹没**。
这一轮实验证明的是**测量无效**，不是参数无效。已回滚 T1b 到 500ms，并在 `TierInfo` 里写死了这段原因。

> **教训（第三次同类）**：单次读数不能当基线（v0.8 已经吃过）、相关性不能当因果（R17）、
> **噪声里做参数决策等于掷骰子**。抬 T1b 是"看起来有道理"的动作，但在当前环境里它和"不抬"无法区分。

### 6.5 用稳定的量代替不可控的占比

占比（`single-core`）会被环境干扰，但这些量不会：

| 量 | M1.1 | M1.2 | 判断 |
|---|---|---|---|
| 平均 `UpdateLayout` | ~2.0 ms | 1.90 – 2.21 ms | 未变 |
| 平均 `ApplySnapshot` | 0.28 – 0.39 ms | 0.26 – 0.49 ms | 未变 |
| 帧率 | 1.82 /s | 1.78 – 1.87 /s | 未变 |
| 采集（`--hidden`） | — | 0.624% | 与 m06 的 0.573% 同量级 |

UI 那两块加起来 4.7 ms/s ≈ 0.47%，与 M1.1 的估算一致。**没有证据表明 M1.2 让程序变贵了。**

### 6.6 结论与待办

- **按 1.5% 验收线，本轮 6 轮里 2 轮超标，不能宣称通过。**
- 根因是环境不满足独占条件，不是可归因的回归。
- **待办**：在机器空闲（任务管理器 CPU 利用率 < 10%）时重跑 6 轮。`tools/m12/measure.cmd` 是一键脚本。
- 若安静环境下仍稳定超线 → 按 A-26 顺序：先抬 T1b floor（这次是有意义的测量），再关 `EnablePerCoreLoad`，最后才考虑界面瘦身。**不得再动目标。**

## 8. 怎么跑

```bash
# 正常启动
dotnet CoPul.dll

# 截图（无头验收）
dotnet CoPul.dll --shot out.png --wait 6000

# 自身开销：60 秒窗口 + 10 秒预热 + 线程级分解
dotnet CoPul.dll --stats out.txt --seconds 60 --warmup 10

# 只采集不显示窗口（分离 UI 成本）
dotnet CoPul.dll --stats hidden.txt --seconds 30 --warmup 8 --hidden
```

一键复测（双击，需先把机器上其他重负载关掉）：

```
tools\m12\measure.cmd
```

配置在 `%APPDATA%\CoPul\config.json`，删掉即恢复默认（居中、820×760、全展开）。
