# M4.33 全屏游戏"看不见却点得到"——自动让路

> 报障原话：「mc 全屏时候不是看不清是根本不显示」「图片上面的帧率是游戏自带的」
> 「还有个新发现就是点击游戏中悬浮窗所对位置就会退出全屏显示悬浮窗」

## 1. 第三句话把问题定死了

前两轮我一直在查"为什么不显示"，全部结论都是"显示正常"——因为取证方式本身有毛病（见 §3）。
真正有诊断价值的是用户顺手说的第三句：

> **点游戏画面里悬浮窗所在的位置，游戏就掉出全屏，然后悬浮窗出现了。**

这一句同时证明了三件事：

| 事实 | 推导 |
| --- | --- |
| 点击命中了悬浮窗（而不是落到游戏上） | `WM_NCHITTEST` 被我们的窗口接走了 |
| 点击导致游戏掉出全屏 | 前台切给了悬浮窗 → 游戏失焦 |
| 掉出全屏之后悬浮窗就看得见 | 窗口本身、位置、渲染**全都是对的** |

也就是说：**窗口在、Z 序最上、能接收鼠标，但它的像素没有出现在显示器上**。

## 2. 根因：合成层与扫描输出不是一回事

正常情况下 DWM 把桌面（含 topmost 覆盖层）合成好，再交给显卡扫描输出，两者一致。
全屏游戏会走 **独立翻转 / 独占全屏**：游戏的交换链被直接送去扫描输出，
DWM 的合成结果**不参与这一路**。于是：

- 输入路由：按 Z 序 + 可见性算，跟扫描输出无关 → 我们的窗口照样能吃到点击；
- 画面：显示器扫的是游戏的翻转链 → 我们的窗口不出现。

"只有 MC 这样"也对得上：MC 是 OpenGL，NVIDIA 驱动对 OpenGL 全屏的默认呈现方法偏向
原生呈现（非分层窗口），而其它游戏（DX11/12 窗口化全屏）走的是 DWM 合成那一路。

> **结论：这不是 Z 序问题，也不是渲染问题，程序侧没有任何办法把自己的像素塞进
> 别人的独占翻转链。** 能做的只有两件：① 全屏期间别让它坑用户（本轮做的）；
> ② 让游戏别用独占呈现（驱动/游戏侧设置，见 §5）。

## 3. 我前两轮为什么一直"验不出来"

这是本轮最该记的教训。

| 取证方式 | 拿到的是 | 在这种场景下 |
| --- | --- | --- |
| `--shot`（RenderTargetBitmap） | WPF 自己的视觉树 | 只能证明"画了"，与上屏无关 |
| `--shot-screen` / `shot-full.py`（GDI BitBlt 桌面） | **DWM 合成结果** | 会拍到悬浮窗；且 BitBlt 本身会打断全屏直通 → **假阳性** |
| 游戏内截图（F11 / 游戏自带 F2） | 游戏自己的交换链 | 必然不含桌面层，**不能**用来证明"眼睛看不到" |
| 用户口头/手机拍照 | 真实扫描输出 | ✅ 唯一可信 |

所以两轮"120/120 拍都在最顶""像素 24~36 一直在画"全部是**合成层证据**，
拿去反驳用户的"看不见"根本站不住。**以后凡是"用户说看不见但截图里有"，
一律先怀疑取证口径，不要先怀疑用户。**

## 4. 本轮的实际改动：全屏期间自动让路

既然是"看不见却点得到"，那就让它点不到。

- 新增 `ConfigStore.FloatAutoThroughFullscreen`（默认 **true**）。
- `FloatWindow.SetAutoThrough(bool)`：由 1Hz/4Hz 巡检里的
  `Monitors.IsFullscreenForeground` 驱动，前台一旦铺满屏就打开临时穿透，离开立刻还原。
- 命中测试条件由 `_clickThrough` 改成 `(_clickThrough || _autoThrough)`。
- `_autoThrough` **不写盘、不改锁定状态**，与用户手动那个"鼠标穿透"互不覆盖。
- 出口三处：设置页「全屏自动穿透」开关、托盘菜单「全屏游戏自动让路」、配置文件。

### 验收

```
20:35:16.891 [float] auto-through on（前台铺满屏 → 命中测试让路，避免点掉游戏全屏）
20:35:26.221 [float] auto-through off（前台恢复 → 命中测试交回自己）
```

`--float-zreport` 同期读到 `hitTestHits=20`（鼠标每次移动都会来一条 `WM_NCHITTEST`，
计的是**真实被拦下的次数**，不是配置值）。用 `tools/fake-fullscreen.py` 造铺满屏的前台窗口，
先起探针再让它抢前台才测得准 —— 反过来的顺序里前台会被探针自己的浮窗占住，
`IsFullscreenForeground` 判 `self` 直接返回 false。

编译 0 警告 0 错误。

## 5. 剩下那一半（显示）要用户侧动手

按"对症程度 × 成本"排序：

1. **NVIDIA 控制面板 → 管理 3D 设置 → 程序设置 → 添加 `javaw.exe` →
   "Vulkan/OpenGL 呈现方法" 改为「优先使用分层窗口」**。
   最对症：只有 OpenGL 的 MC 出问题，其它游戏正常。
2. 设置 → 系统 → 屏幕 → 显示 → 图形 → 默认图形设置 → 关掉「优化窗口化游戏」。
3. 给 MC 装无边框全屏类 mod（Borderless Mining 等），或直接用窗口模式。
4. 都无效时才考虑禁用 MPO（`OverlayTestMode=5`，需重启，会影响其它场景，不推荐先动）。

## 6. 判障对照表（下次直接用）

| 现象 | 判据 | 结论 |
| --- | --- | --- |
| 看不见 + **点得到** | 点击会切前台/掉全屏 | 扫描输出被旁路（独立翻转），程序侧无解 |
| 看不见 + 点不到 | 点击落到游戏上 | 真的被 Z 序压住 → 查 `[topmost] raise` |
| 看得见但很淡 | 条内 luma vs 条外 | 玻璃浓度问题，调 `FloatGlassLevel` |
| 自己截图有、眼睛没有 | 合成层 ≠ 扫描输出 | 换手机拍照再判，别信 BitBlt |
