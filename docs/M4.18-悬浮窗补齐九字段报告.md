# M4.18 悬浮窗补齐到九字段（与任务栏同项可选）

## 需求

> 给悬浮窗也添加能够选择显示内容的功能

任务栏条一直有九项可开关（`TrayFields`），悬浮窗只有六项。补齐后两处同项可选。

## 补的三项

| key | 名称 | 数据来源 | 列宽（100% 档） |
| --- | --- | --- | --- |
| `disk` | 硬盘温度 | `DashboardState.FloatDisk`（多盘上下两行） | 36 |
| `io` | 上传 / 下载 | `DashboardState.FloatIo`（`↑` / `↓`） | 48 |
| `pwr` | 整机功耗 | `DashboardState.FloatPwr`（`~68W`） | 44 |

采集与格式化代码**本来就有**（任务栏在用），这次只是把三格接到悬浮窗的两套面板上。

### 两个设计决定

1. **顺序不与任务栏对齐，新三项一律追加在末尾。**
   任务栏是 `…显存, 硬盘温度, 上传下载, 网络延迟, 功耗`，悬浮窗是 `…显存, 网络延迟, 硬盘温度, 上传下载, 功耗`。
   老用户已经记住"第六个是网络延迟"，把它挪到第八位等于白记一次。
   `FloatFields` 的顺序契约是"条上的顺序，不接受重排"。

2. **新三项默认关闭。**
   老用户升级上来如果三项全开，横向条 381 → 533 DIP、竖向 272 → 384 DIP —— 那是没打招呼就把界面改了。
   播种逻辑：`ConfigStore.SeedFields()`，只在 `ConfigVersion < 2` 时把 `FloatFields.DefaultHidden`
   写进 `FloatHiddenFields`，然后把 `ConfigVersion` 顶到 2。**只做一次**，之后用户怎么勾都不再干预。

## 踩到的坑：XAML 的 Binding 会盖掉代码设的 Margin

第一版把新格子的右间距照旧写成 `Margin="{Binding CellGap, …}"`，然后想用代码把"最后一个可见格"的
间距清零（末位不该有尾部空白，否则条子凭空变宽）。结果**清零无效**，条宽从 380.67 变成 388.67（多一个 8 DIP）。

原因：代码里 `row.Margin = gap` 设的是 local value，但那格上的 Binding 仍会在 `CellGap` 变化时把它写回。
（而且首次调用时 `CellGap` 还是 0、`Margin` 也是 0，`Equals` 相等 → 压根没设，Binding 一直活着。）

改法：**横向九格的 Margin 不再写 Binding，全由 `ApplyFieldVisibility()` 负责**
（构造函数一次 + 每次缩放一次 + 每次切换字段一次）。竖向那套仍用 `RowCellMargin` Binding 不动，
因为它"末位也带下间距"是既有行为。

新增诊断 `cells:`（sidecar）与 `FloatWindow.FieldsDiag`：每格的 `可见性/右间距/宽度` 一行打出来，
下次再遇到"条子宽了几个 DIP"直接看这行，不用再靠肉眼量截图。
