# M4.44 设置页「关于」

> 上线前盘点里的一条：用户报问题时最先要问的三件事（哪个版本、跑的是哪份文件、装了哪些
> 第三方组件），当时一条都查不到。这一版把它们放进设置页的第三页。

## 做了什么

设置页左侧导航从两页变三页：`常规` / `诊断` / `关于`。关于页三张卡片：

| 卡片 | 内容 | 为什么要有 |
| --- | --- | --- |
| 版本与许可 | `0.1.0 (d129cbf)`、构建时间、协议版本与同意时间、「查看完整协议」 | 用户报 bug 时能一句话给出定位；也证明"你看的这份条款就是我当时同意的那份" |
| 第三方组件 | `THIRD-PARTY-NOTICES.txt` 正文（可滚动）+「打开文件」按钮 | MPL-2.0 §3.2 要求告知源码获取方式；组件清单是许可合规的硬要求，不能只躺在仓库里 |
| 文件位置 | 程序目录、配置文件路径、日志路径 | 排查"改了配置没生效""部署没换 dll"时第一个要看的东西 |

## 实现要点

| 文件 | 内容 |
| --- | --- |
| `Sdk/AboutInfo.cs`（新增） | 版本 / 构建时间 / 程序目录 / 组件清单正文，供界面与探针**共用同一份** |
| `SettingsWindow.xaml` | 导航加 `NavAbout`，`AboutPage` 三张卡片；`AboutScroll` 是这一页的滚动容器 |
| `SettingsWindow.xaml.cs` | `Nav_Checked` 三分支；探针 `nav:about` / `about` / `scroll:` |
| `CoPul.App.csproj` | `THIRD-PARTY-NOTICES.txt` 双落：嵌入程序集 + 复制到输出目录 |
| `EulaWindow.xaml(.cs)` | `ReadOnly`：只读查看形态（隐藏勾选框与主按钮，「退出」改「关闭」） |

**版本串取 `AssemblyInformationalVersion` 而不是 `AssemblyVersion`。**
后者是四段 `0.1.0.0`，用户报问题时看不出是哪一次构建；前者的 `+sha` 段是 SDK 构建时写进去的
源码版本，截前 7 位就对得上 git 提交。

**构建时间取 dll 的写盘时间，不是编译时刻。**
排查"改了源码但部署没生效"时，要看的就是这一份 dll 是什么时候落盘的。

**组件清单只嵌一份，不复制第二份正文。**
界面读的是嵌入资源，随包的 `THIRD-PARTY-NOTICES.txt` 是同一份文件的两个落点。
资源缺失时**必须说出来**（页面上给一句"组件清单未随程序提供"并记 trace），
不能安静地显示空白 —— MPL-2.0 的告知义务空着就等于没做。

**「查看完整协议」必须是另一个窗口实例。**
首启那个协议窗是模态的、早就关了，语义也是"征求同意"，与"回看条款"不是一回事。
只读形态复用同一个 XAML：勾选框与主按钮 `Collapsed`，「退出」改「关闭」、`IsCancel=true`，
底部说明改成"这是曾经同意过的条款，仅供查阅"。

## 验收

编译 0 警告 0 错误。

| 项 | 结果 |
| --- | --- |
| 嵌入资源 | `CoPul.App.EULA.txt`、`CoPul.App.THIRD-PARTY-NOTICES.txt` 都能在 dll 里检索到 |
| 关于页 | 三张卡片渲染正常，图标与分隔线正常（`icon=ok noticesChars=1425`） |
| 导航 | `nav:about` 后 `pages=[general=Collapsed,diag=Collapsed,about=Visible]` |
| 只读协议窗 | `--eula-ro` 排版正常，隐藏按钮后底部不留空 |
| 滚动探针 | `scroll:` 按当前页选容器（常规页 / 关于页），写死 `GeneralPage` 会在关于页静默无效 |

> 截图里的版本串是拍摄时的 HEAD；换过 dll 之后这一行会跟着变，这本身就是"部署有没有生效"的判据。
