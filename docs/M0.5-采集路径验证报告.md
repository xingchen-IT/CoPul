## 2. 关键发现

### F1 · LHM 已从 WinRing0 迁移到 PawnIO（推翻 M0 报告的假设）

在 `LibreHardwareMonitorLib.dll` 里搜 `Ring0` / `KernelDriver` → **0 个命中**。实际存在的是：

| 类型 | 可见性 | 说明 |
| --- | --- | --- |
| `LibreHardwareMonitor.PawnIo.PawnIo` | public | 设备句柄封装，`LoadModuleFromResource` / `Execute` |
| `LibreHardwareMonitor.PawnIo.IntelMsr` | **public** | `new IntelMsr()` 无参构造，`ReadMsr(uint, out ulong)` |
| `...PawnIo.AmdFamily17` / `AmdFamily10` / `RyzenSmu` | public | AMD 侧对应模块 |
| `...PawnIo.IsaBridgeEc` / `LpcAcpiEc` / `Smbus*` | public | SuperIO / EC / SMBus |

模块本身以 `.bin` 字节码内嵌在程序集里（`LibreHardwareMonitor.Resources.PawnIo.IntelMSR.bin` 等 12 个），由 PawnIO 驱动解释执行。

**驱动本体不在 NuGet 包里。** 它是一套独立安装的驱动包，本机现状：

```
服务名   : PawnIO
状态     : Running
启动方式 : Manual
驱动路径 : C:\WINDOWS\system32\DriverStore\FileRepository\pawnio.inf_amd64_a72a2f969b8b7496\PawnIO.sys
安装目录 : C:\Program Files\PawnIO\  (PawnIOLib.dll / PawnIOUtil.exe / uninstall.exe)
版本     : 2.2.0.0
```

本机之所以已装，是因为 M0 时代跑过 LHM——**LHM 的安装包负责装 PawnIO**。CoPul 是绿色版 exe，没有这一步。这是新增的打包约束，见第 5 节。

### F2 · LHM 那 218 ms 不在驱动层

这是本次最有价值的数字：

| 操作 | 耗时 |
| --- | --- |
| 单条 MSR 读（驱动往返全含） | **1.66 ~ 2.18 µs** |
| 51 条连续读（模拟 `Cpu.Update()` 的传感器数量） | **0.10 ~ 0.15 ms** |
| LHM `Cpu.Update()`（M0 实测） | **218.10 ms** |

同一条驱动、同一批 MSR，差 **约 1500 倍**。

推论：LHM 的 218 ms **不是 ring0 往返开销，而是它自己托管层的开销**（每个传感器各自一套取值逻辑、状态判断、事件通知、UI 无关的簿记）。M0 报告当时把它归因为"内核驱动读 MSR 的往返"，是错的——本次实测证明驱动往返只要微秒级。

**这个差别很重要**：如果瓶颈在驱动层，那"自研"也快不了多少，Q-19 的 A 方案就白选了；实际瓶颈在调用者的实现，绕开它收益是数量级的。

### F3 · 驱动未加载时 `ReadMsr` 返回 `true`，值为 0

非管理员运行的实测：

```
PawnIo.IsInstalled = True
实例 IsLoaded      = False
试读 MSR 0x1A2     -> 返回 true，值 = 0x00000000
```

`ReadMsr` 不报错，只是把 0 填给你。若不校验，UI 会显示 `TjMax 0°C`、`封装 0°C`、`功耗 0W`，全部是假值。

**这与 M0 的硬盘 `0.00°C` 是同一类问题的两个实例**：传感器读数的"成功"不等于"有效"。因此第 11 章那条"温度/功耗连续 3 次为 0 判定失效"的硬约束不是保险措施，而是必需品；本次还要再加一条**启动时的合理性校验**（`0x1A2` 的 TjMax 必须落在 80–120 之间）。

### F4 · APERF/MPERF 在本平台返回乱数，倍频要读 `IA32_PERF_STATUS`

`MSR 0xE7`（MPERF）连续采样：

```
16084303452784
16084358737664   +55284880          ← 0.1 秒涨了 5.5e7，说明量级对
37831937663856   +21747578926192    ← 突然跳到 3.7e13
15733771778116   ↓ 倒退             ← 递减，物理上不可能
```

自由运行的 64 位计数器不可能倒退。**结论：这条 MSR 在本平台返回的值不可信**（可能是 PawnIO 的 IntelMSR 模块对 0xE7/0xE8 的实现与该 CPU 微码不匹配）。

改用 `IA32_PERF_STATUS (0x198)` 采样（期间有一个线程满载）：

```
0x00002C00   [15:0]=11264   [15:8]=44
0x00002C00   [15:0]=11264   [15:8]=44
0x00001A00   [15:0]= 6656   [15:8]=26     ← 空载瞬间跌到 2.6 GHz
0x00002400   [15:0]= 9216   [15:8]=36
```

`[15:8]` 取出的 44 / 26 / 36 → 4.4 / 2.6 / 3.6 GHz，与 i7-13650HX 的基频 2.6 GHz、睿频 4.9 GHz 吻合，且随负载变化。`[15:0]` 是 `ratio << 8`，直接用会得到 1126 GHz 这种荒谬值。

**所以 C06 的实现要改成：`ratio = (MSR_0x198 >> 8) & 0xFF`，频率 = `ratio × 100 MHz`。**

### F5 · 硬盘温度自研成功，LHM 报的 0.00°C 确认是它的解析 bug

`IOCTL_STORAGE_QUERY_PROPERTY` + `StorageDeviceProtocolSpecificProperty(50)` + NVMe `Get Log Page 0x02`：

| 盘 | SMART 前 16 字节 | 温度 | 剩余备用 | 备用阈值 | 已使用寿命 |
| --- | --- | --- | --- | --- | --- |
| PhysicalDrive0 | `00-49-01-64-05-06-...` | K=329 → **55.9 °C** | 100% | 5% | 6% |
| PhysicalDrive1 | `00-3C-01-64-01-00-...` | K=316 → **42.9 °C** | 100% | 1% | 0% |

两个实现细节：

1. **协议数据必须放在缓冲区偏移 8 处**，不是 12。偏移 12 在两次运行中都失败（`ERROR_INVALID_PARAMETER`）。这与 `STORAGE_PROPERTY_QUERY` 的 `sizeof` 在 C# 与 C 头文件间的差异有关。
2. **非提权时 `CreateFile(\\.\PhysicalDriveN)` 直接返回错误 5（拒绝访问）**，连 IOCTL 都到不了。

字节偏移的含义也顺带确认了（之前 M0 报告里我猜错过）：`[0]` 严重告警位、`[1..2]` 温度（Kelvin，小端）、`[3]` 剩余备用百分比、`[4]` 备用阈值、`[5]` 已使用寿命百分比。**不是**警告/临界温度阈值。

### F6 · 全核温度的成本 98% 在切换核心，不在读 MSR

| 操作 | 耗时 |
| --- | --- |
| 固定亲和后的纯读 | 2.20 µs |
| 切核 + 读（每核） | 85 ~ 103 µs |
| 一轮 20 核 | 1.70 ~ 2.06 ms |

`SetThreadAffinityMask` 每次约 **83–101 µs**，是 MSR 读本身的 **40 倍**。

这决定了调度设计：**封装温度可以 200ms 一次（几乎免费），全核温度不能**。若全核温度也跟 200ms，单这一项就是 0.85–1.03% 单核；固定在 500ms 则降到 0.34–0.41%。

### 3.3 预算推算（按 4.0 分级）

| 项 | 频率 | 成本/秒 | 单核占用 |
| --- | --- | --- | --- |
| 封装温度 + RAPL | 200 ms | 0.02 ms | **0.002%** |

## 5. 新增的打包约束（必须提前想清楚）

这不是技术问题，是分发问题，但会卡住 M5：

1. **PawnIO 驱动不在 NuGet 包里**，只有 `.bin` 模块。目标机若从未装过 LHM，`new IntelMsr()` 会抛异常或读到全 0。
2. **安装驱动需要管理员**，而 CoPul 本身也已确认必须提权（M0 结论 R1b）。两者可以合并为同一个 UAC 流程，但要在首启明确告知用户在装什么。
3. **PawnIO 的分发许可需要单独确认**。LHM 是 MPL-2.0，PawnIO 是独立项目（namazso），许可证与 LHM 不同。**在确认之前不要把它打进安装包**；稳妥做法是：检测未安装 → 引导用户去装 → 装完自动恢复 T1 采集。
4. **绿色版承诺要打折**。原需求写的是"免安装绿色版 exe"。现在必须变成"exe 本身免安装，但硬件深度读取依赖一次性安装 PawnIO 驱动"，并在文档里明示。
