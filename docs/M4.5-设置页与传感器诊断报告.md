# M4.5 设置页与传感器诊断 阶段报告

- 日期：2026-10-30
- 范围：**G-08 设置页** + **G-09 传感器自检**（Q-18 独立 tab）
- 未含：副屏任务栏（单屏机器无法验收，见第 6 节）、G-03 全局热键

---

## 1. 做了什么

一个独立窗口，左侧两项导航：**常规** / **传感器诊断**。

| 分组 | 内容 |
| --- | --- |
| 显示模式 | 大窗口 / 悬浮窗 / 任务栏条，三选一 |
| 任务栏条字段 | 八字段独立勾选（7.4 / Q-03），只剩一个时该项置灰 |
| 悬浮窗外观 | 毛玻璃开关、浓度 1–7 步进、界面缩放 100/125/150 |
| 任务栏条 | 文字取色（自动 / 浅色底 / 深色底）、点击穿透 |
| 采集与网络 | 延迟探测目标（可改，Enter 或「应用」生效）、全屏时自动隐藏 |
| 启动 | 开机自启（计划任务，G-04） |
| 传感器诊断 | 六个采集器逐项：状态徽标 / 初始化耗时 / 不可用原因 / 修复建议 |

两个入口都通到同一个函数（`OpenSettings`）：大窗口标题栏的 `⚙`、托盘右键「设置…」。

---

## 2. 三个设计决定

### 2.1 独立窗口，不塞进大窗口

大窗口是一个 0.5s 刷新一次、九区块的监控面板。设置项混进去会让两边都难受：面板要为低频控件留白，设置项会被刷新打断。分成独立窗口后，面板保住「只读」这一条性质 —— 这也是它从 M1 就在守的边界。

### 2.2 没有「确定 / 取消」，改即生效、即落盘

每个控件改完直接写 `ConfigStore.Current` 并通知对应窗口刷新。理由和悬浮窗的 `PersistAppearance` 一样：设置页被任务管理器结束、或程序崩掉时，用户刚调好的东西不该丢。

代价是不能「反悔」。但「取消」要额外维护一份改前快照，而真正会误触的只有两个——字段开关与浓度——两者都是一眼能看出效果、再点一次就回去的。

### 2.3 复用现有属性，不写第二套

设置页的每个开关都落在**已经存在的**那个入口上：

| 设置项 | 落到 |
| --- | --- |
| 毛玻璃开关 | `FloatWindow.GlassEnabled`（新开放的同名属性，内部就是右键菜单那条 `ApplyGlass`） |
| 浓度 / 缩放 | `FloatWindow.GlassLevel` / `ScalePercent`（本来就 public，改完自己持久化） |
| 文字取色 | `TaskbarWindow.SetInkMode`（右键菜单 `SetInk` 的公开壳） |
| 点击穿透 | `TaskbarWindow.ClickThrough` |
| 探测目标 | `CollectorHost.SetPingTarget` → `OsProvider.PingTarget`（探针线程下一轮就按新目标发） |
| 全屏自动切换 | `FullScreenAutoSwitch.ApplyConfig` |

窗口不存在时（用户没切过去过）就只写配置，下次创建时从配置读。这条分支不是补丁，而是必须的：**三个视图都是按需创建的**，构造设置页时悬浮窗与条多半还是 `null`。

### 2.4 切回大窗口时关掉设置页

设置页 800×700、主窗口 853×509，都居中 —— 切到大窗口后两者严丝合缝地重叠，用户只会看到「点了没反应」。所以 `mode:main` 这条路径顺手 `Close()`。

切到悬浮窗 / 任务栏条**不关**：那两个是边缘小窗，用户本来就是想边看边调。

## 3. 传感器诊断（G-09 / Q-18）

数据全部来自已有的 `IMetricProvider`，一项都不新造：

| 显示 | 来源 |
| --- | --- |
| 状态徽标 | `Status`（Ready / Unsupported / Failed / NotInitialized） |
| 右侧耗时 | `InitializeMs` |
| 原因 | `UnavailableReason` |
| 建议 | `Remedy`（例如 MSR 那条直接给 `https://pawnio.eu/`） |

实测（非提权运行）：

```
3/6 个采集器就绪 · 管理员权限：否（温度 / 功耗 / 硬盘温度会降级为 —）

NVML        就绪        init 39 ms
OS / PDH    就绪        init 589 ms
MSR/PawnIO  初始化失败   init 5 ms    读取 CPU 温度需要管理员权限（PawnIO 驱动句柄被拒）。
                                    以管理员身份重新启动 CoPul。
NVMe SMART  初始化失败   init 0 ms    读取硬盘温度需要管理员权限（物理盘盘符句柄被拒）。
进程        就绪        init 52 ms
帧率        初始化失败   init 0 ms    FPS 需管理员权限（PresentMon 的 ETW 会话被拒绝访问）
                                    以管理员身份运行 CoPul（或把当前用户加入「性能日志用户」组）
```

这正是 4.2「不得静默降级」在设置页的落点：条上一个 `—` 到底是「没这个硬件」还是「没提权」，只有这里说得清。

## 4. 验证

全部为真机运行，证据来自 `%TEMP%\copul-trace.log`、`config.json` 与截图。

| 场景 | 操作 | 结果 |
| --- | --- | --- |
| 常规页渲染 | `--settings --shot` | 800×700，八字段 4×2 勾选、分段选中态、开关胶囊均正常 |
| 诊断页 | `--settings --settings-page diag --shot` | 见第 3 节，六项齐全 |

## 5. 本轮踩到的坑

### 5.1 `Padding` 写死在 ControlTemplate 里，样式改了也不生效

「玻璃浓度」两侧的 `-` `+` 按钮渲染成**两个空方块**。查下来不是字符问题：`MiniButton` 的模板里写的是

```xml
<Border ... Padding="12,5">   <!-- 硬编码 -->
```

而 `StepButton`（28×28）靠 `<Setter Property="Padding" Value="0"/>` 去覆盖它 —— 无效。边框左右各吃 12px，28px 的按钮只剩 2px 内容区，字被压成一个点。

改成 `Padding="{TemplateBinding Padding}"`，并在 `MiniButton` 上补默认值 `12,5`，两个按钮立刻正常。

> 教训：`ControlTemplate` 里凡是「用户可能想改的量」都必须走 `TemplateBinding`，写了字面量就等于把这个属性从样式系统里摘掉了 —— 而且它不报错，只是**静默失效**。

### 5.2 「拒绝关闭最后一个字段」时回滚错了对象

第一版记了一个 `lastOff`，语义看着是「刚被关掉的那个」。但那是**遍历结束后**的值 —— 它指向的是「最后一个未勾选的框」。

于是「只剩 FPS 时关 FPS」被拒绝后，被重新勾上的是最右边的**「整机功耗」**，FPS 依然是关的。截图一眼就能看出来，但代码读一百遍都像对的。

改法是**按配置整份重同步**：拒绝时不猜「刚才动的是哪个」，而是把八个框全部按 `TrayFields.IsVisible(_config, key)` 重设一遍 —— 配置本来就没动，所以一定回到操作前的样子。

这个 bug 是探针抓出来的（`--settings-probe field:fps`），手点也能发现，但需要先构造出「只剩一个字段」的状态。

### 5.3 `--shot` 的 target 在定时器外面求值

`--settings --shot-screen` 拍出来是一张**主窗口**。原因：`Window target = settings is { IsVisible: true } ? settings : ...` 写在 `timer.Start()` 之前，而设置页是 1.5 秒后才 `Show()` 的 —— 求值那一刻它还不存在，于是永远选中主窗口。

把整段判断移进 `timer.Tick` 才对。加了留痕：

```
[shot] target=SettingsWindow visible=True left=880 top=446 size=800x660 settings=True
```

### 5.4 GDI 抓屏会被「持续置顶的游戏浮层」切成两半

诊断页截图左半边一直是游戏画面（斜向路面），右半边才是设置页。

- 先怀疑 `SaveWindow` 的坐标算错 —— 留痕证明 `left=880 top=446 size=800x660` 完全正确；
- 再怀疑 Z 序，加了 `target.Topmost = true` 等 350ms 再拍 —— **还是被盖住**。抓一张整屏才看清：`UnrealWindow` 与一个 `Tauri Window` 都压在上面，而且游戏每一帧都在把自己重新置顶，Windows 的 topmost 组里「后来者居上」，抢不过。

结论：**这个环境里屏幕抓屏不可靠**。设置页没有毛玻璃、背景是纯色，`RenderTargetBitmap`（`--shot`）就能拿到完整像素，不必和 DWM 合成较劲。

> 对照：悬浮窗/任务栏条**必须**用 `--shot-screen`（毛玻璃与 DWM 阴影只存在于合成结果里）。所以两条路都得留着，按窗口类型选。

### 5.5 `Show()` 之后要 `Activate()`

打开设置页却不激活，用户点了 `⚙` 之后窗口没到前面 —— 这个流程是从托盘/主窗口唤起的，桌面焦点很可能在别的程序上。补一句 `Activate()`。

> 顺便把一个**被证伪的假设**记在这里：当时以为诊断页「只画了一半」是「后台窗口合成被节流」，还按这个方向改了一次。5.4 证明真正原因是别的窗口压在上面（`Topmost` 都抢不过）。留着这一条是为了下次别再从「合成节流」查起。

## 6. 已知限制

1. **副屏任务栏没做**。本机只有一块显示器，副屏任务栏（`Shell_SecondaryTrayWnd`）无法真实验收 —— 更关键的是它的 `FreeLeftWidth` 降级路径不同：副屏任务栏没有开始按钮，`Start` / `ReBarWindow32` 两个锚点都找不到，会退化到「任务栏宽的 1/4」。这条分支只能靠猜，按项目纪律（每项都要真实证据）先不做。
2. **探测目标填域名时每轮 ping 都会解析一次 DNS**（1Hz）。填 IP 没有这个问题；默认值 `223.5.5.5` 也是 IP。后续可以在 setter 里把解析结果缓存住。
3. **不做跨窗口实时同步**：设置页开着时，若用户从托盘菜单改了字段，设置页的勾选不会自动刷新（下次打开才同步）。托盘菜单与设置页最终写的是同一份配置，不会分叉，只是显示会短暂不一致。
4. **不提供刷新挡位**（Q-23：v1 固定 0.5s，G-08 明确「设置页不显示该项」）。
5. `--settings` 不算测量模式，已有实例在跑时会被单实例拦下 —— 自测时要配 `--shot`/`--shot-screen` 一起用。

## 7. 自测开关

| 开关 | 作用 |
| --- | --- |
| `--settings` | 启动 1.5s 后打开设置页 |
| `--settings-page diag` | 直接切到诊断 tab |
| `--settings-probe <命令[,命令]>` | 走控件自己的事件路径：`field:pwr` / `ping:1.1.1.1` / `level:+` / `scale:125` / `ink:dark` / `through:0` / `glass:0` / `fullscreen:0` / `mode:float` / `diag` / `scroll:700` |

探针存在的理由和 M4.1 的 `--tray-menu-probe` 一样：本机 `SetCursorPos` 不可靠，模拟点击会把「点歪了」误判成「功能坏了」。探针翻的是 `IsChecked`，触发的是同一批事件处理函数，不是影子逻辑。
