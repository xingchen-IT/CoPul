# M4.17 失焦白框：真凶是 `WM_NCACTIVATE`

## 现象

> 移动完位置之后再点击桌面或者别的应用之后还是会有白框（横向也是）
> 好像还要同时开着设置界面才会有这种情况（不是很确定）

用户截图（`clipboard-2026-10-31T10-07-19`）按像素量出来的形状：

| 位置 | 颜色 | 宽度 |
| --- | --- | --- |
| 左缘 x=27..36 | `#FFFFFF` | **10 px** |
| 右缘 x=585..593 | `#FFFFFF` | **10 px** |
| 上缘 y=48..50 | `#FFFFFF` | 2~3 px |
| 下缘 y=96..97 | `#FFFFFF` | 2 px |

外框跨度 566×50 px ≈ 悬浮窗 571×51（380.67×34 DIP @150%）。
白带外侧还有一圈 9 px 的**暗带**（luma 70）——那是 DWM 阴影压在亮背景上，
所以从外往里是「亮背景 → 阴影 → **白框** → 条内容」，白框位置正是非客户区。

10 px = `WS_THICKFRAME` 的 8 DIP × 1.5，与 M4.16 反例 `--no-nccalc` 量到的 `gap=10/10` 同宽。

## 三个触发场景的共同点

点桌面 / 点别的应用 / 开着设置页 —— **都是悬浮窗失焦**。

## 为什么 M4.16 的守门抓不到

M4.16 的 `GuardFrame()` 判据是「客户区矩形 vs 窗口矩形」。失焦探针实测：

```
ncCalcHits=4  ncActivateHits=2  guardHits=0
window=571x51 client=571x51  gapLR=0 gapTB=0
```

**gap 恒为 0**。这条路径是"把非客户区**画**出来"，不是"把客户区切小" ——
几何判据对它是**结构性失明**，所以它再怎么巡检也不会触发。

## 真凶：`WM_NCACTIVATE`

窗口失焦时系统发 `WM_NCACTIVATE`（wParam=FALSE），`DefWindowProc` 会顺手**重画一遍非客户区**，
那条被 `WM_NCCALCSIZE` 吃掉的 8px 框架就在这时被画回来。浅色主题
（`AppsUseLightTheme=1`）画成白色 —— 白框。

探针计数直接证实：`ncActivateHits=2`（失焦一次来两遍），
关掉开关（`--no-ncactivate-guard`）后 `ncActivateHits=0`，说明计数就是这条消息本身。

## 修法

### 1. 拦 `WM_NCACTIVATE`，让 `DefWindowProc` 跳过非客户区重绘

```csharp
if (msg == WM_NCACTIVATE && NcActivateGuard && EatFrame)
{
    _ncActivateHits++;
    handled = true;
    return DefWindowProc(hwnd, msg, wParam, (IntPtr)(-1));   // -1 = 别重画非客户区
}
```

`lParam = -1` 是 WPF `WindowChromeWorker` 里的同款做法（MSDN 未记载，但实际有效）。
它只跳过"非客户区重绘"这一步，激活/失焦该发生的照常发生。

### 2. 激活状态变化一律强制重算框架

`Activated` / `Deactivated` 改成 `GuardFrame(force: true)`：不判 gap，直接补一次
`NotifyFrameChanged`（`SWP_NOMOVE|NOSIZE|NOZORDER|NOACTIVATE|FRAMECHANGED`，不改几何也不重排）。
因为这条路径几何不变，只能无条件补。

副作用是可观测的：`ncCalcHits` 从 4 涨到 6~8（强制重算真的触发了 `WM_NCCALCSIZE`），
但尺寸一次都没变。

## 取证

| 项 | 结果 |
| --- | --- |
| 编译 | 0 警告 0 错误 |
| 横向尺寸 | 380.67×34 DIP / 571×51 px（基线一致） |
| 竖向尺寸 | 47.33×272 DIP / 71×408 px（基线一致） |
| 失焦探针 | `ncActivateHits=2 guardHits=2 gapLR=0 gapTB=0` |
| A/B（`--no-ncactivate-guard`） | `ncActivateHits=0` |
| 自证 `--float-move-focus-probe framebreak` | `break=10/10 -> guard=0/0` |
| 拖动描边 | keep `#FFFF7FB8` / release 回 `#0DFFFFFF` |
| 配置污染 | 无（`FloatEdgeMode=faint` 等保持原值） |

**未做到的**：本机 `--shot-screen` 抓不到 DWM 的非客户区图层，两张对照抓屏
（守门开/关）纯白像素都是 **0**，所以**没有本机视觉复现**。
结论建立在「消息计数 + 用户截图的像素几何」两条证据上，最终判定要用户在真机上确认。

## 自测开关

- `--no-ncactivate-guard`：关掉"失焦时不重画非客户区"，A/B 用
- sidecar 新增 `ncActivateHits`
- 原有：`--no-nccalc`、`--no-frame-guard`、`--float-move-focus-probe move,drag,defocus,framebreak`
