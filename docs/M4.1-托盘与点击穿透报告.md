## 1. 为什么这两件事必须一起做

7.6 的 Q-12 已定方案 2：**任务栏条默认穿透，全部操作走托盘右键**。

单看这一句像是两件独立的功能，实际上是同一个改动的两面：

- 只做穿透不做托盘 → 条上再也收不到右键，**连退出都没有入口**
- 只做托盘不做穿透 → 条仍然吃掉鼠标，Widgets 被盖住那块点不到

所以顺序必须是"先有出口，再堵入口"。本次一次提交里同时落地。

## 3. 托盘：为什么不用 `Forms.NotifyIcon`

| 方案 | 代价 |
| --- | --- |
| `System.Windows.Forms.NotifyIcon` | 要开 `UseWindowsForms`，WPF 与 WinForms 两套消息泵、两套 DPI 感知混在一个进程里。为一个图标不值 |
| 纯 P/Invoke `Shell_NotifyIcon` | 约 250 行，但行为完全可控，且与项目 `Interop/` 目录其它文件风格一致 |

选了后者。要点：

1. **需要一个真实顶层隐藏窗口**收回调，不能用 message-only 窗口 ——
   菜单要能正常消失，`TrackPopupMenu` 需要前台窗口配合。
2. `NIM_SETVERSION` 设成 V4 之后，回调的 `lParam` 低 16 位才是事件码。
3. `cbSize` 必须等于 `Marshal.SizeOf<NOTIFYICONDATA>()`，写死 956 之类会在
   不同架构上错位（本项目只出 x64，但仍然按 sizeof 走）。

### 3.1 菜单为什么用原生 `TrackPopupMenu`

WPF 的 `ContextMenu` 需要一个 `PlacementTarget`（真实 `Window`）才能定位。
而托盘图标**可能在三视图全部隐藏时被点击**（左键隐藏当前视图之后就是这种状态），
那时没有合适的宿主窗口。

原生菜单按屏幕坐标自己弹，与窗口无关 —— 这是它的长处，也是选它的唯一原因。
代价是菜单样式跟随系统而不是跟随 WPF 主题，实际看下来与现有菜单观感一致。

两个必须做的收尾动作：

- `SetForegroundWindow(hwnd)` 在前 —— 少了它菜单点外面不消失（`TrackPopupMenu` 老毛病）
- `PostMessage(hwnd, WM_NULL)` 在后 —— 官方文档要求的补刀，否则菜单可能残留

## 4. 图标：小尺寸必须单独化简

本机 `pip install pillow` 无源、`Add-Type`（运行时编译 C#）被安全策略禁，
所以图标由 `tools/make-tray-icon.py` 用标准库生成：手写 PNG（zlib）再套 ICO 容器。

构图按 10.3 的配色：`#0F1216` 圆角方块 + `#4FB3A6` 心电图折线。
第一版只画了一个对称的峰谷，放大看像字母 **M** 而不是脉搏 ——
补上 Q 波（起跳前的小 dip）与 S 波（回落后的深谷）才读得出是心跳。

**16px 与 24px 用另一套点位**（`PULSE_PTS_SMALL`）并加粗线宽到 `size * 0.13`：
48px 那套细节在 16px 下只剩 3 个像素，QRS 三个波糊成一块色斑。
小尺寸只留「基线 → 单尖峰 → 基线」，这一步是看放大图才发现的。

## 5. 穿透：为什么用 `WM_NCHITTEST` 而不是 `WS_EX_TRANSPARENT`

| 方案 | 问题 |
| --- | --- |
| `WS_EX_TRANSPARENT` | 顶层窗口要真正跨进程穿透得配 `WS_EX_LAYERED`；而 layered 会把 WPF 换成软件合成路径，毛玻璃与文字渲染都会变（M2 为整窗 alpha 付过这个代价） |
| `WM_NCHITTEST` → `HTTRANSPARENT` | 只影响命中测试，**渲染一个像素都不动** |

选后者。实现上是挂一个 `HwndSource` 钩子，`_clickThrough` 为真时一律返回 `-1`。

改开关不需要重建窗口：命中测试每次都读当前字段。
这条很关键，因为穿透之后条上收不到右键，用户要改文字颜色就得先用托盘菜单
把「任务栏条可点击」打开 —— 如果那时需要重建窗口，改一次颜色就要闪一次。

## 7. 三个把验证带偏过的坑

### 7.1 `WindowFromPoint` 不能用来判断穿透

穿透生效后 `WindowFromPoint` **仍然返回条窗口**。它不做命中测试，
只按 Z 序和窗口区域找 —— 想知道会不会穿透，只能直接
`SendMessage(hwnd, WM_NCHITTEST, ...)` 问窗口本人。

### 7.2 本机 `SetCursorPos` 不可靠，模拟点击验不了菜单项

用 `SetCursorPos(1200,1000)` 之后 `GetCursorPos` 拿到的是 `(819,705)`、
下一次又是 `(9,820)` —— 光标被真实鼠标挪走了（人还在用电脑）。
所以 `mouse_event` 点的落点完全不受控。

结论：**菜单"弹出来长什么样"用截图验，"点了之后做什么"用探针验**。
`--tray-menu-probe <id>` 走的是与 `RightClick` 完全相同的那一份 `switch`，
所以它验证的是真实分发路径，不是复制出来的一份影子逻辑。

### 7.3 Win11 默认把新图标收进溢出区

注册成功后托盘右端看不到图标，要先点 `^` 展开。
这是系统策略，程序无法强制显示 —— 用户需要自己在"任务栏设置 → 隐藏的图标"里打开。
**这不是缺陷，但必须写进交付说明**，否则第一次用会以为程序没生效。
