# M4.54 跨进程鼠标穿透修复

> 真机报障：「全屏游戏时鼠标移到悬浮窗上，右键或左键还是会点到悬浮窗，游戏操作不了。」
> 结论：M4.21 起的穿透实现**从来没有真正生效过**，只对同进程窗口有效。

---

## 1. 现象与初判

配置 `FloatClickThrough=True`、`FloatAutoThroughFullscreen=True`，日志里 `[float] auto-through on`
正常出现，说明全屏判定成功、穿透标记已经打开。但随后又出现 `auto-through off`，
而它唯一的触发条件是"前台窗口变成了 CoPul 自己" —— 也就是**点击确实被悬浮窗接走了**。

## 2. 根因

M4.21 的实现在 `WM_NCHITTEST` 里返回 `HTTRANSPARENT`。微软对这个返回值的定义是
**"in the same thread"** —— 消息只传给同一线程的下层窗口。游戏在另一个进程，
系统走到进程边界就停：点击既没到游戏，也没被自己处理，直接消失。

M4.33 的"验收"为什么没发现：当时只统计 `hitTestHits`（我们自己返回 −1 的次数），
**从没验证过点击落到哪个窗口**。这个计数只能证明代码返回了正确的常量，不能证明系统行为。

## 3. 对照实验（跨进程）

三个覆盖层各起一个进程，压在另一个进程的目标窗口上（200×120 覆盖层完全落在 600×300 目标内部，
点击点取覆盖层中心），各测左右键：

| 覆盖层实现 | `WindowFromPoint` 命中 | 左键到目标 | 右键到目标 | 被覆盖层接收 |
| --- | --- | --- | --- | --- |
| `HTTRANSPARENT`（现状） | 覆盖层 | 否 | 否 | 否 |
| 仅 `WS_EX_TRANSPARENT` | 覆盖层 | 否 | 否 | 是 |
| `LAYERED` + `TRANSPARENT` | **目标窗口** | **是** | **是** | 否 |

三次重复完全一致。两个关键结论：

1. `HTTRANSPARENT` 跨进程时点击**凭空消失**（既不到目标，也不到自己）。
2. 单独加 `WS_EX_TRANSPARENT` 不够 —— 必须同时有 `WS_EX_LAYERED`。

探针：`D:\CoPulProbe\ptest\passthrough_test.py`（不入库）。

## 4. WPF 的两个坑

### 4.1 `WS_EX_LAYERED` 不能在窗口建好之后加

```
[pass] on=True 写入=0x801A8 设后=0x1A8 alpha后=0x1A8 frame后=0x1A8
```

`SetWindowLongPtr` 写入后**立刻**回读，LAYERED 位就没了 —— WPF 的窗口过程在
`WM_STYLECHANGING` 阶段把它改了回去（同进程的 `SetWindowLong` 会同步走 WPF 自己的 WndProc）。

所以只能靠 `AllowsTransparency="True"` 让 WPF 自己给这个位。**且它是创建时属性，运行时改不了。**

### 4.2 不能调 `SetLayeredWindowAttributes`

第一次改成 layered 后，悬浮窗变成**一块纯灰空条，数字全没**：

```
glass: Accent Acrylic    ← 但画面是空的
```

原因：`AllowsTransparency` 下 WPF 用 `UpdateLayeredWindow` 逐像素提供位图，
而 `SetLayeredWindowAttributes(LWA_ALPHA)` 把窗口切到"常量 alpha + 色键"那条路，
WPF 的位图随即被弃用。

**纯 Win32 窗口上那句是必需的**（否则窗口完全不画），**对 WPF 的 per-pixel 窗口是破坏性的**。
这两条正好相反，是本轮最容易踩反的地方。

## 5. 最终实现

`Interop/PassThrough.cs`（新增）：

- 只负责 `WS_EX_TRANSPARENT` 位，layered 由 XAML 的 `AllowsTransparency="True"` 提供。
- 进入时记下原始 exstyle，退出按掩码还原**这两位**，不碰 topmost / toolwindow。
- 不调 `SetLayeredWindowAttributes`。

`FloatWindow`：

- 新增 `SyncPassThrough()`，取或 `_clickThrough || _autoThrough`（与 `WM_NCHITTEST` 判断同源）。
- 三个调用点：`ClickThrough` setter、`SetAutoThrough`、`SourceInitialized`（配置启动即穿透）。
- `InteractDiag` 增加 `passThrough=` 与 `exStyle=0x…` 两个字段。

`WM_NCHITTEST` 那条 `HTTRANSPARENT` 保留（同进程窗口间仍是正确做法，且 layered 失效时可兜底），
注释改为说明其真实适用范围。

## 6. 验证（外部探针，不读程序自报）

`D:\CoPulProbe\ptest\float_probe.py` 按进程 ID 枚举窗口、直接读 exstyle、再 `WindowFromPoint`：

| 状态 | exStyle | WindowFromPoint | `passThrough` |
| --- | --- | --- | --- |
| 穿透开 | `0x801A8`（LAYERED+TRANSPARENT+TOPMOST+TOOLWINDOW+WINDOWEDGE） | **穿透 → 下层 Qt 窗口 pid=129692** | 1 |
| 穿透关 | `0x80188`（无 TRANSPARENT） | 命中自己 | 0 |

三个探测点（中心 / 左上内 / 右下内）结论一致。左右键在对照实验里同结论。

另外：穿透开启时 `hitTestHits` 恒为 0 —— 系统在命中测试阶段就跳过本窗口，
那条消息根本不来，属正常现象。

## 7. 代价

| 代价 | 说明 |
| --- | --- |
| 文字失去 ClearType | 窗口常驻 layered，数字用灰度抗锯齿。**不是只在穿透期间**，因为 AllowsTransparency 不能动态切 |
| DWM 阴影 | layered 窗口拿不到 DWM 给的系统阴影（`WS_THICKFRAME` 那套还在，但 DWM 不画） |
| 毛玻璃 | sidecar 两次均为 `glass: Accent Acrylic`，全部尺寸/颜色字段一致；像素级 A/B 因桌面背景在两次拍摄间变化、且本环境无法立固定灰底而**未做严格证明**，以用户实机观感为准 |

## 8. 遗留

- **任务栏条**（`TaskbarWindow`）用的是同一套 `HTTRANSPARENT`，M4.38 起它已经是
  `AllowsTransparency="True"`，所以只差补一个 `WS_EX_TRANSPARENT` 就能真穿透。
  本次按计划只改悬浮窗，等实机确认后再定。
- 需要用户进游戏实测：无边框窗口化全屏下点击能否穿到游戏、画面观感是否可接受。
  若不接受，回退方式是把 `FloatWindow.xaml` 的 `AllowsTransparency` 改回 `False`
  并移除两处 `SyncPassThrough()` 调用（穿透回到"不生效"的原状，视觉复原）。
